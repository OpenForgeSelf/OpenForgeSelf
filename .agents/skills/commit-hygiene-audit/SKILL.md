# 提交内容卫生审计

一句话：提交物必须**换环境自洽**（无机器绑定地址）、**不泄漏身份**（无指向具体个人的标识）、**不夹带无关项目语境**（其他项目业务细节不入库）；机械拦截靠 pre-commit 第 4 道门，语义判断与改写靠本技能。

## 何时用 / 不用

- **用**：提交前自检；提交被 `hygiene.*` 规则拦截后定位与改写；全仓存量盘点与清理批跟踪；拒绝列表（denylist）增删评审。
- **不用**：代码风格 / lint（走对应门禁）；密钥类敏感信息扫描（另行流程，本门禁不覆盖密钥语义）；设计规范（走 design:check）。

## 铁律

1. **引用违规只写规则 ID + `文件:行号` + 计数**，禁止把违规原文粘贴进任何提交物（防二次违规）。
2. **棘轮只拦暂存新增行**（pre-commit `-Staged`）；存量按已批准的清理批推进，不顺手扩大范围。
3. 拒绝列表在 `.forgeself/`（已 gitignore，**本地维护、不入库**）：人名 / 昵称 / 账号片段入列，**通用角色词不入列**。
4. 语义边界按 §B13 默认执行（属待拍板项）：通用角色词（用户 / 任务协调人 / 各专项审查方等）放行；其他项目作为调研对象 / 公开依赖可提其名，业务细节禁入。

## 流程（场景 → 动作）

| 场景 | 动作 |
| --- | --- |
| 提交前自检 | `pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/check-commit-hygiene.ps1 -Staged`；命中 → 按「改写手法」处理 → 重扫至 PASS |
| 提交被第 4 道门拦截 | 读 FAIL 行的规则 ID + `文件:行号` → 只改该新增行（存量行不属本提交的不动）→ 重新 `-Staged` |
| 全仓盘点 | `-All` → 按规则 ID 分组产出 `文件:行号` 清单（不贴原文）→ 报清理批范围，交用户拍板批次 |
| 拒绝列表评审 | 新增词条先问「是否指向具体个人 / 具体机器」；是 → 入列；通用词 → 拒绝入列并说明 |

## 改写手法（命中后怎么办）

- 盘符 / POSIX 用户目录 / UNC 绝对地址 → 改**仓库相对路径**；确需指用户级位置时用文字形态（「用户主目录下的 <名称> 目录」）。
- file URL 盘符形态 → 去掉协议头，留仓库相对路径。
- 人名 / 昵称 / 成员名 → 通用角色词（用户 / 任务协调人 / 各专项审查方等）。
- 机器账号片段 → 删除，或改以「实例端口 / 实例名」等非个人标识描述。
- 其他项目业务细节 → 删除，或压缩为「调研对象名 + 结论一句」；公开依赖 / 调研对象的名可留。

## 出口清单

- [ ] `-Staged` 退出码 0（摘要行 PASS）
- [ ] 本批**新增行**无 `hygiene.*` 命中（存量命中已按批次边界另行报备）
- [ ] 新增拒绝词条已评审（指向具体人 / 机才入列）
- [ ] 清理批产出只含规则 ID + `文件:行号` + 计数，无违规原文

## 真源指针

- 规则正文 / 执行机制 / 退出码 / 边界 → `docs/04-standards/agent-workflow/b-engineering-platform.md` §B13
- 守卫脚本 → `scripts/check-commit-hygiene.ps1`
- 拒绝列表 → `.forgeself/commit-hygiene.denylist.txt`（本地，不入库）
