# 跨 AI 规划交接与预注册验收（pilot-handoff）

> 适用：用户要求「只做规划与方案 / 输出完整文档 / 实现交给别的 AI / 完成后你验收」类任务。
> 本质：把 AI-Native 闭环的 Intent→Spec→Plan→Task 做成**不依赖规划者上下文**的交接包，并把 Test→Evidence→Review 的验收标准**在实现开始前**预注册，规划方事后独立复验。
> 实例（2026-10-01）：design-system 三里程碑 `docs/ai/pilot/2026-10-01-design-system-m{1-agent-tools,2-showroom-wizard,3-style-guideline}/`。

## 一、什么时候用

- 用户明确「只做规划，实现交给别的 AI」；或同一任务跨会话/跨人交接、事后由本会话（规划方）验收。
- 不适用：本会话一口气做完（走常规 AI-Native 闭环）；纯问答/查状态。

## 二、交接包 = 每任务一套 pilot 工件（00–07 八件，缺一不可）

- `00-repository-understanding`：技术栈/架构/测试方式**从真实仓库读出来**（禁止常识推测）；末尾放「开工前复核清单」（实现方第一步要做并写入 05 的动作，含如"先对未改动 Model.xml 跑 xcode 对表"这类环境对表）。
- `01-intent` / `02-spec`：规范九节 + 不确定点标 `Unknown`；AC 编号化（后续 05/06 逐行对表）。
- `03-plan`：**零自决契约**——文件级清单 + 实现契约详表（schema/公式/词表/白名单/步骤/测试计划），实现方不需要再做设计决策；末尾留「Plan 偏差记录」表。
- `04-task`：闸门状态表 + **显式待批事项表（每项带默认推荐）** + 交接说明（见 §三）+ Task Slices（每片可独立交付）+ 技能增补建议 + Verification Commands。
- `05-evidence`：骨架 + 只留待填栏位（来源等级 Verified/Inferred/Unknown；AC→证据矩阵；反向探针记录）；可预填规划会话的真实基线实测。
- `06-review`：**预注册验收清单**（见 §四）。
- `07-final-report`：骨架；各节在验收通过后由规划方填写。

## 三、交接说明（04-task 必含，逐条写死）

1. 分工声明：规划方不写业务代码；实现方独立实施并自证；规划方事后独立复验并签 06/07。
2. 读序（文件与节号精确到 §）。
3. 环境约束（实测过的）：TMP 重定向、UTF-8、verbose logger、总数==发现数、`--no-build` 期间不重编译。
4. **不可颠倒的顺序**（有则必须单列）——例："先录黄金基线，再改任何生成器代码"；"先对未改动 Model.xml 跑 xcode 对表，再加表"；"先写 schema2↔3 不凭空新增的用例，再改快照"。违反 = 验收直接 CHANGES_REQUIRED。
5. 检查点（CP-A/B/C → 片级验收）。
6. 证据纪律：05 只记真实发生；e2e 不可行标 Unknown + 替代证据；**06/07 结论栏实现方不得碰**。
7. 回报格式（状态五选一 / 05 路径 / 实跑命令与总数 / 偏差条数 / 未验证项 / 须用户授权动作清单）。
8. 范围纪律 + 失败处理（3 次失败回滚升级）。
9. 并行会话约束：共享文件只做局部精确替换、改前重读；他人改动不碰。

## 四、验收预注册（06-review 写什么）

- **V 清单**：每条 = 动作 + 通过判据（规划方将独立复跑，不采信 05 自述）。必含：
  - 前置闸门检查（前置里程碑验收通过、用户批准留痕）——缺则整体 BLOCKED。
  - 范围（Forbidden 零 diff、无新依赖）。
  - **反作弊点**：默认产物逐字节回归先于改动；生成物二次生成逐字节一致且无手改；升级路径（旧库/旧数据）独立复现；幂等重发；反射断言（无删除路由等）；测试质量形状（无永真断言 / 无被跳过用例 / 报告总数==发现数）。
  - **抽测**：不看 05，独立复现 N 条 AC（喂测试未覆盖的输入）。
  - 交给用户的口径项（文案审阅、发布授权）如实列"待用户"。
- **Final Decision 判定规则**（APPROVED / CHANGES_REQUIRED / BLOCKED）与"一律 CHANGES_REQUIRED"的硬红线清单。
- 07 的五步闭环表对"规划方不可代做项"（打 tag 发布 / 用户页面更新 / 只读复验）如实标"待用户授权"。

## 五、收尾（停下前）

- `scripts/verify-pilot-artifacts.ps1 -TaskId <dir>` 全部相关目录 PASS。
- 无关仓库文件零改动；插件类同步其 ROADMAP（指向 pilot 目录）；`TODO.md` 条目改为「规划完成，实现交接，待用户闸门1/闸门2」；日记勾选 + 完成记录；记忆文件回写。
- **不提交 git**；给用户的回复三件事：目录路径 / 一句话摘要 / 待拍板项（含每里程碑闸门1 是否已批、哪些点需要显式批）。

## 六、验收阶段（实现方交付后，回到本技能）

- 按 06 预注册清单独立复跑；先读 05 列声称 Verified 项，再抽测反作弊。
- 试后由**规划方**填 06 的审查八问/Final Decision 与 07；实现方只填 05。
- 验收通过 → 闸门3（提交授权）仍归用户；回归 AGENTS §11 闭环收口。

## 七、技能边界

| 阶段                           | 技能                                                             |
| ------------------------------ | ---------------------------------------------------------------- |
| 新建插件立项                   | `plugin-feasibility-study`（先）                                 |
| **跨 AI 规划交接与预注册验收** | **本技能** `pilot-handoff`                                       |
| 实现与门禁                     | `plugin-development`（转派各专项）                               |
| 交付证据的具体形态             | `design-system-verify` / `e2e-testing` / `plugin-publish-verify` |

> 新增技能须同步登记 `AGENTS.md` §2.4（不在表里 = 后续会话必漏读）。
