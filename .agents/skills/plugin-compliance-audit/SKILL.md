# 插件完整性 / 合规核对（逐项 · 改动面驱动 · 带证据）

**定位**：门禁只能做「文本模式」判断（裸色值、token 族、pilot 工件齐全、story 是否注册）；
本技能负责门禁**判不了**的部分——语义是否正确、渲染是否可读、状态是否有反馈、契约是否对得上。
按本技能走一遍，要求**每一项都留下证据**；没有证据的项一律记 `Unknown`，不许写「看起来没问题」。

> 与 `plugin-development` 的关系：它是「怎么改/怎么发」的总入口，本技能是**交付前的核对闸门**，
> 每次插件改动结束时由 `plugin-development` 转派到本技能，走完才允许宣称完成。

---

## 一、什么时候必须用（缺一不可，不靠自觉）

| 场景 | 是否必用 |
|---|---|
| 新插件第一次交付（或首次带 UI 上线） | ✅ 全量 |
| 任意插件的任意改动（后端 / 前端 / 样式 / 清单 / 文档 / 版本） | ✅ 按「改动面矩阵」过的项 |
| 修完一个缺陷（尤其"第二次出现"） | ✅ 全量 + 同类扫查 |
| 用户说「核对 / 自检 / 看看这个插件行不行」 | ✅ 全量 |
| 只读代码做调研、没改任何文件 | ❌ 不用（但仍不许拍脑袋回答事实问题） |

---

## 二、铁律（10 条）

1. **每一项都要有证据**：命令输出 / `文件:行` / 实测数值 / 截图路径。证据分三级：`Verified`（亲手跑过）> `Inferred`（读码推断，须标注依据）> `Unknown`（没查）。**不许把 Inferred 写成 Verified。**
2. **先划改动面，再挑检查项**：不许「全量跑一遍」当交差——按第一节矩阵，命中哪部分就过哪些项；命中多项就全过。
3. **门禁绿 ≠ 合规**：`design:check` / `pnpm run check` / vitest 绿只覆盖它们写得出的规则；语义与渲染必须靠本技能。
4. **结构存在 ≠ 能力可用**：有 story、有 e2e 文件、有按钮，都不等于「点了有反应、出错有提示、数据是真的」。
5. **不看图不算走查**：截图必须真的打开读过；只生成文件即 `Unknown`。
6. **默认主题 ≠ 暗色验证**：`system` 在 CI/Playwright 解析为浅色；暗色必须显式 `html.dark` 或切主题后再测。
7. **异步必须当场观感**：点一下就开始计时——≤100ms 有没有反馈？完成前是否先闪出「无数据/无表」？连点两次是否重复发请求？切走后旧响应会不会覆盖新选择？
8. **发现的问题不许"顺手带过"**：本批范围内→当场修并验证；同根因→`problem-class-closure` 同类扫查；异根因→记 `TODO.md`；门禁缺口→补守卫；规范缺口→回写真源文件（只写一处）。
9. **绝不改门禁语义来变绿**：基线只能降，判据只能更严；改判据必须走规范评审并留痕。
10. **核对报告必须落盘**：`docs/ai/pilot/<task>/` 或 `Plugins/<X>/docs/`，含每项结论与证据；聊天里只报路径 + 结论 + 待办。

## 三、第一步：划定改动面（30 秒）

```bash
git status --short                      # 改了哪些文件
git diff --stat                        # 规模
```

把改动映射到 A–H 八面，取并集即为**本次必过项**：

| 面 | 判定信号（文件路径/内容） | 必过项 |
|---|---|---|
| A 清单与身份 | `plugin.json`、目录改名、版本号 | P-01 P-02 P-19 |
| B 后端接口 | `Controllers/` `Services/` 工具注册、错误码 | P-03 P-04 P-05 P-06 P-17 P-21 P-24 |
| C 前端交互 | `web/src/**` 视图、事件、请求 | P-02 P-04 P-07…P-16 P-20 |
| D 样式与主题 | `<style>`、`*.css`、token 引用 | P-07 P-08 P-15 |
| E 测试 | `*.spec.ts` / `*.ct.spec.ts` / `*.story.ts` | P-15 P-16 P-17 |
| F 文档 | `docs/`、`README`、`ui-design-brief` | P-18 |
| G 发布 | 版本号、打包脚本、更新通道 | P-19 P-16 P-02 |
| H 权限与安全 | 路由鉴权、作用域、脱敏、审计 | P-03 P-21 P-24 |

**任何改动面都至少过**：P-02（加载得起来）、P-04（前后端字段对得上）、P-18（文档同步）、P-20（没污染宿主）。

## 四、第二步：逐项核对清单（P-01 … P-24）

每项格式：**怎么查 → 合格判据 → 不合格怎么办**。核对时逐条打勾并写证据。

### 身份与加载

- **P-01 清单一致**：读 `Plugins/<X>/plugin.json`。
  判据：`Id` 为 kebab-case、与目录 PascalCase 的映射正确、版本号与 `csproj`/发行串一致、`views[0]` 指向产物入口。
  不符 → 改清单，别改加载器。
- **P-02 真能加载**：构建 `cd Plugins/<X>/web && pnpm run build`，在真实宿主打开该路由。
  判据：页面正常渲染，**无** `.plugin-view-state--error`；浏览器控制台无 404（`/plugins/<id>/web/dist/index.js`）。
  404 先查「旧 Vite 复用」与「dist 未构建」，别急着改代码。
- **P-03 权限正确**：调一个**需鉴权**的只读端点。
  判据：带 token 200，不带 token 401；权限模式（如 AskWrite）与界面提示一致。
  401 立即上报，不许把空页当结论。

### 契约与数据

- **P-04 契约对齐**：逐字段对照后端 DTO 与前端 `types.ts` / normalize。
  判据：字段名（camelCase）、可空性、错误码/HTTP 状态（200/202/4xx/424）都有处理分支；**没有「后端给了但前端忽略」的字段**。
  不符 → 改前端 normalize 或后端 DTO，两边同时补断言。
- **P-05 边界与错误路径**：空结果、超长、截断、超时、非法输入逐个试。
  判据：每种都有明确反馈，不抛白屏、不静默失败；截断有 `truncated` 类标记并提示。
- **P-06 落盘位置**：代码只放 `publish/plugins/<Dir>/`，数据只放 `~/.forgeself/plugins/<id>/`。
  判据：新写的文件路径落在正确一侧；不把 dll 写进数据目录，反之亦然。

### 视觉与主题（本次事故的主战场）

- **P-07 颜色来源**：`scripts/style-token-baseline.json` 里该插件目录计数 + 新增改动是否含裸色值。
  判据：**新增裸色值 = 0**；存量只降不升；颜色一律 `var(--el-*)`。
  注意：**token 化 ≠ 安全**——值可以定义错，见 P-08。
- **P-08 亮/暗可读性实测**：打开页面，亮色一次、**显式暗色**一次，用 `getComputedStyle` 取实际 `color` 与 `background-color`，算 WCAG 对比度。
  判据：正文/选中行/标签/横幅 **≥4.5:1**；图标/大号字 ≥3:1；两态都记数值。
  重点表面：列表/树选中行、状态标签、信息横幅、禁用态、悬浮态。
  不达标 → 先查「背景级 token 是否被当文字色」（`color: var(--el-color-*-light-5..9)` 一律违规），再查主题 ramp 取值方向（暗色下 N 越大应越暗）。
- **P-09 五态齐备**：加载 / 空 / 出错 / 无权限 / 正常。
  判据：五态各有**可见**表现；空态有引导动作，出错态有原因+重试，无权限态说清要什么权限。
- **P-10 异步反馈**：对每个异步动作（点连接/切数据源/查询/保存/上传）实际点击并掐表。
  判据：≤100ms 出**局部** loading；**完成前不显示空态**；重复点击去重；旧响应不覆盖新选择（请求序号或取消）。
- **P-11 失败可重试**：制造一次失败（断网/非法 SQL/无驱动）。
  判据：错误可读 + 有重试入口；重试后状态回到正常，不需刷新页面。
- **P-12 交互语义**：「点 A 出现 B」与 Spec/`ui-design-brief` 一致。
  判据：逐条对照，无「点了没反应」「该弹窗却跳页」「同表重复开标签」等偏差。
- **P-13 数据形态**：0 行、1 行、超大行、超长字段、空字符串、null。
  判据：布局不塌、不溢出、有省略/截断提示。
- **P-14 可访问性底线**：Tab 可达、焦点可见、图标有 `aria-hidden` 或标签、`prefers-reduced-motion` 下不转圈。

### 测试与证据

- **P-15 组件状态基线（CT）**：`ForgeSelf.Web/src/components/<X>.story.ts` + `.ct.spec.ts` 是否覆盖关键状态（含 loading、空、错）。
  判据：有 **行为断言**（不只 `toHaveScreenshot`）；像素基线**读过图**；暗色基线缺失要明说（画廊固定暗色）。
  缺 → 补 story + 行为断言，别只补截图。
- **P-16 插件 e2e 冒烟**：`ForgeSelf.Web/e2e/plugins/<id>/<id>.spec.ts`。
  判据：至少 1 条主链路，**含运行态断言**（loading 可见、错误码可见、数据非空）；零 mock；截图落 `screenshots/e2e/<id>/`。
  缺（如 CostScope）→ 补，不允许以「插件能用」替代。
- **P-17 后端构建与测试**：`dotnet build` + 相关 `dotnet test`（含新逻辑的用例）。
  判据：构建绿、新增逻辑有测试、未删测试求绿。

### 文档、发布与影响面

- **P-18 文档同步**：`Plugins/<X>/docs/ui-design-brief.md` 五态与亮暗实测数值、接口/用法说明、`docs/02-features/<NNN>-*.md`。
  判据：文档与实现无矛盾；数值是实测的，不是抄的。
- **P-19 发布一致性**：版本号、产物、插件能否被更新通道识别。
  判据：发行串一致；只发插件时宿主无需重启；发布走 `plugin-publish-verify`，**禁止停/启/杀宿主**。
- **P-20 不污染宿主**：`ForgeSelf.Web/src/views` 未新增插件页面；未 `import` 宿主私有模块；共享依赖走 external + import map。
  判据：宿主侧改动为零（或仅共享层必需改动并已说明）。
- **P-21 安全**：密码/密钥掩码、SQL 注入面、命令执行面、日志与审计脱敏。
  判据：全页与所有输入框搜不到明文；危险操作二次确认；审计有记录。
- **P-22 状态与清理**：关闭/刷新/卸载插件后，定时器、订阅、草稿、临时文件是否残留。
  判据：刷新后草稿按设计保留或明确丢弃；无重复订阅、无泄漏的 interval；卸载后宿主无报错。
- **P-23 兼容性**：旧数据（旧版本字段）、驱动缺失（424）、旧配置、宿主版本差异。
  判据：降级路径明确（提示 + 可操作），不因缺失驱动/旧数据白屏。
- **P-24 可观测**：关键失败有日志/审计条目，含可定位信息（连接 id、操作、错误码）。

## 五、第三步：出核对报告（模板）

落盘到 `docs/ai/pilot/<task>/05-evidence.md` 或 `Plugins/<X>/docs/audit-YYYY-MM-DD.md`：

```markdown
## 改动面
A / B / C / D / E / F / G / H → 命中：B、C、D

## 逐项结论
| 项 | 结论 | 证据（等级） | 备注 |
|---|---|---|---|
| P-02 | PASS | 打开 /plugins/<id> 正常，控制台无 404（Verified） | |
| P-08 | FAIL | 暗色选中行 1.10:1（Verified，bg=#FDE68A / color=#FFF） | 已修/待修 |
| P-10 | Unknown | 未实测异步点击（未核） | 需在 B2 补 |

## 结论
- PASS：n 项｜FAIL：m 项｜Unknown：k 项
- 总结论：PASS / 有条件通过（FAIL 已修且复验）/ BLOCKED
```

总结论规则：**有任何 `Unknown` 且属于本次改动面 ⇒ 不许写 PASS**。

## 六、第四步：问题分流（发现即处置）

| 情形 | 处置 |
|---|---|
| 本批改动直接导致 | 当场修 + 复验，记入本批 05 |
| 同根因（如"背景级 token 当文字色"再次出现） | 走 `problem-class-closure`：同类扫查 + 守卫 + 归档 |
| 异根因、非本批 | `TODO.md` 记 P1/P2/P3 + 来源，不顺手改 |
| 门禁本该拦住却没拦 | 补守卫（静态规则 / 主题对比度脚本 / CT 行为断言），并加红灯用例证明确实能拦 |
| 规范没写清 | 回写**唯一真源**（`DESIGN.md` / 技能 / 02-spec 模板），不在第二份文档复制 |

## 七、反自欺清单（每次收口前逐条自问）

1. 这条结论是 `Verified` 还是 `Inferred`？命令输出在哪？
2. 我看了图，还是只生成了图？
3. `pnpm run check` 绿 = 合规吗？（它不含对比度、不含运行态）
4. 我只测了默认主题？暗色测了吗？
5. story/e2e 文件存在 = 有能力吗？（有没有行为断言）
6. 单插件绿 = 同类插件也绿吗？（同类扫查了吗）
7. 有没有把「改判据/放宽基线」当成修复？

## 八、收口命令（按改动面挑，全过才算完）

```bash
cd Plugins/<X>/web && pnpm run build          # 前端产物
cd ForgeSelf.Api.Tests && dotnet test          # 后端（含 filter 定向）
cd ForgeSelf.Web && pnpm run check             # vue-tsc + eslint + 组件规范守卫
cd ForgeSelf.Web && pnpm run design:check      # 裸色值 / token 族 / 主题守卫
cd ForgeSelf.Web && pnpm exec playwright test -c playwright-ct.config.ts src/components/<X>.ct.spec.ts
cd ForgeSelf.Web && pnpm run test:e2e -- e2e/plugins/<id>
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/check-problem-classes.ps1   # 缺陷类时
```

> 跑 e2e 前先按 `AGENTS.md` §5.0 设 `NO_PROXY` 与 `TEMP`；干净启动，避免复用旧 Vite（否则插件资源 404 会被误判成代码问题）。
