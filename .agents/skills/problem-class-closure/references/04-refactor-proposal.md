# 04 重构提案（P4）

## 与"无关重构"的边界（关键澄清，规范 v1.2.0 §1 第 5 条）

- **消除同一问题类的结构性修复不属于"无关重构"**——同根因扫查命中项按铁律 3 天然在本任务范围内；
- 属"无关重构"的是：顺手改与本 PC 不变量无关的代码（命名、格式化、性能微调）——一律不做，发现问题记 TODO；
- 判据：改动能否用一句「它在执行 PC-NNN 的 canonical fix」解释？能 → 范围内；不能 → TODO。

## R0-R3 分档

| 档 | 定义 | 审批 | 本任务内做什么 |
|---|---|---|---|
| R0 | 不值得重构（守卫已够） | 无 | 07 写"无 + 理由" |
| R1 | 局部：≤3 文件、同模块、不动公共契约 | 任务内做，07 披露 | 直接修 |
| R2 | 跨模块或动公共契约（API/DI 入口/前端封装层） | **闸门1 批准**（六段方案落盘 pilot 目录） | 按批文做 |
| R3 | 架构级（如统一注册入口、状态机收敛） | 升级 `architecture-design` + ADR + 独立 pilot | 本任务只做 G3 止血 + 提案登记 PC 守卫台账 |

## 提案的写法（07「重构提案」节固定格式）

```
档：R2
动机：一句话（哪条不变量、当前表达面为什么留了犯错空间）
改动：文件:行 → 动作（≤5 条，超 5 条说明该拆批）
不改：边界声明
代价回滚：1-2 行
状态：已批（闸门1，日期）/ 提案（待阶段四评估）/ 否决（理由）
```

## 主动提出（铁律 7）

- 每次缺陷收口都问一遍：**能不能改结构让这个错"写不出来"？**（G4 思路：`RegisterContract` 统一入口、authFetch 强制封装、dev-stack 脚本化都是范例）
- 提不出来也要写"无 + 理由"（如 PC-002：入口已存在，缺的是守卫不是结构）——空着不写 = 悬空教训，违反铁律 8。
- 提案默认**不在本批实施**（防范围失控），登记到 PC 守卫台账（G4 提案行）等阶段四批次统一评估；仅 R1 档当场做掉。
