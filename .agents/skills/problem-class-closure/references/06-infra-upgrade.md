## 技能侧上浮（大技能防膨胀）

- 教训**不回写进大技能正文**（`plugin-development` 已 74KB，`design-system-verify` 72KB——继续塞战争故事只会加速失效）；
- 技能只加**一行指针**（"改插件契约前先查 PC-001 lens"），内容留在 PC；
- 新增技能必须登记 AGENTS §2.4（不登记等于不存在）；本技能自身的迭代经验回写本 references，不扩 SKILL.md 正文（≤120 行是硬限）。

## 何时升级为"全量级开发任务"

上浮动作若触碰 `AGENTS.md`、规范、模板、hook —— 按项目规则本身就是动了流程宪法：**走完整 pilot 工件链 + 闸门1**，不能当免批文档补丁（问题类闭环机制自身的落地就是此例，见 `docs/ai/pilot/2026-10-17-problem-class-closure/`）。例外：往台账/case 里追加记录属免批动作（否则补账永远排不到——同 §2.5 文档回写逻辑）。

## 验证上浮生效（防"改了个没人走的入口"）

每个基建动作完成后，用**一次反向演练**证明它必然被经过：
- 改了 Spec 模板 → 下一个缺陷任务的 Spec 里该节真实出现；
- 改了 hook → 故意缺节提交被拒（红灯输出存证）；
- 加了守卫 → 故意植入违规 → 测试红 → 撤销 → 绿（红绿两跑都留日志）。
