# 智能体聊天页（重构）需求与验收标准

- 版本：v1.1（v1.0 按原型定稿；v1.1 补统一能力入口与助手面板自适应）
- 日期：2026-11-18（Asia/Shanghai）
- 状态：已补「统一能力入口」「助手面板自适应与插件复用」。前后端方案对齐后，测试补测试计划；门禁锁定前不开工
- 需求真源：本文件 + 同目录 `prototype.html`
- 能力范围真源：仓库 `docs/02-features/021-ai-agent.md` 及关联功能文档（工作流、记忆、技能、设计系统、项目工作区、待办、MCP 等）
- 插件：智能体（技术名 MAF，id `ai-agent`，路由 `/ai-agent`）

## 1. 目标

用全新组件替换现有智能体聊天页。页面要能完成四件事：下任务、看执行、能介入、可复盘。

实现约束：

- 不得读取、参考或复用既有智能体聊天页的视图、组件与布局。
- 不得把插件 `docs` 目录下既有的工作台原型或旧评审稿当作新界面来源。
- 视觉与交互以本目录 `prototype.html` 为准；截图见 `previews/`。
- 复用宿主已配置的模型，不另开账号。
- 高风险操作必须给人确认或取消的位置，即使后端审批通道尚未完全接通，界面也要预留，不能在这一轮拿掉。
- 本页与后续其它插件（如数据库、智能终端）共用同一套组件和同一套 Agent 能力入口，避免各插件各自实现一套助手。
- 旧聊天、计划执行、工作流若已对不上本页，不得继续作为主入口迁就使用；要重新提供统一入口，并实时展示执行过程。

## 2. 范围与非目标

**范围内**

- 智能体聊天页：会话列表、对话主区、输入区、右侧工作区。
- 开放任务与计划任务两种执行模式的界面。
- 执行中的观察、停止、高风险审批、卡住时介入、失败重试、完成后复盘。
- 右侧工作区的默认入口，以及可打开的面板：计划、执行记录、工作流、记忆、设计、建议、项目、待办、技能、工具、代码片段。
- 上下文附加（技能、提示词、记忆、MCP、项目、图片等）的入口，不在输入框上方常驻一排标签。
- 同一套组件支持两种呈现：整页三栏，以及收缩后的右侧助手面板；本轮必须预留嵌入契约（布局槽位、当前上下文、工具范围），供其它插件直接复用。
- 统一的 Agent 能力入口：供本页和其它插件调用，实时推送执行过程，并覆盖计划确认、审批、卡住时的跳过 / 补信息后继续 / 取消。

**非目标（本页不做）**

- 不产品化云端计算机或远程常驻沙箱。
- 不做团队共享工作区。
- 不另建第二套智能体运行时。
- 本页不承担即时通讯网关里的外部会话。
- 不在本页管理模型供应商账号。

## 3. 信息架构

从左到右三栏，外加页头：

1. **左侧**：本页会话列表。
2. **中间**：页头、对话（或空态）、输入区。
3. **右侧**：工作区。进入页面或没有需要强制打开的面板时，默认显示「打开面板」入口；点击某一项进入对应面板，顶栏「全部面板」返回入口。

页头（PageHead）：

- 眉题：等宽字体、金色，格式为「智能体 · 开放任务」或「智能体 · 计划任务」。
- 标题：当前会话标题，展示字体，约 26px。
- 主操作：每屏只有一个金色主按钮。默认是「新建会话」。当对话里或右侧出现决策主按钮（例如「确认并执行」「批准后执行」）时，「新建会话」改为幽灵按钮，把主按钮让给当前决策。

顶部宿主导航（铸己匣、智能体页签等）沿用宿主，不在本需求里重做。原型顶部的预览条和主题切换条只用于评审，不属于产品界面。

以上三栏是**整页模式**（路由 `/ai-agent`）的默认布局，视觉以 `prototype.html` 为准。同一套组件还必须能收成右侧助手面板，见 3.1；调用一律走统一能力入口，见 3.2。

### 3.1 助手面板（自适应与插件复用）

整页三栏与右侧助手面板是同一套实现的两种布局，不是两套页面。

**整页模式（默认）**：左会话、中对话与输入、右工作区，如现有原型。

**助手面板模式**：三栏收缩到宿主页面右侧的一个面板里，作为当前插件的 AI 助手。数据库、智能终端等插件直接嵌入这一套，禁止再各自实现聊天或执行界面。

面板形态的产品要求：

- 对话与输入始终在。下任务、看执行、能介入、可复盘在面板内成立，不能收成只剩一个输入框。
- 会话列表、工作区入口和各功能面板改为面板内的一层切换或展开（例如列表层、工作区层），不要求三栏同时铺开，但能力不能丢。
- 页头改为紧凑型：保留模式眉题和会话识别，主按钮规则不变——每屏只有一个金色主操作；出现「确认并执行」或「批准后执行」时，「新建会话」让位为幽灵按钮。
- 宽度跟随宿主给出的槽位自适应。变窄时优先保证对话和输入，会话与工作区从面板内入口进入，不得横向撑破宿主布局。
- 主题、会话方向、消息形态、工具行默认折叠、附加上下文规则与整页一致。
- 嵌入契约（本轮必须预留，由前端方案写清，实现时落地）至少包括：
  1. **布局**：宿主提供右侧槽位或容器，组件以助手面板模式渲染。
  2. **当前上下文**：宿主传入当前项目、工作目录、当前对象等，助手在这个上下文里工作。
  3. **工具范围**：宿主传入本插件允许使用的工具或能力边界；助手不越权使用未授权能力。
- 本轮验收看两件事：智能体页能切换或演示助手面板形态；嵌入契约已写清并在实现中预留。其它插件的实际挂载在契约就绪后接入，不另做第二套界面。

### 3.2 统一能力入口

本页和其它插件使用 Agent 能力，都走同一套入口，而不是各接各的旧接口。

- 现有聊天流、计划执行流、工作流进度如果已经对不上这版页面，不得继续作为本页或其它插件的主入口去迁就使用。要重新设计提供给前端及其它插件的统一入口。
- 该入口必须能实时推送执行过程，至少包括：文本、工具调用与结果、计划、步骤进度、审批、工作流状态。
- 必须覆盖人在回路：计划确认后再执行、高风险审批（批准后执行 / 取消）、运行中停止、卡住时跳过 / 补充信息后继续 / 取消。
- 开放任务与计划任务都走这一入口，用调用参数区分模式，而不是让前端拼多套互不相通的接口。
- 接口细节由后端方案给出。产品验收看：整页、助手面板、以及后续其它插件调用时，看到的是同一套执行过程与介入能力。

## 4. 会话方向与消息呈现

本页的方向与形态按原型约定，不按「通用聊天软件」自行改掉：

- **用户消息**：右对齐气泡。气泡上不标注「你」或其它身份标签。
- **助手消息**：通栏排版正文，不套气泡，也不标注智能体名称作为身份标签。
- **工具行为**：默认只占一行，展示工具名称和结果摘要，可展开看细节；默认不摊开原始数据结构。
- **高风险待确认**：出现在对话主区，说明风险并提供「批准后执行」与「取消」，不能只藏在右侧。
- 一旦有对话，消息从对话区顶部向下排列。右侧工作区开或关都不改这个起点。空会话仍是纵向居中的空态和输入框。
- 对话列占满中间栏的可用宽度，随页面变宽变窄，并在该栏内居中铺满。输入框保持较窄（最宽约 720px）并在栏内居中，不把对话列锁成输入框同宽。

## 5. 左侧会话列表

- 展示会话标题、模式（开放任务 / 计划任务）和状态（例如刚刚、进行中、计划待确认、待审批、已卡住、已完成、失败）。
- 当前会话有明确的选中态：金色左边线，不要用发光金框。
- 进行中、待确认、卡住、失败等状态用点或短文本区分，不用 emoji。
- 点击切换会话；「新建会话」进入空态。

## 6. 空态

新会话、空列表时的中间区域：

- 居中印章「匣」+ 衬线主句：「下任务、看执行、能介入、可复盘。」
- 一句说明：「选好智能体和模型，在下方说明你要做的事。」
- 下方是干净的输入框，输入框上方没有常驻标签。
- 右侧仍显示工作区入口，不因为是空会话就把右栏收掉。

## 7. 输入区

- 占位文案：「说明你要做的事。Enter 发送，Shift+Enter 换行。」
- 可切换开放任务 / 计划任务，并选择当前智能体和宿主已配置的模型。
- 左侧「+」为「附加上下文」菜单，至少包括：技能、提示词、记忆、MCP、项目、图片。选中后在输入框上方出现少量可移除的附加标记；没有附加时不占那一行。
- 发送按钮：默认金色主操作（箭头）。任务进行中变为朱砂停止按钮，并有说明：任务进行中，可以停止，或等它完成后再继续追问。
- 发送后进入真实对话流；本原型未接模型，实现时要接到现有开放任务与计划任务接口。
- 不另开模型账号。可在输入区附近保留一句说明：「复用宿主已配置的模型，不另开账号。」

## 8. 右侧工作区

### 8.1 默认入口

右侧栏在本页默认打开，不依赖某次运行才出现。

入口标题为「打开面板」，一句说明：「从这里进入计划、记忆、工作流等。对话进行中也可以随时切换。」

每一项包含：名称、一句说明、当前状态。状态随会话变化，例如：

| 面板 | 说明 | 状态示例 |
|------|------|----------|
| 计划 | 先看步骤，确认后再执行 | 无计划 / 待确认 |
| 执行记录 | 本轮步骤、工具结果与轮次 | 暂无 / 进行中 · 3/20 / 待审批 / 卡住 / 已完成 / 失败 |
| 工作流 | 关联工作流的执行与控制 | 未启动 / 执行中 |
| 记忆 | 本轮检索到的条目，可写回 | 条数 |
| 设计 | 组件与令牌预览，默认不写库 | 无预览 / 有预览 |
| 建议 | 按最近习惯推荐下一步 | 条数或暂无 |
| 项目 | 当前工作目录、档案与命令 | 未绑定 / 项目名 |
| 待办 | 可下发给智能体的任务 | 待处理条数 |
| 技能 | 本智能体已启用的技能 | 已启用个数 |
| 工具 | 本轮可见的宿主与 MCP 工具 | 已连接或可见范围 |
| 代码片段 | 本轮产出或收藏的片段 | 暂无 / 个数 |

点击一项打开对应面板。面板顶栏提供「全部面板」返回入口，不覆盖对话。

需要用户立刻处理的内容（待确认计划、正在跑的工作流、卡住的执行记录等）可以自动打开对应面板，但仍必须能回到入口、改开其它面板。空会话、普通进行中的开放任务、对话里已经展示审批卡片时，右侧默认停在入口。

### 8.2 计划

- 展示目标、步骤、约束。
- 确认前不开始执行。
- 主按钮「确认并执行」，次按钮「改计划」（可在右侧改步骤，或在输入框说明怎么改）。
- 确认后按步骤执行，并可在执行记录里看到进度。

### 8.3 执行记录

- 无记录时的空态：说明开始任务后，步骤、工具结果和轮次会显示在这里。
- 进行中：展示当前轮次（如 3 / 20）和步骤状态（完成 / 进行中 / 失败 / 卡住）。
- 已完成、失败、卡住时从入口也能打开同一份记录，作为复盘入口。
- 失败提供「重试」；卡住的处理见第 10 节。

### 8.4 工作流

- 展示关联工作流的步骤与当前状态。
- 提供暂停、取消。
- 工作流里若仍有高风险步骤（例如写文件），要在执行到该步时再次确认，不能因为工作流已启动就跳过确认。
- 异步启动后的进度要能在本面板持续看到，不能打开后就没有下文。

### 8.5 记忆

- 展示本轮检索到的记忆条目（分类或来源可标出）。
- 提供把本轮结论写回记忆的动作，写回是明确操作，不是静默覆盖。

### 8.6 设计

- 展示本轮相关的组件预览与设计令牌。
- 默认不写入设计系统。写入必须是明确的主操作，并在确认后才写库。

### 8.7 建议

- 根据最近习惯或当前上下文给出下一步建议（例如转到工作流、写记忆、下发待办）。
- 每条建议可执行或可忽略，点击后进入对应动作，而不是一句空文案。

### 8.8 项目

- 展示当前绑定的工作目录、档案摘要、可运行命令。
- 未绑定时要明确「未绑定」，不要假装已有项目。
- 运行命令若属高风险，走对话里的确认，不在本面板直接执行高风险操作。

### 8.9 待办

- 展示可下发给智能体的待办（目标、范围或验收可在条目中看到）。
- 支持将某条待办下发给当前智能体。

### 8.10 技能

- 展示当前智能体已启用和未启用的技能。
- 本面板用于查看本轮会用到的技能；启用或关闭放到智能体设置，不在对话里直接改配置。

### 8.11 工具

- 展示本轮可见的宿主工具（由该智能体的工具白名单决定），以及已连接的 MCP 服务。
- 未连接 MCP 时要说明「未连接」，连接后出现在同一份名单里，并受同一套白名单约束。
- 本面板只展示，不在这里直接执行工具。高风险操作仍在对话里确认或取消。

### 8.12 代码片段

- 无片段时给出空态说明。
- 有片段时按条目展示（语言或用途、内容），并提供复制。
- 智能体在对话中给出可复用的命令或代码后，应能收入本面板。

## 9. 两种执行模式

**开放任务**

- 用户直接下任务，智能体在多轮中使用工具推进，直到结束或被停止。
- 界面要能看到正在做的事（工具行、执行记录、进行中状态），而不是只有一段正在生成的文字。

**计划任务**

- 先出计划，用户确认或修改后再执行。
- 执行中可在步骤上介入：补充信息后继续、跳过、取消。
- 计划在右侧以文书形式出现，不只是对话里的一段列表。

两种模式都在输入区可见、可切换；页头眉题要与当前模式一致。

## 10. 人在回路

- **停止**：运行中可将发送按钮改为停止，停止后任务不再继续调用工具。
- **高风险审批**：例如执行终端命令、写到敏感位置。对话中给出简要风险说明、将执行的命令或动作，「批准后执行」或「取消」。未批准不得执行。
- **卡住**：智能体无法继续时，执行记录或对话给出原因，并提供补充信息后继续、跳过或取消。
- **失败**：给出失败步骤和原因，提供重试。
- **完成**：对话给出结论，执行记录可复盘。

## 11. 视觉与主题

必须使用本项目主题（`workshop-forge` 与 `DESIGN.md` 的 token），只使用 `--el-*` 与设计 token，禁止自造 `--surface-*`、`--forge-*`、`--app-*` 一类变量。

- 默认深色；浅色为宣纸「白日工坊」。
- 字体：标题用 Noto Serif SC，正文 Inter，代码与眉题 JetBrains Mono。
- 主色金大约 8%，朱砂大约 2%，其余为中性。金色约 `#F59E0B`。
- 圆角不超过设计 token 的最大档；按钮用中小圆角，禁止 9999px 胶囊按钮（极小状态点或标记除外）。
- 三禁：无 emoji、无胶囊按钮、无蓝紫渐变。
- 空态用图标（印章）加衬线句，不用插画堆砌。
- 悬停用轻微上移（`translateY(-1px)`），不用放大。
- 玻璃模糊不得调高到超过主题规定（18 / 24）。
- 对话优先：主区不要再套一层玻璃大卡片；右侧是文书式面板，不要卡片套卡片。

## 12. 验收标准

以下为必验项。测试计划须同时覆盖功能（F）与交互（I），含 v1.1 增补的 F27、F28、I13。环境以宿主实际运行环境为准（当前项目以 Linux 宿主为主）；每一项通过都必须有截图或录屏等证据，没有证据记为未跑，不能记通过。

### 12.1 功能

| ID | 必验 | 步骤与预期 |
|----|------|------------|
| F01 | 是 | 新聊天页为独立实现。代码与界面不得复用既有智能体聊天页或工作台旧实现。对照本需求与原型验收，不以旧页为参照。 |
