# 智能体聊天页（重构）测试计划

- 版本：v1.1
- 日期：2026-11-18（Asia/Shanghai）
- 状态：已按需求 v1.1 与对齐后的前后端方案补全 F27、F28、I13；门禁尚未锁定，本文件不宣布通过
- 需求真源：同目录 `01-requirements.md`（v1.1）与 `prototype.html`
- 方案对照：前端 `03-frontend-component-scheme.md`；后端统一入口 `/api/agent`（发送 202，`GET .../events?after=seq` 订阅）
- 视觉对照：同目录 `previews/`（§13 全部场景）
- 能力范围真源：仓库 `docs/02-features/021-ai-agent.md` 及关联功能文档
- 插件：智能体（id `ai-agent`，路由 `/ai-agent`）

本计划覆盖全部必验项 **F01–F28** 与 **I01–I13**。功能和交互都要测；没有对应宿主或真实页面证据的项记 `not-run`，不能 `pass`。实现者不得自行把项标为 `pass`。

## 1. 原则

- 对照本目录需求与原型验收，不以既有智能体聊天页或工作台旧实现为参照。本页与助手面板只走新的统一能力入口 `/api/agent`，不得以旧的聊天流、计划执行流、工作流进度接口作为主入口。
- 原型顶部预览条和主题切换条只用于评审，不属于产品界面，不纳入通过条件。
- 顶部宿主导航沿用宿主，本计划不重测。
- 高风险确认必须出现在对话主区（「批准后执行」/「取消」）；未批准不得执行。即使后端审批通道未完全接通，界面也必须预留并按本计划验证。
- 复用宿主已配置的模型，不另开账号，本页不管理模型供应商账号。
- 本页不做：云端计算机 / 远程常驻沙箱、团队共享工作区、第二套智能体运行时、即时通讯网关里的外部会话。智能终端、数据库等其它插件的实际挂载本轮不测（契约与加载器要预留）；不得因为它们尚未挂载就把 F28 记为失败，也不得另做第二套界面。
- 深色为默认产品主题；浅色（宣纸「白日工坊」）至少在 I01 跑一次，确认仍然可读。
- 通过口径：Linux 或 Windows 任一真实宿主（打开产品页，不是只打开 `prototype.html`）截图即可关闭单项，另一系统只做补强。画廊、夹具、纯原型预览只算预检。

## 2. 环境与证据

- 环境：已挂载智能体插件的控制台宿主，路由 `/ai-agent`。宿主已配置至少一个可用模型（可继续用关键词模拟上游，但必须走宿主已有提供方，不在本页新建账号）。
- 建议准备：一个已启用技能的智能体、可触发高风险动作的命令或写文件步骤、可启动的工作流、至少一条记忆、一个已绑定项目与一个未绑定对照、若干待办、已连接与未连接的 MCP 状态、可产出代码片段的任务。
- 证据目录（实现后建立，先按此命名）：`/workspace/acceptance-gates/evidence/ai-agent-chat-redesign/`
- 文件名：`{ID}-{场景}-{系统}.png`，例如 `F04-open-run-stop-linux.png`、`I08-empty-linux.png`。同一张图可同时作为多个 ID 的证据，在记录里交叉引用，不要为凑数重复截无差别图。
- 每条记录：结果（`pass` / `fail` / `blocked` / `not-run` / `waived`）、证据路径、环境与系统、日期（Asia/Shanghai）、执行人。
- 代码类项（F01、I01 的 token 检查、F27 的入口路径检查、F28 的嵌入契约预留）除截图外，需附检索或接口/类型检查说明。
- F28、I13 必须有助手面板形态的实现截图，不能只交整页图。面板预览若尚未补入 `previews/`，以实现对齐需求 §3.1 与前端方案第 4、5 节为准。
