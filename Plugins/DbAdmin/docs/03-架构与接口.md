# 03 · 架构、数据模型与 HTTP 接口

## 1. 执行链路（定稿：XCode `DAL`）

```
Controller / ToolFunction
  → SqlGuard（分类 + 硬拒）  → ApprovalQueue（AskWrite）
  → DbConnectionService.Resolve(connId)
      系统连接：直接用已注册 ConnName（宿主 / PluginDbs），标记 ReadOnly
      用户连接：ConnName = "DbAdminU_<id>"，首次 DAL.AddConnStr(name, connStr, null, provider)
  → var dal = DAL.Create(name)
  → dal.Tables（schema） / dal.Query(sql, params)（读） / dal.Execute(sql, params)（写）
  → ResultLimiter（Agent：1000 行 / 256KB；UI：分页）
  → AuditWriter（脱敏）
```

- 一律参数化（字典或 `IDataParameter[]`）；分页由服务端包装，不信任客户端拼 LIMIT  
- 用户连接 ConnName 前缀 `DbAdminU_` 隔离，**不得**写入 `XCodeConfig.PluginDbs`，不得与宿主 ConnName 重名  
- 只读判定在服务端：系统连接对 `Execute` 一律硬拒（不仅靠 UI）  
- 驱动：**2026-11-06 起暂时关闭预检**（`DriverCatalog.ProbeEnabled=false`）——不探测驱动，交给 XCode 在连接期自行获取；失败按底层异常返回 `sql_error` + 脱敏消息。预检开启时仍走 `driver_missing` + 包名提示。

## 2. 插件自有数据（ConnName `DbAdmin`，`Data/Model.xml` → xcode）

| 实体 | 关键字段 |
|------|----------|
| `DbConnection` | Id, Name, Provider, Mode(form/connstr), Host, Port, Database, UserName, **PasswordEnc**, ConnStrEnc, Readonly, CreateTime, UpdateTime |
| `DbQueryHistory` | Id, ConnectionId, SqlRedacted, Kind(read/write), RowCount, ElapsedMs, Success, Error, Source(ui/agent), CreateTime |
| `DbApproval` | Id, ConnectionId, SqlRedacted, Kind, Destructive, Status(pending/approved/rejected/expired), Source, CreateTime, ResolveTime |
| `DbAuditLog` | Id, Kind, ConnectionId, SqlRedacted, Decision, Detail, CreateTime |

- `Data/DbAdminTables.cs` 的 `EnsureCreated()` 在插件启动路径调用  
- 唯一性（连接名）直查 DB，不用 `Meta.Cache`  
- 业务写 `.Biz.cs`；密码字段加解密在 Biz 层  
- 审批中的原始 SQL 仅内存持有（批准后执行），落库为脱敏版

## 3. HTTP（前缀 `/api/db-admin/*`，类级 `[Authorize("ApiKeyPolicy")]`）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/providers` | provider 列表 + `driverAvailable`（预检关闭时恒 `true`） |
| GET | `/connections` | 系统只读 + 用户连接；密码掩码 `****` |
| POST | `/connections` | 新建（用户连接） |
| PUT | `/connections/{id}` | 编辑；密码空 = 不改 |
| DELETE | `/connections/{id}` | 仅删配置（二次确认），**不删库文件** |
| POST | `/connections/test` | 测连（未保存的表单也可）；返回 `{ok, code}`，见 3.1 |
| GET | `/connections/{id}/tables` | 表/视图 |
| GET | `/connections/{id}/tables/{table}` | 列、主键、索引 |
| POST | `/query` | `{connectionId, sql, params?, page, pageSize}` → 只读结果 / 或 `awaiting_approval` / `rejected` |
| GET | `/approvals` · POST `/approvals/{id}/resolve` | 审批队列 |
| GET | `/history` · GET `/audit` | 历史、审计（分页过滤） |
| GET/PUT | `/permission-mode` | 查看 / 修改当前模式 |

错误统一 `{code, message}`，`code ∈ rejected_hard | readonly_connection | driver_missing | sql_error | not_found | unauthorized`。其中 `driver_missing` 仅在驱动预检开启（`DriverCatalog.ProbeEnabled=true`）时产生，当前默认关闭。

### 3.1 已定契约（2026-11-04，前后端对齐；以本节为准）

JSON 一律 camelCase。前端 `web/src/normalize.ts` 是唯一适配点；后端按下列形态输出，前端文件不因本节修改。

**① 审批 resolve**：`POST /approvals/{id}/resolve`，请求体 `{decision: "approve" | "reject", confirmDestructive?: boolean}`。
- `decision` 为其它值时返回 400 `invalid_request`。
- 破坏性语句（DROP / TRUNCATE / ALTER…DROP）必须由 UI 发起且 `confirmDestructive=true`，否则返回 409 `confirmation_required`；Agent 永远无法批准破坏性语句。
- 审批已处理过返回 400 `invalid_request`；审批不存在或已过期（30 分钟 / 重启）返回 404 `not_found`。
- 响应体与 `/query` 相同（QueryOutcome）：`approve` 成功为 `status:"ok"` 带 `affectedRows`，`reject` 为 `status:"rejected"`、`code:"approval_rejected"`。

**② 响应字段**
| 项 | 定稿 |
|---|---|
| 查询结果 | `columns: string[]`，类型另给 `columnTypes: string[]`（按下标对应）；`rows: any[][]`；另有 `total, page, pageSize, truncated, affectedRows, elapsedMs, approvalId, destructive, code, message` |
| `/query` 状态码 | `ok` 和 `rejected`（业务拒绝：`rejected_hard` / `readonly_connection`）都返回 200；`awaiting_approval` 返回 202；`error` 按 code 映射：not_found 404、driver_missing 424、sql_error / invalid_request 400 |
| 列表形态 | `providers / connections / tables / approvals` 返回**数组**；`history / audit` 返回**分页对象** `{items, total, page, pageSize}`（前端 `listOf` 两者都接受） |
| 测连 | 永远 200：`{ok: boolean, code: "ok" \| "sql_error" \| "driver_missing", message, serverVersion?}`；预检关闭时失败恒 `sql_error` + 底层错误（脱敏），`driver_missing` 仅预检开启时出现且 message 含包名 |
| provider id | **以后端小写为准**：`sqlite / mysql / postgresql / sqlserver`。前端自行适配展示（`SQLite` 等仅作 displayName）。服务端输入大小写不敏感（`SQLite` / `SQLITE` 均可），存储与输出统一为小写 |
| kind | 对外只有 `read` / `write`；破坏性用独立字段 `destructive: true` 表达（query 结果、approvals 均有）。history 的 kind 同样只有 read / write |
| id 类型 | 连接 id 是**字符串**：用户连接为数字串 `"12"`，系统只读连接为 `"sys:<ConnName>"`。approval / history / audit 的 id 以及 `approvalId` 是 JSON **数字**（Int64）；前端 normalize 统一 `String()` |
| 连接视图 | `password` 恒为 `****` 或空；`connStr` 为掩码串；`kind: "user" \| "system"`（前端据此推断 `system`）；`readonly` 布尔 |
| source | `ui` / `agent` |
| 时间 | ISO 8601 本地时间字符串 |

**③ 审批轮询**：前端每 5 秒调用 `GET /approvals?status=pending`。
- 开销小：pending 判断走 `Status` 索引；单次最多 200 条，按 id 倒序；过期清理只扫内存里的待审字典和 pending 行；不连目标库，也不执行 SQL。
- 结构稳定：始终返回数组，元素为 `{id, connectionId, sqlRedacted, kind, destructive, status, source, createTime, resolveTime}`；无变化时连续两次返回完全一致（单测守卫）。
- `sqlRedacted` 已脱敏，原始 SQL 只在内存里，不经此接口下发。

**④ S8 Agent 回显：由审计承载，不新开接口**。调用 `GET /audit?kind=agent`，可选过滤参数 `sessionId`、`connectionId`、`status`、`source`、`from`、`to`、`page`、`pageSize`。
- 记录时机：Agent 每次调用 `db_query_readonly`、`db_execute_write` 或 `db_resolve_approval`，产生一条 `kind="agent"` 摘要（UI 发起的查询不产生）。
- 审计视图在 `kind=agent` 时额外给出：`tool`、`status`（ok / awaiting_approval / rejected / error）、`code`、`sqlKind`（read / write）、`rowCount`（返回行数或影响行数）、`truncated`、`approvalId`、`sessionId`、`source`；`sqlRedacted` 与 `detail`（message）均已脱敏，参数值不落库。
- 对应 `DbAuditLog` 新增列：`Source, SessionId, Status, Code, SqlKind, RowCount, Truncated, ApprovalId`（Model.xml 已改并由 xcode 重新生成；旧库由 XCode 反向工程自动补列）。
- 前端 `AgentToolEcho` 的映射：`tool ← tool`、`status ← status`、`rowCount ← rowCount`、`truncated ← truncated`、`approvalId ← approvalId`、`message ← detail`、`at ← createTime`。`args` 前端只展示 `sqlRedacted`。

**⑤ 前端注册**：在 `plugin.json` 中注册。
```json
"frontend": { "views": ["DbAdminView"], "menu": "数据库管理", "route": "/db-admin", "icon": "fa-database", "entry": "web/dist/index.js" }
```
与 `web/vite.config.ts`（lib 模式，产物 `dist/index.js` + `dist/style.css`）以及 `web/src/index.ts`（导出 `DbAdminView`）一致。宿主 StageAllPlugins 会拷贝 `Plugins/*/web/dist/**`，约定同 SmartTerminal。
