# 05 · 已知风险：多引擎与密码

## 1. 多引擎「未实测」

- 定稿：MVP 支持 SQLite / MySQL / PostgreSQL / SQL Server 等，**验收仅实测 SQLite**  
- 其它引擎：配置页、测连、驱动缺失提示必须可用；文档与 UI 标「未实测」  
- 方言差异（分页语法、schema 元数据、标识符引号）依赖 XCode provider，未覆盖的问题记 `TODO.md`

## 2. 额外 NuGet provider

- 宿主当前仅随附 **SQLite**（`XCode.SQLite`）  
- 其它引擎需在 `DbAdmin.csproj` 引入对应 provider/驱动包（如 MySQL、Npgsql、Microsoft.Data.SqlClient 系）并设 `CopyLocalLockFileAssemblies=true`  
- 风险：插件输出目录体积变大；与宿主共享 DLL 版本冲突（混入宿主共享 DLL 会导致宿主启动崩溃）；原生依赖的 RID 差异  
- 对策：发布脚本校验不覆盖宿主共享 DLL；驱动加载失败统一映射 `driver_missing`，不让插件整体加载失败  
- **已定（见文末决策 1）**：MVP 不打包，仅做「驱动缺失」提示。原问题：是否 MVP 即打包这些驱动，或仅做「驱动缺失」提示由用户另装（定稿要求「可配置、可使用」，倾向打包）

## 3. 密码

- 插件库加密存储（密钥来源：插件数据目录下本机密钥文件或宿主 DataProtection，已定：插件数据目录本机密钥文件，见文末决策 2）  
- 后续可迁宿主 vault  
- 原始连接串模式同样加密整串，GET 只返回掩码版本

## 4. 数据安全红线

- 插件**绝不**自动删除任何数据库文件 / 数据目录；删除连接只删配置  
- 测试库指向随机隔离目录


## 研发决策（2026-11-04，后端 MVP 定稿）

### 决策 1：驱动打包 —— MVP 不打包非 SQLite 驱动，缺驱动明确提示
- SQLite：沿用宿主已带的 System.Data.SQLite，实测可用。
- MySQL / PostgreSQL / SQL Server：**不随插件打包**，也**不允许 XCode 运行时自动下载驱动**。
- 理由：① 驱动包（MySqlConnector / Npgsql / Microsoft.Data.SqlClient）与宿主共享依赖（System.* / 原生 SNI 等）有覆盖冲突风险，宿主 StageAllPlugins 按 bin 平拷；② 自动下载在离线/内网环境不可控且属执行外部代码；③ 插件体积与未实测引擎的维护成本。
- 行为：`GET /providers` 返回 `driverAvailable`/`driverPackage`/`tested`；测连或执行时缺驱动统一返回 `driver_missing`（HTTP 424）并带包名，插件本身照常加载。用户把驱动 DLL 放入宿主目录或插件目录后重启即可识别（`DefaultDriverProbe` 依次查已加载程序集、类型名、宿主/插件/数据目录 DLL）。
- 后续：若产品坚持「开箱可用」，再按引擎逐个评估打包并补实测，改动集中在 `DriverCatalog.cs` 与 `DbAdmin.csproj`。

### 决策 2：密钥来源 —— 插件数据目录本机密钥文件
- 文件：`<插件数据目录>/dbadmin.key`，32 字节随机密钥，首次启动以 CreateNew 生成，Unix 下权限 0600；**不入库、不进日志、不随接口返回**。
- 算法：AES-256-GCM，密文格式 `v1:` + base64(nonce12 | tag16 | cipher)；带版本前缀便于后续换算法/轮换。
- 加密对象：表单模式的密码（PasswordEnc）、连接串模式的整串（ConnStrEnc）。GET 一律返回 `****` / 掩码连接串；PUT 传空或 `****` 表示不改。
- 未选宿主 DataProtection：插件子容器拿不到宿主 DataProtection 契约（插件开发规范禁止构造注入宿主契约），且其密钥环在用户 Profile，迁移/备份数据目录时会与密文分离。
- 已知风险：拿到数据目录（DbAdmin.db + dbadmin.key）即可解密；**密钥文件丢失则已存密码不可恢复**（需重新录入）。备份/迁移须二者同带。后续可迁移到系统凭据库（DPAPI/Keychain/libsecret）或宿主统一 vault，`ISecretProtector` 已抽象。
