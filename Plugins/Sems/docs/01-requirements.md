- 版本：v1.0
- 日期：2026-11-19（Asia/Shanghai）
- 插件：软件工程管理系统（id：`sems`，路由：`/sems`）
- 对照基线：`main` [`900a528`](https://github.com/OpenForgeSelf/OpenForgeSelf/commit/900a528)（工作台 1.3.0）
- 状态：产品已梳理。测试先按本文对需求并完善测试计划；前后端再按本文核对并改实现。门禁锁定前不得宣布完成，也不得自行合入 main。

## 1. 定位

SEMS 是铸己匣里管理「本机软件项目」的工作台，做五件事：登记项目、维护并运行命令、查看执行、沉淀规格与验收覆盖、只读查看该项目自己的工程插件。

一句话：管项目、跑命令、看执行、记规格、看项目插件。

它不是包管理器，不是插件市场，不是 MCP 工具目录，也不是云端沙箱或团队共享工作区。复用宿主已有的项目档案与模型配置，不另开一套账号或运行时。

与相邻能力的边界：

- 项目档案仍落在宿主项目登记（`IProjectRegistry`）。SEMS 是主要的自助管理界面；智能体把工作目录登记为项目（来源 `ai-agent`）与在本页手工登记互不覆盖。
- `sems_*` 工具继续经能力中心对外提供给智能体调用，但这是接口能力，不是项目工作台里的一屏。
- 「运行」指本项目已登记命令的进程与日志，不是待办插件里的任务，也不是智能体会话。

## 2. 本轮决策（相对 1.3.0 工作台）

用户已授权产品对不合理功能直接取舍。对照当前实现，决定如下。

### 2.1 纠正「插件」屏

1.3.0 把项目壳里的「插件」做成 22 个 `sems_*` 工具清单（经能力中心暴露的 MCP 工具）。这不是项目相关插件，不能再作为产品界面。

本轮保留「插件」这一屏，但语义换成**当前项目已声明的工程插件**，优先覆盖前端项目（从项目根目录 `package.json` 的依赖里识别构建/框架/代码质量类插件）。只读展示，不安装、不升级、不卸载，也不执行 `npm` / `pnpm` / `yarn`。

没有前端清单或未声明任何插件时，显示空态说明，**不得**回退展示 `sems_*` 或任何宿主插件/MCP 工具。

仪表盘上的「可用工具 22」以及指向该工具清单的入口一并去掉；若展示插件数量，只统计本项目工程插件。

### 2.2 正名并收拢信息架构

1.3.0 用交接包的 11 屏去套现有实体：导航写「依赖」，实际是运行命令；「任务」与「依赖」又各挂一份命令维护，重复且易混。

本轮项目内导航改为五栏：

| 导航 | 内容 |
|------|------|
| 概览 | 项目档案摘要与真实统计（运行中会话、命令数、规格数、本项目插件数） |
| 运行 | 运行命令的维护，以及启动、停止、本机检测、日志 |
| 规格 | 规格版本、关联变更、反查、验收用例覆盖 |
| 插件 | 本项目工程插件（只读） |
| 设置 | 项目档案编辑，以及真实生效的显示偏好 |

工作台顶层仍是：项目列表、登记、导入。

### 2.3 砍掉的界面与方案

- 在项目工作台展示 `sems_*` / MCP 工具清单，或把它叫作「已装插件」。
- 导航或文案用「依赖」指代运行命令；本轮也不做 `package.json` 全量依赖树，更不提供「安装依赖」。
- 面向用户的「经典视图」切换、「恢复示例数据」、DEMO 模式。工作台是唯一产品界面。经典实现可暂时留在代码里便于对照，但默认不再出现入口。
- 状态栏里没有行为的装饰控件（无点击含义的图标等）。状态栏只保留有用信息：当前项目路径（可关）、运行中数量、工作台版本、时钟。
- 2026-10-26 `requirements.md` 中的「AI 原生开发管理平台」方案（容器沙箱、云端形态、任务队列平台等）不纳入本轮，也不作为后续默认路线。
- 登记/导入项目时创建磁盘文件、初始化仓库、执行安装命令，或做插件市场/脚手架。

### 2.4 保持不变的核心能力

- 项目档案的登记、浏览目录、编辑、移除（移除只删档案和命令，不动磁盘）。
- 运行命令的增删改，在项目根目录启动与停止，检测本机已属于该项目的进程，查看日志，启动全部。
- 规格只追加版本、手工关联 commit / PR / Issue、按标识反查、验收标准用例登记与覆盖查看。已登记用例标识不表示用例已通过。
- 现有 22 个 `sems_*` 工具的对外契约本轮不改，作为回归范围，不在工作台做目录页。

## 3. 信息架构与主路径

- 进入 `/sems` 即进入工作台，默认落在项目列表。
- 未打开项目时：顶栏在「项目 / 登记 / 导入」之间切换。登记为两步向导：确认目录 → 填写档案。
- 打开项目后：左侧为项目切换与上述五栏；主区只显示当前栏。
- 路径不可达时，列表与项目壳都要明确提示，允许编辑档案或移除，但启动命令不可用。

## 4. 功能需求与验收标准

下列条目是本轮必验范围。没有对应证据不得记 pass。

### 4.1 项目档案

**F01 项目列表**  
列出已登记项目，至少展示名称、类型、标签、描述、根目录、来源、是否 git 仓库、路径是否可达。无项目时是空态，并引导去登记或导入。列表/卡片两种布局可切换，刷新后保持。

**F02 登记项目**  
可通过逐级目录浏览或填写本机绝对路径，确认一个已存在的目录，再填写名称等档案后写入列表。来源记手工登记。过程不创建、不修改项目目录里的文件，不执行 git 或包管理命令。目录不存在或不可读时不能完成登记，并说明原因。

**F03 导入项目**  
从目录浏览选择已有目录并登记到列表，规则与 F02 相同（不改磁盘）。同一路径已登记时不得再生成一条互相覆盖名称的新档案，应明确提示已存在并可打开原项目。

**F04 编辑档案**  
可修改名称、类型、标签、描述。根目录只读。保存失败可在原处重试，不丢未提交的修改提示。

**F05 移除项目**  
需二次确认。确认后移除档案并级联删除该项目的运行命令，磁盘文件与目录保持不动。列表中不再出现该项目。

**F06 登记来源共存**  
智能体将某目录登记为项目后，本页能看到该项目；在本页编辑档案不得把来源改写掉，也不得因再次登记同一路径而覆盖已有手工修改的名称与描述。

### 4.2 运行命令与执行

**F07 维护运行命令**  
在「运行」页维护命令：名称、脚本、运行后访问地址、排序。可新增、编辑、删除。删除需确认。列表按维护结果即时更新，不再另开一个叫「依赖」的页面承载同一份数据。

**F08 启动命令**  
在项目根目录执行已登记脚本，会话进入运行中，运行计数加一。若填写了访问地址，运行中可打开该地址。路径不可达或没有命令时，不能启动，并说明原因。

**F09 停止会话**  
可停止由本页启动的会话；运行计数与列表状态同时更新，不得出现「列表已停、计数仍在跑」。按本机进程标识停止外部捕获的会话时，也要同步状态。

**F10 检测本机进程**  
「检查」能捕获本机已在运行、且判定属于当前项目的进程，并并入运行列表，不重复创建无法对应的幽灵会话。

**F11 启动全部**  
对当前项目全部可启动命令逐一启动。没有命令时按钮不可用，不得空转成功。

**F12 运行日志**  
选中一条运行记录立刻拉取日志；运行中定时追加并滚到最新；结束后保留日志与结束时间，记录不消失。停止后不得继续按「运行中」追加。

**F13 空内容不可执行**  
命令名或脚本为空时不能保存，也不能触发启动。不要先提交再弹出「不能为空」之类的失败提示。

### 4.3 规格与验收覆盖

**F14 新建规格**  
标题与正文必填，验收标准可后补。创建后列表出现该规格，版本为 v1。

**F15 只追加版本**  
追加新版本不得覆盖已有版本。可按版本号读取历史版本。列表默认显示最新版版本号。

**F16 关联变更**  
可手工登记 commit、PR 或 Issue 等关联，并在规格详情中看到。

**F17 按标识反查**  
输入已登记的关联标识，能找到对应规格版本；没有匹配时给出空结果说明，不报错中断。

**F18 验收用例覆盖**  
可为某版验收标准登记用例标识，并查看覆盖情况。界面须写明：已登记只表示写下了标识，不表示用例已通过。没有验收标准时，不能登记用例。

### 4.4 项目工程插件（本轮重做）

**F19 只读识别项目插件**  
打开「插件」页时，只读扫描当前项目根目录，展示已声明的工程插件。本轮范围以前端项目为主：读取根目录 `package.json` 的 `dependencies`、`devDependencies`、`optionalDependencies`，将名称符合下列规则的包视为插件：

- `vite-plugin-*`、`*-vite-plugin`、`@vitejs/plugin-*`
- `rollup-plugin-*`、`unplugin-*`
- `babel-plugin-*`、`@babel/plugin-*`
- `eslint-plugin-*`、`@*/eslint-plugin-*`、`eslint-config-*` 不计入（配置包不是插件）
- `prettier-plugin-*`
- `@vue/cli-plugin-*`、`vue-cli-plugin-*`
- `*-webpack-plugin`、`webpack-plugin-*`

每条至少展示：包名、声明版本、分组（构建 / 转译 / 代码质量 / 框架 / 其他）、来源（`package.json`）。不读取 `node_modules`，不判断是否已经安装，避免把「未安装」做成猜的状态。

后端提供只读查询（建议 `GET /api/projects/{id}/engineering-plugins`），扫描失败（文件不是合法 JSON、目录不可读）时页面说明原因，列表为空。

**F20 搜索与分组**  
插件可按名称或分组搜索；无匹配时显示「没有匹配的插件」，不是空白死页。

**F21 空态，且禁止回退成工具清单**  
无 `package.json`、或有清单但识别不到插件时，空态文案说明「未发现本项目声明的工程插件」，并提示本页不展示能力中心工具。列表中不得出现任何 `sems_*` 工具名，也不得出现宿主其他插件的 MCP 工具。

**F22 不做安装与变更**  
本页没有添加、下载、安装、升级、卸载、启用/停用等会改动磁盘或执行包管理器的操作。

**F23 概览数字一致**  
概览上的插件数量等于本页识别到的插件数，不得写死为 22 或「Sems 已注册能力」。命令数、规格数、运行中会话同样取真实数据；不得再把命令数标成「依赖项」。

### 4.5 设置、对外工具与产品壳

**F24 项目设置**  
可编辑档案（同 F04）。显示偏好只保留真实生效的项：项目列表的列表/卡片布局、状态栏是否显示项目路径。变更立即生效并在刷新后保持。不得再放写了却不生效的开关。

**F25 对外工具回归**  
经能力中心可列出并调用现有 22 个 `sems_*` 工具，分组仍为：项目档案 4、运行命令 4、运行会话 5、项目规格 9。本轮不改工具名、权限与既有语义。工作台不得再做这一清单的产品页。

**F26 单一工作台入口**  
`/sems` 只有工作台这一套产品界面。没有「切换经典视图」「恢复示例数据」；也没有面向使用的 DEMO 模式横幅或入口。

### 4.6 交互与视觉

**I01 导航与文案**  
顶层与项目内导航符合第 3 节。不得再用「依赖」指代运行命令，不得再用「插件」指代 `sems_*` 工具，不得用「任务」与待办插件混淆——本页对应能力的导航名是「运行」。

**I02 每屏一个主按钮**  
遵循主题规范：每屏仅一枚金色主操作。破坏性操作（移除项目、删除命令等）用朱砂样式，并先确认后执行。页头若已有主操作，列表或页脚不得再放第二枚金色主按钮。

**I03 空态**  
列表类空态为图标加一句说明，并在有下一步时给出动作（例如去登记项目、去添加命令）。不要空白或只显示「暂无数据」。

**I04 窄宽度**  
项目壳在约 320px 宽的面板或窄窗口中，导航、主按钮和页脚说明仍可用，不被裁切，消息或列表面不出现无意义的横向滚动。

**I05 主题**  
使用 `workshop-forge` 与 `DESIGN.md` 的主题 token（`--el-*` 与设计 token），禁止自造一套工作台颜色变量去延续交接包样式。字体为 Noto Serif SC / Inter / JetBrains Mono。禁止 emoji 装饰、禁止胶囊按钮（极小标签和开关除外）、禁止蓝紫渐变。玻璃模糊不得高于既有上限（18/24）。PageHead 为等宽金色眉题 + 衬线 26px 标题。悬停用 `translateY(-1px)`，不用放大。

**I06 状态栏**  
只保留有意义的状态。去掉无行为的装饰图标。路径显示受 F24 开关控制。

**I07 危险与失败**  
启动命令、移除项目、删除命令前要确认。接口失败时在当前页说明，并保留可重试路径，不把页面打成不可恢复的空白。

## 5. 对外工具清单（回归，非界面）

保持现有 22 个工具，供智能体与外部调用，不在本页做市场或目录：

- 项目档案：`sems_list_projects`、`sems_register_project`、`sems_update_project`、`sems_remove_project`
- 运行命令：`sems_list_commands`、`sems_add_command`、`sems_update_command`、`sems_delete_command`
- 运行会话：`sems_list_runs`、`sems_check_runs`、`sems_run_command`、`sems_stop_command`、`sems_stop_run`
- 项目规格：`sems_create_spec`、`sems_add_spec_version`、`sems_get_spec`、`sems_list_specs`、`sems_link_spec`、`sems_list_spec_links`、`sems_find_spec_by_ref`、`sems_link_spec_case`、`sems_get_spec_coverage`

本轮若为 F19 新增只读查询接口，属于工作台使用的 HTTP 接口，不强制再包一个 MCP 工具；若补工具，须是只读查询，不得具备安装或改盘能力。
