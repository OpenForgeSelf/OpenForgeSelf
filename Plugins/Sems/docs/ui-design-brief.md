> - 若设计师交回稿件后发现需求缺口,先回写本文再改实现,保持本文为交互设计唯一真源。

**怎么用这份文档:** 你只需要这份文档就够了。每个模块写了"有什么、点什么出现什么、必须出现的状态和文案"。交付形式(一个 HTML 加相关文件)由你定,但最终要能点出本文所有交互,并让我们用文末的核对清单逐条验收。
标记说明:【已有】是已上线功能,需要保留并重新设计;【新增】是提案功能,尚未实现。
凡是文中没给数值的地方(时间阈值、保留期限、预算、次数上限、判定口径),界面里写"可配置"或"待定",不要自己编数字。

## 一、产品与角色

**一句话:** 以前的开发平台管人提交的代码,这个平台管 Coding Agent 的工作:任务、会话、轨迹、权限和产出。目标是产出可信、可追溯、成本可控。

**入口:** 只有一个菜单"软件工程管理",路径 `/sems`。所有新页面都挂在它下面,不新增一级菜单。规格区放在项目卡片内部,从"规格"进入。

**角色:**
- **规格制定者:** 写需求和验收标准,维护上下文资产,回答澄清与决策请求。
- **评审者:** 审计划、审变更,批准或驳回。
- **资深评审人:** 鉴权、支付、数据迁移类变更的指定审批人。
- **人类责任人:** 每个变更必须有一位。
- **平台管理员:** 维护准入清单、阈值、分级规则、数据策略。
- **系统设计者:** 看代码库健康和资产关系。
- **值班人员:** 审批生产修复。
- **Agent:** 不是界面用户,但它的身份、状态、轨迹、升级提问要在界面里出现。

## 二、全局规则(每个页面都适用)

1. **五种状态:** 每个数据页都要画出加载、空、出错、无权限、正常。空态必须带"下一步动作"按钮。
2. **禁用要说原因:** 任何禁用的按钮,悬停或旁边要有具体原因,比如"该项目有运行中的会话,先停止才能删除"。
3. **二次确认:** 删除、停止、驳回、接管等不可恢复操作要弹确认框,写清对象、后果、能否恢复。**高危动作审批**(见模块 4)在视觉上要和普通确认明显不同。
4. **自动刷新不闪:** 状态轮询刷新时,不丢滚动位置、不清空正在输入的内容、不整页闪。
5. **长文本:** 路径、命令、提交哈希、标题都要能超长。截断显示,可查看全文。窄屏布局不破。
6. **密钥:** 令牌和密钥只显示"已设置"或末 4 位,永远不出现明文。
7. **颜色:** 用 Element Plus 组件,颜色用 `--el-*` 变量和 Tailwind,不写裸色值,浅色和深色都要给。状态不能只靠颜色,要配文字或图标。键盘可操作,文字对比度达到 WCAG AA。
8. **建议与事实分开:** AI 写的摘要、诊断、修复建议,统一贴"建议"标签,样式上与系统记录的事实区分,不能看起来像已经执行。
9. **责任人与审计:** 任何变更相关页面都显示人类责任人。审计记录只读,界面上没有任何编辑或删除入口。
10. **不展示虚荣指标:** 任何位置都不出现"AI 生成了多少行代码"。
11. **术语一致:** 全稿只用这些词:任务(Agent 被分派的一件工作)、会话(项目命令启动出来的进程)、轨迹(Agent 一次任务的完整动作记录)、规格、门禁(合并前必须通过的自动检查)、任务契约(任务开始前约定的目标、范围、验收条件)、上下文包(交给 Agent 的、筛选过的任务上下文)、决策请求(需要人拍板的问题)、范围扩张请求(Agent 想超出计划范围时发起的申请)。不要混用。
12. **示例数据:** 每个列表都做 0 条、1 条、很多条三种情况,并包含超长路径、命令、哈希、标题。
13. **【新增】事实标签:** 凡是描述"现状"的条目(现状识别结果、上下文包条目、证据),都带三种标签之一:已验证、推断、未知。标签要有文字和图标,不能只靠颜色。"推断"和"未知"条目旁给"去核实"入口。
14. **【新增】证据出处与过期:** 任何"通过"或"已完成"旁边都能点开出处:提交版本、环境、时间。提交版本变化后,旧证据自动显示"已过期",不再计入完成。
15. **【新增】"待我处理"入口(此条为我们的提议,待确认):** 页面右上角固定入口,带数量角标,汇总我名下待办的计划审批、高危动作审批、范围扩张请求、决策请求、升级提问。

## 三、模块(点什么 → 出什么)

### 模块 0:项目与运行命令【已有】

**数据:**
- **项目:** 名称、根目录(唯一键)、类型(frontend / backend / fullstack / library / tool / other,也可自定义)、描述、标签(逗号分隔)、来源(manual 手工 / ai-agent 自动登记)、创建时间、更新时间、最近活跃时间。另有两个只用于展示的标记:目录是否存在、是否 git 仓库。
- **运行命令:** 名称、脚本、访问地址(可空)、排序。
- **运行会话:** 一条命令启动后的进程。至少要显示:命令名、是否存活。其余字段你按合理方式补。

**交互:**
- **项目列表:** 按最近活跃倒序。每张卡片显示名称、根目录、类型、标签、来源、目录不存在警示、git 标记、运行中会话数。【新增】卡片上再显示"接入成熟度"进度(见模块 21)。
- **点"登记项目":** 弹出表单,字段是根目录(必填)、名称、类型、描述、标签。根目录旁有"浏览"按钮。
  - **点"浏览":** 出现目录选择器,只列当前目录的直接子目录,不显示文件,不递归。点子目录进入下一层,有"上一级"。选中后回填根目录。
  - **提交:** 目录不存在时,在字段处报错"目录不存在"。
  - 根目录已登记过时,不覆盖已有信息,只刷新活跃时间,界面提示"该项目已登记,已刷新活跃时间"。
- **点"编辑项目":** 可改名称、类型、描述、标签。根目录不可改(显示为只读)。
- **点"删除项目":**
  - **有存活会话:** 按钮禁用,原因"有运行中的会话,先停止"。后端也会拒绝(冲突),界面要能显示这条错误。
  - **无存活会话:** 弹确认框,写明"将删除项目档案及其全部运行命令,不会删除磁盘上的任何文件,不可恢复"。
- **命令区(卡片内展开):**
  - **命令列表:** 按排序显示,每条有名称、脚本(截断)、地址、启动按钮、编辑、删除。
  - **点"添加命令":** 表单字段是名称、脚本、地址(可空)、排序。表单上方有醒目提示:"该脚本会在项目根目录以命令行执行,请确认内容可信"。提交前再确认一次。
  - **点"启动":** 该命令出现一条运行会话,显示"运行中"。
    - 同一条命令已有存活会话时,启动被拒,提示"命令不存在或已有存活会话(重复启动被拒绝)"。
    - 有地址的命令,会话旁给"打开"链接。
  - **点"停止":** 确认框"将结束该会话及其全部子进程",确认后会话变为已停止。找不到存活会话时提示"未找到存活的会话"。
  - **点"检测":** 扫描本机进程,把属于该项目的运行中进程显示出来。结果区分"由本平台启动的会话"和"检测到的本机进程",两者要看得出区别。
- **页面固定提示:** "运行会话只保存在内存,宿主重启后清空"。

### 模块 1:规格【部分已有】

**数据:**
- **规格:** 标题、内容、作者、备注、版本(从 v1 起递增)。【新增】再加:生命周期标签、权威状态、责任人。
- **验收标准:** 每条有编号(如 AC1,同一版本内不重复,不区分大小写)和文字。
- **关联:** 版本、类型(commit / pr / issue 等)、引用值(如哈希或编号)。
- **用例登记:** 版本、验收标准编号、用例标识,格式"测试文件路径::用例名"。

**交互:**
- **项目卡片 → "规格":** 进入规格列表,每行显示标题、最新版本号、作者、更新时间。【新增】列表再加三列:生命周期标签、权威状态、用例覆盖(如"3/5")。空态按钮"新建规格"。
- **点"新建规格":** 表单字段是标题(必填)、内容(必填)、作者、备注、验收标准列表。
  - **验收标准列表:** 每行是编号加文字,有"添加一条"和"删除"按钮。编号重复时,在输入框处报错。
  - **提交:** 空标题或空内容不能提交,字段处提示。创建后自动是 v1。
- **规格详情:**
  - **顶部:** 版本切换器,默认最新版。切到旧版本时出现醒目横幅"正在查看历史版本 vN,只读"。
  - **主体:** 标题、内容、验收标准、作者、备注、时间。
  - **没有编辑按钮,只有"追加新版本":** 修改永远产生新版本,旧版本不被覆盖。
- **点"追加新版本":** 表单带入上一版内容,可改内容、作者、备注、验收标准。
  - 不动验收标准时,提示"验收标准将沿用上一版"。
  - 改动验收标准时,提示"新标准编号与旧用例关联可能不再对应,旧版本的关联保持不变"。
- **关联区:**
  - **点"登记关联":** 选类型,填引用值,绑定到当前查看的版本。
  - **列表:** 每条显示类型、引用值、所属版本。升版本后,旧关联仍显示原版本号,界面要看得出"它指向的是 v1,不是最新版"。
  - **没有任何关联:** 显示空态。
  - **反查入口:** 输入类型和引用值,点"查找",显示它所依据的规格及版本。找不到时显示"没有找到对应的规格"。
  - 同一规格可对应多个变更,同一变更也可对应多个规格。
- **验收标准覆盖区:**
  - **总览:** "N 条标准,已登记用例 M 条"。
  - **逐条:** 每条标准显示"已登记(用例标识列表)"或"未登记"。
  - **"已登记"绝不能用代表通过的绿色对勾,** 因为它只表示登记过,不表示测试通过。建议用中性色加"已登记"字样。
  - **点"登记用例":** 选标准,填用例标识。输入框有格式提示"测试文件路径::用例名"。标准不存在时报错"规格 vN 没有验收标准 X"。
  - 同一条用例重复登记只显示一次。
  - **规格没有验收标准时:** 覆盖区显示专门的空态"该规格还没有验收标准",并给"追加新版本并添加标准"的入口。
  - 用例登记按版本固定,切版本时覆盖区跟着切。
- **【新增】生命周期标签:** 每个规格有一个标签,三选一,标签名称可调整,但三种情况的界面差异必须都有。
  - **持续维护:** 正常显示"追加新版本"。
  - **不可变基线:** "追加新版本"禁用,原因"该规格是不可变基线,请发起变更"。旁边出现"发起变更"按钮,点后进入变更申请表,填变更原因,提交后创建一个任务。
  - **探索中:** 页面顶部横幅"该规格处于探索阶段,确认新意图后需做规格协调"。点"完成规格协调"前,标签不能改成其他值。
- **【新增】权威状态与责任人:**
  - **规格详情顶部:** 显示"权威意图"或"待确认",以及规格责任人。
  - **点"确认为权威":** 只有责任人可点,其他人看到禁用并写明原因。确认要填理由,并记录谁、何时。
  - **AI 提出的修改:** 不直接生成新版本。它显示为"待确认修订",带"建议"标签,并列出与当前版本的差异。责任人可"采纳"(生成新版本)、"退回修改"或"拒绝",三个操作都要填理由。
  - **固定文案:** "AI 不能自行改写权威意图"。

### 模块 2:上下文资产【新增】

**对象:** 规则文件、架构文档、编码规范、领域知识、技能、工具(MCP 服务器)。每项有类型、所属层级(组织 / 团队 / 仓库)、版本、最近更新时间。

**交互:**
- **资产清单:** 可按类型、层级筛选。每行显示名称、类型、层级、版本、更新时间、新鲜度标记。
  - **超过新鲜度阈值的资产:** 显示"可能过期"标记。阈值显示为"阈值由管理员配置"。
- **点"查看某仓库生效规则":** 选仓库后,列出最终生效的规则集合。**每条规则标注来源层级。** 下层覆盖上层时,上层那条显示为"已被覆盖",并能看到被谁覆盖。
- **点"修改规则":** 提交前先点"评估影响",列出受影响的仓库和团队。影响范围为空时显示"没有受影响的仓库"。
- 规则变更若尚未经过回放评测,在这里显示"未评测"标记(见模块 12)。

### 模块 3:任务(分派、契约、计划审批、监控、接管、升级提问)【新增】

**任务状态:** 排队中、澄清中、阻塞待决策、待计划审批、执行中、等待范围扩张审批、等待人回答、已被接管、已完成、已超时、已超预算中止、已中断、已恢复。状态名可调整,但这些情况每一种都要有。

**交互:**
- **任务列表:** 每行显示标题、负责 Agent、状态、阶段/进度、风险等级(低/中/高/严重)、影响模块数、预算使用、责任人、更新时间。可按状态筛选。
- **点"分派任务":** 表单字段如下:
  - 来源工单。
  - 负责 Agent。
  - 使用模型。
  - 仓库。
  - 预算上限(可配置)。
  - 网络出口范围。
  - 运行形态。
  - 人类责任人(必填)。
  - **提交前就要提示的拒绝原因:** 模型未准入、仓库禁止代码出域、没设预算、没选责任人。出现这些情况时,"提交"按钮禁用并写明原因。
- **【新增】任务契约:** 表单顶部选"轻量契约"或"完整契约"。
  - **轻量契约:** 用于小任务,字段少,只有目标、范围、验证命令。
  - **完整契约字段:** 目标、范围(分"允许修改"和"不修改"两栏)、相关规格(从规格列表选,可选版本)、验收条件、约束、依赖、风险、验证命令。每条验收条件旁要指定证据类型,类型取自模块 6 的 7 类。
  - **必填口径:** 目标必填,其余字段是否必填显示"待定"。
  - **选了相关规格后:** 验收条件区提供"从规格验收标准导入"。
  - **影响范围提示:** 任务影响的模块数超过阈值(可配置)时,出现提示条"该任务影响范围较大,建议拆分",并列出受影响的模块。有两个操作:"拆分任务"和"确认继续"。点"确认继续"必须填理由。
- **提交后:** 任务进入"澄清中"(见模块 18)或"待计划审批"。
- **【新增】阶段:** 任务详情顶部有阶段条,共 8 个阶段,**名称待定,先用"阶段 1"到"阶段 8"占位。** 点开某阶段,卡片统一显示四项:目标、决策点、必要输入与输出、完成条件。内容先留"待定"。
- **计划审批:**
  - **页面显示:** Agent 给出的计划(标注"建议"标签)、涉及的文件和动作。
  - **【新增】计划必须回答六个问题,逐项显示:** 问题出在哪里、计划修改哪些组件、每项修改对应哪条需求或约束、是否影响公共接口 / 数据库 / 权限 / 其他模块、用哪些测试证明、哪些行为不应受影响。
  - **【新增】需求映射:** 计划里每项修改旁有"对应需求"链接,点开跳到规格或任务契约里的那一条。没有对应需求的修改用"无对应需求"警示色标出。
  - **【新增】是否需要独立审查:** 跨模块、数据迁移、权限、安全、破坏兼容这五类必须由人审。低风险小任务可免审,但页面要显示免审原因。
  - **固定文案:** "未批准前,任务不会进入实现"。
  - **三个操作:** 批准、要求修改、驳回,**都要填理由。** 审批人没有权限时,按钮禁用并说明原因。
- **【新增】范围扩张请求:**
  - **触发:** 执行中 Agent 想改计划以外的文件或模块时,任务进入"等待范围扩张审批",并出现一张卡片。
  - **卡片显示:** 新增的文件或模块、理由(带"建议"标签)、风险说明。操作是批准、拒绝,**都要填理由。**
  - **拒绝后:** 任务回到"执行中",按原计划范围继续,卡片留痕。
  - **固定文案:** "未批准前,Agent 不会修改计划范围以外的内容"。
  - **未经批准却实际超出范围时:** 在模块 6 的"范围"门禁里显示失败,并列出超出的文件。
- **任务详情(执行中):**
  - 当前阶段和进度条。
  - 轨迹时间线:Agent 的动作、对话、工具调用,按时间排列,可展开。
  - 沙箱信息。
  - 成本消耗。
  - 工作区。
  - 【新增】页签:契约、澄清、上下文包(模块 19)、计划、验证(模块 6 的证据与门禁)。
- **点"接管":** 确认框"接管后 Agent 将停止修改该工作区,由你继续"。确认后,状态变为"已被接管",页面横幅显示"Agent 已停止,当前操作者:某某"。
  - **"交还 Agent"按钮:** 在"已被接管"状态下出现。
  - 接管瞬间若有未完成的修改,要提示"有未提交改动"。
- **Agent 升级提问:**
  - **提问卡片:** 任务进入"等待人回答",列表出现醒目标记,同时产生通知。
  - **点开:** 看到问题、相关上下文、轨迹片段。直接在页面输入回答并提交,任务继续。
  - **无人响应:** 显示"等待中 N 小时",超时后的处理规则显示"待定"。
- **异常状态展示:**
  - 超时的任务显示"已超时,已回收"。
  - 超预算的任务显示"已超预算中止"及原因。
  - 平台重启后的任务显示"已恢复"或"已中断"。

### 模块 4:高危动作审批中心【新增】

**高危动作清单:** 删除、外发数据、修改 CI 配置、引入新依赖。

**交互:**
- **待审批列表:** 每条显示动作类型、对象(具体文件、地址、依赖名)、发起 Agent、所属任务、发起时间、触发来源。
  - **触发来源是不可信输入时(Issue 文本、网页、依赖文档、日志),** 这条要有醒目标注,例如"此动作由外部文本触发,文本如下",并展示那段原文。
- **点开一条:** 显示详情和风险说明。三个操作:批准、拒绝、拒绝并标记来源可疑。**都要填理由。**
- **固定文案:** "未经人工确认,该动作不会执行"。
- **引入新依赖:** 详情里显示"该包是否在可信源中"的校验结果。不在可信源时,默认状态为"待确认",并有提示"可能是 Agent 虚构的包名"。
- **批量审批:** 允许勾选多条,但**来源不可信的条目不允许批量批准**,必须逐条审。禁用时写明原因。
- **超时未处理:** 默认结果显示"未执行"。

### 模块 5:Agent 身份与权限【新增】

**权限级别:** 读代码、改代码、提交、合并、访问生产环境。每级可配不同审批策略(自动 / 需人工确认 / 禁止)。

**交互:**
- **Agent 列表:** 每个 Agent 显示独立身份、当前任务数、权限摘要。
- **点"新建 Agent 身份":** 填名称,逐级设置权限和审批策略。页面说明"Agent 不继承开发者的全部权限"。
- **权限变更:** 点"保存"前显示"变更前 / 变更后"对比,保存后写入审计。
- **越权请求被拒:** 在"审计"里能看到这条,内容是谁请求、什么动作、被拒原因。
- **审计列表:** 只读。每条能回答"谁执行、何时、谁批准"。没有编辑和删除入口。

### 模块 6:变更评审与验证证据【新增】

**变更详情页包含:**
- **基本信息:** 变更标题、关联规格(及版本)、Agent、模型、人类责任人。【新增】再加三个角色并列显示:执行者、审查者、合并授权人。同一个主体担任多个角色时显示警示;高风险变更不允许同一主体兼任,"批准"按钮禁用并写明原因。
- **【新增】完成状态:** 页面顶部用五选一显示:已完成、带风险完成、部分完成、未完成、阻塞。不出现"差不多""基本完成"这类说法。点状态可看判定依据。
- **门禁结果:**
  - **【新增】先显示一条"六组门禁条":** 范围、契约、规格测试、回归、资产同步、风险审查。每组显示结论(通过 / 失败 / 跳过 / 未运行)和判定方式(机器检查 / AI 评审 / 人工)。关键组不能只由 Agent 对自己的工作自评通过,出现这种情况时显示"需机器或独立检查"。
  - **再往下是技术检查明细(原有):** 逐项列出测试、静态分析、类型检查、SAST、SCA、密钥泄露、许可证检查,每项通过或失败。明细放在可展开区域,不必归到某一组里。
  - **失败项:** 展开可看原因。
  - **任一硬性项失败:** "合并"按钮禁用,原因"门禁未通过:xxx"。
- **【新增】验收证据矩阵:**
  - **行:** 每条验收条件。
  - **列:** 7 类证据:行为正确、接口兼容、数据正确、权限正确、架构合规、交付范围、构建与部署。
  - **单元格五种状态:** 通过、失败、未执行、已过期、不适用。五种都要有不同样式,且不只靠颜色。
  - **点单元格:** 侧边出现出处面板,显示日志正文、提交版本、环境、时间。
  - **提交变化后:** 旧证据自动变"已过期",变更的完成状态随之回退。
  - **不适用的格子:** 显示"不适用",不能留空。
- **风险等级:** 低 / 非低(分级规则可配置)。涉及鉴权、支付、数据迁移的路径要明确标出,并显示"需要指定资深人员批准"。任务和变更的风险标签点开可看判定依据。
- **AI 评审摘要:** 带"建议"标签。内容是意图与实现的对照,以及标出的高风险改动。**固定文案:** "AI 评审不能取代人的最终判断,非低风险变更必须至少一名人批准"。
- **行为证据:** 预览环境链接、端到端测试结果、截图或录屏。含界面改动但没有证据时,显示"缺少截图或预览"的提醒。
- **测试有效性:** 标出"可能自证正确"的测试(例如没有有效断言的测试),显示原因。
- **验收标准对应:** 关联规格的每条验收标准是否已登记用例(复用模块 1 的"已登记"表达)。

**交互:**
- **点"批准":** 必须已指定责任人。没有责任人时按钮禁用并写明原因"未指定人类责任人,不能合并"。
- **点"驳回":** 填理由。驳回意见会成为"改进候选"的来源(见模块 13)。
- **点"合并":** 低风险且门禁全过时才可点。非低风险要先有人的批准,涉及指定路径要先有资深人员批准。
- **资深人员缺席:** 显示"等待指定审批人"。
- **验证失败时:** 失败项旁出现"去分诊"入口(见模块 20)。

### 模块 7:溯源查询【新增】

- **入口:** 在变更列表或变更详情点"溯源"。
- **一屏内看到:** Agent、模型版本、规格版本、上下文版本、授权人、人类责任人。【新增】再加任务契约版本、上下文包版本,以及执行者、审查者、合并授权人。每项可点进去看原始记录。
- **点"查看轨迹":**
  - **轨迹仍在保留期内:** 展开时间线,查看粒度显示"待定"。
  - **未保留或已过期:** 显示"该变更未保留轨迹"或"轨迹已过保留期",并给出原因,不要显示空白。
  - 保留期限显示为"可配置"。

### 模块 8:运行时与沙箱【新增】

- **运行概览:**
  - 队列与并发,显示"运行中 X / 上限 Y,排队 Z"。
  - 运行形态:本地、云端、后台。首批支持哪些显示为"待定",三种都画出入口。
  - **并发已满时:** 新任务显示排队位置。
- **工作区列表:** 每个任务一个独立工作区。显示任务、工作区路径、状态。同一仓库的两个任务,界面要看得出它们互不可见。
- **网络出口配置:** 每个任务可配置允许范围。
  - **被禁止的访问:** 在"出口被拒记录"里可查,内容是时间、任务、目标地址。
- **密钥:** 显示"临时注入,任务结束后失效",只显示"已设置"。任务结束后,状态变为"已失效"。
- **超时回收:** 超时任务显示"已超时,已回收"。

### 模块 9:模型与工具治理【新增】

- **准入清单:** Agent 和模型两张表,每项有"已准入 / 未准入"。**未准入的不可被选中。**
- **数据策略:** 按仓库或数据分级配置"代码是否允许出域、供应商是否允许留存或训练"。标为"禁止出域"的仓库,在分派任务时模型下拉里,会使代码出域的模型禁用并写明原因。
- **模型路由:** 按任务类型选模型的规则表。
- **账号与计费:** 任一任务能查到所用模型和计费归属。
- **模型升级:** 把某个模型设为默认前,必须有评估记录。没有记录时"设为默认"按钮禁用,原因"缺少评估记录",并给出评估入口(见模块 12)。

### 模块 10:成本治理【新增】

- **成本报表:** 可在任务、团队、项目三个维度之间切换汇总。
- **预算设置:** 设单任务预算上限,设并发限制。超限后动作(暂停或终止)显示"待定"。
- **预算达到上限:** 任务被中止,任务详情里显示原因"已达预算上限"。
- **异常告警:** 疑似陷入循环的任务出现在告警列表,有"查看任务""暂停""终止"操作。判定规则显示"待定"。
- **预算为 0 或未设:** 分派任务时提示,不允许提交。

### 模块 11:度量【新增】

- **时间段选择:** 可选起止日期。
- **五类指标:**
  - **流动效率:** 需求到上线周期、PR 创建到合并时间、评审等待时间。
  - **质量结果:** 变更失败率、回滚率、缺陷逃逸率、返工与代码流失率。
  - **Agent 表现:** 任务一次成功率、人工介入率、被拒绝的 PR 比例。
  - **成本效率:** 每个成功合并任务的成本。
  - **【新增】规格与追踪:** 需求可验证率、追踪完整率、变更影响识别率、文档与契约漂移率。四项口径都显示"待定",不要自己写定义。
- **要求:**
  - 成本效率以"每个成功合并任务的成本"为主,不以 token 总量为主。"成功合并"的口径显示"待定",指标旁给说明图标。
  - **产出速度与评审等待时间必须放在同一个视图里对照,** 用来发现"产出变快但评审积压"。
  - **【新增】任务一次成功率不能单独出现,** 必须和缺陷逃逸率并排显示,防止"一次通过"掩盖后来才暴露的缺陷。
  - **【新增】每个指标卡片:** 悬停显示指标说明,点击可下钻到构成它的任务和证据(见全局规则 14 的出处面板)。
  - **绝不出现 AI 生成行数。**
  - 没有数据的时间段显示空态。

### 模块 12:流程评测【新增】

- **基准集:** 由历史任务组成。点"新建基准集",从历史任务里勾选。
- **回放:** 修改规则、更换模型、调整工具集之后,点"对基准集回放"。
- **结果页:** 并排两列"调整前 / 调整后",显示依据指标和结论(变好 / 变差 / 无显著差异)。判定标准显示"待定"。
- **未经回放的规则变更:** 在规则变更列表里标"未评测"。是否阻止发布显示"待定"。

### 模块 13:知识沉淀【新增】

- **改进候选列表:** 来源有被驳回的评审意见、失败任务、反复出现的错误模式。每条保留来源链接。【新增】失败分诊(模块 20)里归为"需求不明""架构决策缺失"的任务,也会在这里产生候选。
- **点"采纳":** 选择转化为规则、技能或测试,**需人工批准后才生效。** 生效后生成对应变更,并显示来源关联。
- **点"拒绝":** 填理由,候选关闭。
- **技能库与任务模板:** 可按任务类型检索,点开看内容和使用方式。

### 模块 14:代码库健康【新增】

- **架构规则:** 配置依赖规则、分层规则。违反规则的变更会被标出,并指明违反哪条。
- **重复与死代码:** 列表,每条有位置和类型。没检测到时显示空态。规则尚未配置时,显示"还没有配置架构规则"并给配置入口。
- **重构任务:** 点"创建重构任务"并跟踪状态。可设为定期。
- **健康指标:** 持续展示的趋势图。
- **长任务进度与低打扰通知:**
  - 通知可按事件类型合并、静音。
  - 设计一份"哪些事件通知谁"的清单(升级提问、高危审批、预算告警、门禁失败、【新增】决策请求、范围扩张请求等)。
  - 需要有评审疲劳的提示,例如连续批准数过多时提醒。具体机制待定。

### 模块 15:运维与交付【新增】

- **诊断建议页:** 事故分诊和根因分析,全部标"建议",不自动执行。
- **修复审批:**
  - **生产环境默认只读。** 任何写操作入口都要先走审批。
  - **审批前必须已登记回滚路径。** 未登记时"提交审批"按钮禁用,原因"缺少回滚路径"。
  - 无审批的生产写操作被拒时,显示拒绝记录。
- **【新增】问题回流:** 运行实例发现的异常,可点"创建缺陷"或"创建新需求"。创建后进入规格流程,并自动关联到对应的规格和版本。

### 模块 16:策略与设置【新增】

- **管理员可配置:** 新鲜度阈值、风险分级规则、准入清单、数据策略、预算、并发上限、轨迹保留期限、网络出口默认值。【新增】再加:任务影响范围拆分阈值、自动修复次数上限、必须独立审查的变更类型。
- **每次修改:** 保存前显示变更对比,保存后写入审计。审计只读。
- **需求未定的项:** 都要有输入位置,默认值显示"待定",不要填数字。

### 模块 17:工程资产与关系【新增】

**对象:** 8 类资产:意图与需求、规格与契约、架构决策、模块与组件、代码符号、测试与验证、部署与运行实例、变更与决策记录。

**交互:**
- **资产列表:** 顶部按 8 类分页签。每行显示名称、类型、权威性(权威意图 / 机器可读契约 / 自动生成视图)、责任人、最近验证时间、状态。
- **点开一项:** 详情分左右两栏,左栏"上游关系",右栏"下游关系"。每条关系可点击跳到对方。关系指向的对象已不存在时,显示"断链"标记。
- **点"如果它变更":** 列出可能受影响的代码、测试、契约、文档。每项显示"已更新 / 待更新 / 未验证",旁边有"创建任务"按钮。影响范围为空时显示"没有发现受影响的资产",并加一句"影响分析可能不完整"。
- **漂移面板:** 三个计数卡片,过期规格、无效链接、接口定义不一致。点卡片展开对应列表,每条有位置和原因。
- **权威源冲突:** 同一件事实有两个以上来源时,出现冲突卡片。操作"指定权威源",要填理由。指定后,其他来源显示为"由此生成"或"由契约测试验证"。
- **关系图:** 只作辅助视图。默认入口是列表加两栏关系。节点很多时默认折叠,可展开。

### 模块 18:澄清与决策【新增】

**交互:**
- **任务内的澄清清单:** 分三组:已明确、需查证、未决定。每条有描述和风险类别标签:数据正确性、权限、安全、公共契约、不可逆、其他。
- **按风险给不同操作:**
  - **低风险项:** 显示"采用默认值",旁边写出默认值和理由。点击后自动记录"采用默认值"这件事。
  - **高风险项:** **没有"采用默认值"按钮。** 只能点"转为决策请求",旁边写原因"高风险项必须由人决定"。
  - **需要先探索才能判断的项:** 提供"建为探索任务"。
- **有未决的高风险项时:** 任务状态显示"阻塞待决策"。
- **决策收件箱:** 列表显示待我决策的事项、可选方案、各方案的影响、被它阻塞的任务数。
  - **点开:** 选方案并填理由后提交。提交后生成决策记录,被阻塞的任务解除阻塞。
  - **决策记录:** 只读,记录谁、何时、选了什么、理由。
- **没有待决策事项时:** 显示空态"当前没有待你决策的事项"。

### 模块 19:任务上下文包【新增】

**交互:**
- **入口:** 任务详情的"上下文包"页签。
- **顶部:** 显示基线(分支和提交)、生成时间、总体状态("最新"或"可能已过期")。
- **十个区块:** 任务意图、验收条件、相关规格、当前代码基线、相关模块、设计约束、代码定位、修改边界、验证方式、未知事项。
  - **每条内容带来源:** 文件路径、符号或规格版本,以及全局规则 13 的"已验证 / 推断 / 未知"标签。
  - **"修改边界"分三栏:** 允许修改、禁止、需审批。
  - **"未知事项"区块:** 用醒目样式,不能折叠起来。
- **点"重新确认":** 对照当前代码刷新。变化的条目高亮为"已变化"或"已失效",没变的保持原样。
- **点"固定"或"剔除"某条:** 必须填理由,操作留痕。
- **基线比当前代码旧时:** 顶部出现提示"上下文可能已过期"。

### 模块 20:失败分诊【新增】

**交互:**
- **入口:** 模块 6 里验证失败的项旁,点"去分诊"。
- **选失败原因,共 5 类:** 实现错误、需求不明、测试与规格冲突、外部依赖不可用、架构决策缺失。界面可以显示 AI 的归类,但带"建议"标签,最终由人确认。
- **选"实现错误":** 任务进入自动修复,页面显示"已自动修复 N 次,上限 M(可配置)"。达到上限后停止,任务状态转为"部分完成"或"阻塞",并说明原因。
- **选其他四类:** 显示"转为决策请求",点后进入模块 18 的决策收件箱。
- **分诊记录:** 保留原因、选择人、时间,只读。

### 模块 21:项目接入与成熟度【新增】

**交互:**
- **入口:** 项目卡片上的"接入"。
- **向导共 5 步:** 现状识别、任务契约模板、接入验证工具、资产追踪、影响分析。每步有状态:未开始、进行中、已完成、已跳过。
- **现状识别结果:** 表格列出目录、模块职责、公共接口、依赖、测试与构建入口。每行带"已验证 / 推断 / 未知"标签。项目文档里声称、但没有被核实过的内容标"未核实"。
- **点"跳过"某步:** 必须填理由,并记录。已完成的步骤可以"重新执行"。
- **成熟度:** 项目卡片和向导顶部显示进度,如"已完成 N / 5 步"。向导只给建议顺序,**不强制一次做完。**

## 四、状态与文案

- **门禁:** 通过、失败、跳过、未运行。
- **审批:** 待审批、已批准、已拒绝、已超时未处理。
- **资产新鲜度:** 正常、可能过期。
- **规则评测:** 未评测、已评测。
- **会话:** 运行中、已停止、检测到(非本平台启动)。
- **用例登记:** 已登记、未登记。**不要出现"通过"。**
- **【新增】证据单元格:** 通过、失败、未执行、已过期、不适用。
- **【新增】变更完成状态:** 已完成、带风险完成、部分完成、未完成、阻塞。
- **【新增】事实标签:** 已验证、推断、未知。
- **【新增】规格生命周期:** 持续维护、不可变基线、探索中。
- **【新增】规格权威状态:** 权威意图、待确认。
- **【新增】决策请求:** 待决策、已决策。
- **【新增】范围扩张请求:** 待批准、已批准、已拒绝。
- **【新增】失败原因:** 实现错误、需求不明、测试与规格冲突、外部依赖不可用、架构决策缺失。
