# 01 · 产品需求说明

> 状态：**已锁定 / 原型 v0.2** · 2026-11-12（Asia/Shanghai）  
> 已确认范围以炳宏当日拍板 + 原型 v0.2 为准。本套文档取代宿主仓旧插件 `Plugins/SmartTerminal/docs/`。

## 1. 定位

在 ForgeSelf **宿主内**提供本机 / SSH 的 **命令会话**：用户在输出区的提示符里输入命令并回车执行；写操作与高风险命令先确认再跑；右侧是复用宿主模型的助手对话。会话可审批、可审计。

对外一句话：**「可审批、可审计的命令会话」**。

**不要**宣传为独立桌面终端、完整交互式 PTY，或完整 Windows Terminal。首版不以 vim / htop 一类全屏 TUI、真实 PTY 字节流为验收标准。

## 2. 目标用户与场景

| 角色 | 诉求 |
|------|------|
| 开发 / 运维 | 少切出宿主，在插件里打开本机或 SSH 会话，多标签切换，按命令看输出 |
| 使用 AI 的人 | 右侧像真正的助手一样提问；建议默认只插入到提示符，要跑必须经过确认 |
| 产品 / 安全 | 能说明「谁在何时跑了什么」；密码和密钥不进界面原文、审计、URL 和浏览器存储 |

## 3. 范围（首版 · 已锁定）

1. **宿主插件，不是独立终端。** 路由 `/smart-terminal`，外观走本项目主题。
2. **本机壳 + SSH。** Linux / macOS：`bash` / `zsh` / `sh`（探测到的 `fish` / `dash` 可列出）。Windows：`cmd` / `powershell` / `pwsh`。跨平台列表仍列出对方平台壳，并标记 `available=false`，选择器里禁用。默认本机壳：Unix 按 `$SHELL` → bash → zsh → sh；Windows 按 pwsh → powershell → cmd。
3. **可搜索的配置列表。** 本机壳配置与已保存的 SSH（主机、端口、用户、认证方式）。不保存明文密码。
4. **基础多标签。** 新建 / 切换 / 关闭；每标签独立的壳、cwd、输出块、命令历史、审批与助手线程。只做标签，**不做左右分屏**，界面不出现分屏入口。
5. **真正的终端提示符。** 提示符（`user@host:path$`）位于输出表面当前行。输入后回车即执行。输出按「命令 + 输出」分块。上 / 下键翻历史。Tab 按原型提供历史 / 片段建议补全（nice-to-have，已在原型中，作体验项而不是完整壳补全验收）。**不得**再做独立命令输入框，**不得**把「运行」当作主输入路径。
6. **权限闸。** Auto / **AskWrite（默认）** / AskHighRisk。日常只读命令回车直接执行；写操作 / 高风险命令回车后弹出确认，批准后执行，取消不执行。硬拒绝名单始终拦截。
7. **右侧助手对话。** 默认打开「对话」页：消息流 + 底部提示词 +「发送」。Enter 发送，Shift+Enter 换行。复用宿主已有 AI 网关与已配置模型，**不另开账号**。可用当前会话 / 点选的命令块作上下文。「插入到终端」只写入提示符、不自动执行；「批准后执行」走与提示符回车相同的权限闸。片段、历史为侧栏次级页签。
8. **片段。** 可插入到提示符，或直接运行；后者若属于写 / 高风险，必须走权限闸。
9. **SSH 认证。** 配置与密钥进宿主凭据库。插件不存明文密码，不做「记住密码」，密码不进 URL。无密钥时：**先出交互密码框，确认后再创建标签并连接**；取消不建标签。断开后可重连；无密钥则再次要密码。
10. **刷新恢复。** 尽量恢复标签列表、连接摘要、上限内回滚输出（及助手侧栏打开状态）。**永不**恢复或落盘密码、私钥、口令。后端进程若已断，UI 恢复为「已断开」，由用户重连。
11. **展示与审计脱敏。** 界面、接口、审计、日志、助手回包中，密钥形态的值替换为 `****`。
12. **状态完备。** 加载 / 空 / 错误 / 401 / 断线 / 正常，均须可识别、可恢复（见 02）。

## 4. 非目标（本里程碑明确不做）

- 完整交互式 PTY、彩色全屏 TUI（vim / htop 等）作为验收标准
- 左右分屏、拖拽排序、标签撕出独立窗口、完整 Windows Terminal profiles JSON
- **SFTP / 远程文件树**：连入口都不露，03 不提供对应接口
- RDP / VNC / X11 / 串口 / 内嵌 FTP
- 云端保险库、团队同屏、跨设备密文同步
- 插件内自建 SSH 密钥生成与托管 UI（密钥由宿主凭据库处理）
- 密码进入 URL，或任何「记住本会话密码」勾选
- 插件自建一套 AI 账号或模型供应商配置（必须复用宿主）
- 把本插件做成独立 Electron / 桌面终端壳

## 5. 用户故事（首版必须成立）

1. 作为开发，我从左侧打开「本机开发」或点「新建会话」，在提示符里输入 `git status` 并回车，输出以命令块出现；上键可翻出这条历史。
2. 作为运维，我打开需交互密码的 SSH 配置：先看到密码框，确认后才出现标签并连接；我取消则页面上不会多出一个空标签。断开后点「重新连接」，若无密钥会再次要密码。
3. 作为使用者，我输入 `sudo nginx -s reload` 并回车，先看到 AskWrite 确认；取消后命令不会执行，提示符里仍可继续输入。
4. 作为使用者，我在右侧对助手提问，Enter 发出去；助手给出建议命令后，我选「插入到终端」，命令只出现在提示符里，不会自己跑。我再选「批准后执行」，写操作仍要确认。
5. 我刷新浏览器后，标签、连接摘要和近期输出还在，DevTools 存储和审计里看不到密码。
6. 作为安全接口人，我在审计里只能看到脱敏后的命令，看不到密码、私钥或 `token=` 原文。

| P2 | 流式输出体验打磨、助手流式回复、更完整的外壳探测（WT profiles / Git Bash）、进程中断 |

## 7. 继承或仍开放、但不挡 03 的事项

下列**不要**写成「本轮已重新投票通过」，实现时可按括号中的默认推进，待实现再与 03 对齐：

1. **旧版 URL 深链**（`profile + step/run + env`）：建议沿用为「打开标签 + 可选步骤」的启动器；**禁止**把密码放入 URL（旧版「内网过渡 + ack」作废）。`custom:<id>` 仍只留协议位。不挡首版主路径验收。
2. **`st_*` Agent 工具**（`st_list_shells` / `st_create_session` / `st_run_command` / `st_get_output` / `st_list_sessions` / `st_set_permission_mode` / `st_query_audit` / `st_resolve_approval`）：建议沿用名单，入参与行为与 03 对齐；不新设计一大块工具面。Agent 同样受权限闸约束，且不得接收或回传密码明文。
3. **跨平台外壳列表标记不可用**：作为继承约定，写入 03 的 `/shells` 契约。
4. **`wsl-ssh`**：旧版 profile 之一，本轮未再确认；首版可暂不提供入口，协议位保留，不实现也不挡主路径。
5. **标签重命名**：旧版有、原型 v0.2 未演示。P1，不挡 03（接口可预留 PATCH 标题）。
6. **Ctrl+C 中断正在运行的命令**：原型未做，且不以 PTY 为验收标准。同一会话同时只跑一条命令，运行中提示符禁用即可。不挡 03。

## 8. 成功标准

- 主路径像真正的终端：焦点在提示符，回车执行，没有独立「运行」框
- 写 / 高风险命令必须能被取消且确实未执行；只读命令不必多点一次确认
- 无密钥 SSH：先密码框后标签；取消零标签；重连再次要密码；刷新不出现密码
- 助手是对话，而不是只能点卡片；插入不自动执行；批准后执行走同一道闸
- 界面、接口、审计均无密码 / 私钥明文；密钥形态展示为 `****`
- 无分屏入口，无 SFTP 入口
- 测试按 [06](./06-UI交互评审稿.md) 对照原型 v0.2 截图验收
