# 03 · 架构、数据模型与 HTTP 接口

> 状态：**已锁定 / 原型 v0.2** · 2026-11-12（Asia/Shanghai）  
> 本节是前后端实现契约。路径、字段、错误码以本节为准。  
> 契约必须服务「提示符回车」的命令会话，而不是旧版「独立命令框 + 运行按钮」。本里程碑**不提供任何 SFTP 接口**。

## 1. 运行时边界

```
UI / 建议沿用的 st_* 工具
  → SmartTerminalController
  → 权限分类闸（Auto / AskWrite / AskHighRisk + 硬拒绝）
  → 会话进程（本机壳或 SSH，长寿命，按行投喂命令）
  → 命令块 + 流式/轮询输出
  → 助手：ILlmRuntime / IChatCompletion / IChatModelResolver（宿主网关）
  → 凭据：宿主凭据库 + ISecretEncryptionService（只存句柄，不存明文密码）
  → StAudit（脱敏、只追加）
```

- 这是**命令会话**，不是以完整 PTY 为验收标准的字节终端。每个会话持有一个长寿命壳进程（本机或 SSH），按行提交命令，收集输出与退出码，组装成命令块。提示符上的 cwd 尽量跟随（执行后读 `pwd` / `$PWD` /等价命令）。不保证 vim / htop 等全屏 TUI 可用，也不把真实 PTY、窗口尺寸协商、交互式 stdin 作为验收项。
- 同一会话同一时刻只执行一条用户命令；执行中拒绝新的提交（`conflict` / `command_busy`）。
- 取宿主服务一律执行期 `CreateHostScope()` / `ctx.Get<T>()`，构造函数不注入宿主契约（铁律 26）。
- 模块不可用（AI 网关、凭据加密等解析失败）返回 `host_module_unavailable`，不要让整个插件加载失败，也不要让已打开的终端会话一起挂掉。
- 插件自有库 ConnName **`SmartTerminal`**。库文件建议落在数据根 `Plugins/smart-terminal/SmartTerminal.db`。若插件仍在宿主仓内实现，沿用既有 PluginDbs 登记，不必为文档另开仓库。
- 工具前缀：`plugin.json` 声明 `toolPrefix: "st"`，与宿主 `ToolNamespace.PrefixByPluginId["smart-terminal"]` 一致。
- 原型路径 `/api/plugins/smart-terminal/*` 只是示意，**实现不得使用该前缀**。

## 2. HTTP 总则

- 前缀：`/api/smart-terminal`。控制器：`[Route("api/smart-terminal")]` + 类级 `[Authorize("ApiKeyPolicy")]`。
- JSON 一律 camelCase。时间：ISO 8601 带偏移（建议 `+08:00`）或至少可解析的 ISO 8601，前后端同一套。
- 对外 id 均为**字符串**，由后端分配：配置 `p-…`，会话 `s-…`，命令块 `b-…`，审批 `ap-…`，片段 `snip-…`，凭据句柄 `sec-…`，消息 `m-…`。不要让前端自己造业务 id（新建配置 / 会话的请求里不要带自造 id）。
- 列表：会话、配置、外壳、片段、待审批默认返回**数组**（体量小）。审计、命令历史（跨会话查询）返回分页对象 `{items, total, page, pageSize}`。`page` 从 1 起，默认 `page=1, pageSize=50`，`pageSize` 上限 200。
- 业务拒绝用 HTTP 400 + `{code, message}`；未登录 401；无权限 403；不存在 404；状态冲突 409；依赖缺失 424 `host_module_unavailable`。需要用户确认但尚未执行的提交返回 **202**。创建 / 重连已受理但仍在握手时也可 202。
- 统一错误体：`{code, message}`。`code` 取值见 §9。成功响应未特别说明为 200；不要在成功体里回显密码、私钥或口令，相关字段只给 `passwordProvided: true|false` 或直接省略。
- 旧版 `ApiResponse<T>` 包装若宿主仍统一使用，可保留外层，但 `data` 内字段必须与本节一致；错误仍能读到 `code`。推荐与 SuperLab 一样直接返回资源 + `{code, message}`。

## 3. 会话与命令模型（与 UX 对齐）

1. **主提交入口**是 `POST /sessions/{id}/commands`，对应提示符里按 Enter。片段「运行」、助手「批准后执行」也走**同一接口**。不要再把 `POST .../run` 设计成主输入模型，不要为「运行按钮」单开一套语义。
2. 请求体只有一行命令字符串（及可选的来源 / 审批令牌），不是「打开独立输入框」。
3. 服务端先分类，再按会话当前权限模式决定 `allow` / `ask` / `deny`。
   - `allow`：开始执行，202 + 命令块（`status=running`），随后靠轮询或 SSE 追输出。
   - `ask`：不执行，202 + `{status:"awaiting_approval", approval}`，等 `POST /approvals/{id}/resolve`。
   - `deny`：不执行，400 `rejected_hard`，可同时写一条系统块说明原因。
4. 输出以**命令块**为单元：`command` + 增量 `output` + `exitCode` + 时间。前端按块渲染，输入永远在最后一行提示符。
5. 流式不是验收障碍：必须提供 `GET /sessions/{id}/blocks?afterSeq=`（或等价拉块）。可选再提供 `GET /sessions/{id}/events`（SSE）推送 `block_delta` / `block_done` / `session_status`。没有 SSE 时，前端对 running 块按 200–500ms 轮询即可。
6. 交互密码只允许出现在 `POST /sessions` 与 `POST /sessions/{id}/reconnect` 的请求体 `password`，一次性内存使用，用完即焚，**响应、列表、审计、块输出、事件流都不得带回**。若 SSH 需要密码但请求未带：返回 409 `password_required`（`needsInteractivePassword: true`），**不得创建会话、不得把状态改成已连接**。这与「先框后标签」一致——UI 应先收集密码再调用；误调用也不能留下孤儿会话。
7. 断开：`status=disconnected`，块保留，进程结束或不可附着。重连是新的握手，不复用已焚毁的密码。

## 4. 数据模型（ConnName `SmartTerminal`）

`EnsureCreated()` 在插件启动路径调用。唯一性直查 DB。密钥材料不得出现在下列明文列。

### 4.1 `StProfile`（已保存配置）

| 字段 | 类型 | 说明 |
|------|------|------|
| Id / PublicId | Int64 / string 唯一 | 对外如 `p-ssh-api` |
| Kind | string | `local` \| `ssh`（本里程碑不写 `sftp`，不实现 `wsl-ssh`） |
| Name | string | 展示名，必填 |
| ShellId | string? | 本机外壳 id；SSH 可空，默认远端登录壳 |
| Cwd | string? | 起始目录 |
| Host / Port / User | | 仅 SSH；Port 默认 22 |
| Auth | string? | SSH：`key` \| `interactive`。本机空 |
| SecretId | string? | `auth=key` 时指向宿主凭据句柄，见 §7 |
| IdentityFile | string? | 可选，本机私钥路径；只存路径，不把文件内容拷进本表 |
| Source | string | `ui` \| `agent` \| `system` |
| CreateTime / UpdateTime | DateTime | |

禁止列：`Password` / `PasswordEnc` 用于「记住登录密码」。交互密码一律不落这张表。`IdentityFile` 若填写，连接时读文件，失败给 `credential_unavailable`，不要把私钥内容缓存进库。

### 4.2 运行中会话（内存为主，可附带无密钥快照）

会话进程、未焚密码、正在跑的命令属于**进程内状态**，重启宿主后不保证存活。可把无密钥的摘要 + 近期块写入内存快照或短TTL 存储，供同一宿主进程内的页面刷新附着；**快照不得含密码 / 私钥 / 口令**。

对外会话对象（`Session`）：

| 字段 | 说明 |
|------|------|
| id, title, profileId?, kind, shellId, cwd | 身份与提示符素材 |
| status | `connecting` \| `connected` \| `disconnected` \| `closed` |
| host, port, user, auth | SSH 摘要；不要有 password |
| permissionMode | `Auto` \| `AskWrite` \| `AskHighRisk`，默认 `AskWrite` |
| processAlive | 壳进程是否仍可附着 |
| passwordProvided | 本次握手是否用过交互密码（布尔，无原文） |
| prompt | 当前 PS1 字符串，如 `deploy@10.2.8.21:/var/www/api$` |
| createdAt, updatedAt | |
| source | `ui` \| `agent` |

### 4.3 命令块（随会话，内存 + 刷新缓冲）

| 字段 | 说明 |
|------|------|
| id / seq | 对外 id；`seq` 单调递增，供 `afterSeq` 拉取 |
| kind | `command` \| `system`（`connected` / `reconnect` / 硬拒绝说明等） |
| command | 展示用，已脱敏 |
| output | 已脱敏的标准输出/错误合并文本（或分 `stdout`/`stderr`，前端按原型合并展示亦可） |
| exitCode | 系统块可空；失败非 0 |
| status | `running` \| `done` \| `failed` \| `cancelled` \| `awaiting_approval` \| `rejected` |
| startedAt / endedAt | |
| source | `prompt` \| `snippet` \| `assistant` \| `agent` \| `system` |

命令历史对外给脱敏后的整行，供上/下键与侧栏「历史」使用，不得含密钥原文。

### 4.4 `StSnippet`

`Id / PublicId, Name, Command, CreateTime, UpdateTime`。命令按用户原文保存，但接口读出时若含密钥形态仍须脱敏展示；执行时以用户保存的命令走权限闸（分类看真实意图，展示走脱敏）。

### 4.5 `StSecretRef`（凭据句柄，材料由宿主加密保管）

| 字段 | 说明 |
|------|------|
| PublicId | `sec-…` |
| Kind | `ssh-private-key` \| `ssh-certificate` |
| Fingerprint / Label | 可展示的指纹或名称，无材料 |
| Cipher | 经宿主 `ISecretEncryptionService` 加密后的密文；或宿主凭据库返回的外部句柄。接口**永不**输出 Cipher / 材料 |
| CreateTime | |

只用于密钥类材料。**禁止**用这张表实现「记住 SSH 登录密码」。

### 4.6 `StAudit`

只追加。字段：`Id, Kind, SessionId, ProfileId, Source, Actor, CommandRedacted, DetailJson, CreateTime`。

`Kind` 至少包括：`session_create` / `session_close` / `session_disconnect` / `session_reconnect` / `profile_create` / `profile_update` / `profile_delete` / `classify` / `approval_ask` / `approval_approve` / `approval_reject` / `command_start` / `command_result` / `permission_mode` / `secret_add` / `secret_delete` / `rejected` / `chat_message`。

`DetailJson` 与 `CommandRedacted` 必须脱敏（见 04）。不得写入密码、私钥、SSHPASS、Bearer 原文。

### 4.7 助手消息（按会话，内存或短持久，须脱敏）

`id, sessionId, role(user|assistant|system), content, suggestedCommand?, createdAt`。持久化前脱敏。不在本插件保存模型供应商 API Key。

### 4.8 待审批（内存，进程重启后失效）

`id, sessionId, commandRedacted, risk(write|highRisk), mode, status(pending|approved|rejected|expired), source, createdAt, expiresAt`。原文命令仅内存持有，供批准后执行；落审计只留脱敏版。建议 30 分钟或宿主重启后过期。

## 5. HTTP API

基址 `/api/smart-terminal`。

### 5.1 元信息、外壳、权限模式

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/meta` | `{pluginId, version, permissionDefault:"AskWrite", features:{split:false, sftp:false, ptyAcceptance:false}}` |
| GET | `/shells` | 外壳数组。每项 `{id, displayName, executable, kind, available, note?}`。Unix 与 Windows 壳都列出，当前平台不可用的 `available=false`。不可用壳不得被创建会话成功使用（400 `shell_unavailable`） |
| GET | `/permission-mode` | `{mode, sessionDefault:"AskWrite"}`，`mode` 为全局默认 |
| PUT | `/permission-mode` | `{mode}`，`mode ∈ Auto\|AskWrite\|AskHighRisk`。只改全局默认，不改已经打开的会话 |
| PUT | `/sessions/{id}/permission-mode` | 会话级覆盖。Agent 若沿用 `st_set_permission_mode`，应对齐本接口，且不得把全局默认偷偷改掉，除非显式针对全局 |

### 5.2 配置

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/profiles` | 已保存配置数组。可 `?kind=local\|ssh&q=`。每项含摘要，**无密码字段**；`auth=key` 时给 `secretId` 或 `identityFile` 路径，不给材料 |
| POST | `/profiles` | 新建。本机：`{kind:"local", name, shellId, cwd?}`。SSH：`{kind:"ssh", name, host, user, port?, auth, secretId?, identityFile?, cwd?}`。不得接受 `password` 并写入配置（400 `password_not_persistable`） |
| GET | `/profiles/{id}` | 单条，同样无密码 |
| PUT | `/profiles/{id}` | 更新元数据；不能用空 `secretId` 以外的方式上传明文密钥到本接口 |
| DELETE | `/profiles/{id}` | 只删配置；不删宿主凭据句柄，除非请求显式 `deleteSecret=true` 且该句柄未被其它配置引用 |

临时「新建会话」不必自动写入 `/profiles`。另存为配置是 P1，可复用 POST `/profiles`。

### 5.3 凭据句柄（见 §7）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/secrets` | 元数据数组：`{id, kind, fingerprint, label, createdAt}`，无材料 |
| POST | `/secrets` | `{kind, label?, material, passphrase?}` → 201 `{id, kind, fingerprint, label, createdAt}`。`material` 只出现在请求，立即加密后丢弃明文 |
| DELETE | `/secrets/{id}` | 删除句柄与密文 |

### 5.4 会话

**POST `/sessions`**

```json
{
  "profileId": "p-ssh-db",
  "kind": "ssh",
  "title": "staging-db",
  "shellId": "bash",
  "cwd": "~",
  "host": "db.staging.internal",
  "port": 22,
  "user": "ops",
  "auth": "interactive",
  "secretId": null,
  "identityFile": null,
  "password": null,
  "permissionMode": "AskWrite"
}
```

规则：

- 给了 `profileId` 则以配置为准，请求里的 host/user 等不得用来改写已存配置（只作本次会话覆盖 cwd / title）。
- `kind=local`：不需要密码。`shellId` 不可用 → 400 `shell_unavailable`。成功 201，`status=connected`（若壳启动较慢可为 202 + `connecting`，随后变为 connected）。第一条系统块 `kind=system`，命令名 `connected`。
- `kind=ssh` 且 `auth=key`：用 `secretId` 或配置 / 请求中的 `identityFile` 握手。缺密钥材料 → 400 `credential_required`。失败 → 400/424 `connect_failed` / `credential_unavailable`，**不留下 connected 会话**（允许不创建，或创建后立即失败并 close，推荐不创建）。
- `kind=ssh` 且 `auth=interactive`（缺省无 key 时同此）：请求体必须带非空 `password`，否则 **409 `password_required`**，`needsInteractivePassword: true`，**不创建会话**。成功后密码从内存清除。
- 响应为 `Session`，可附 `blocks`（至少含 connected 系统块）。**永不回显 password**。

**其它会话接口**

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/sessions` | 未 close 的会话数组（含 status、摘要、无密码） |
| GET | `/sessions/{id}` | 详情 + 当前 `prompt` + `processAlive` |
| POST | `/sessions/{id}/disconnect` | 断开进程，保留会话与块，`status=disconnected` |
| POST | `/sessions/{id}/reconnect` | 体可选 `{password?}`。无密钥且未带密码 → 409 `password_required`，会话保持 disconnected。成功后追加 `reconnect` 系统块（文案不得含口令） |
| POST | `/sessions/{id}/close` | 结束进程，焚毁该会话内存密码，移出活动列表。幂等 |
| PATCH | `/sessions/{id}` | 可选 `{title}`（重命名，P1 预留，不挡主路径） |

关闭标签 = `POST .../close`。不要用 GET 传递密码。

### 5.5 命令（提示符回车的契约）

**POST `/sessions/{id}/commands`**

```json
{ "command": "sudo nginx -s reload", "source": "prompt" }
```

- `source`：`prompt` \| `snippet` \| `assistant`（客户端声明仅作审计辅助；**不能**用它绕过闸门）。Agent 入口由服务端记 `source=agent`。
- 会话必须 `connected`，否则 409 `session_disconnected`。
- 已有命令 `running` 时再提交：409 `command_busy`。
- 空命令：400 `invalid_request`。
- 返回 202，按分类：

```json
{
  "status": "running",
  "decision": "allow",
  "risk": "read",
  "block": { "id": "b-1", "seq": 4, "kind": "command", "command": "df -h", "output": "", "status": "running" }
}
```

或：

```json
{
  "status": "awaiting_approval",
  "decision": "ask",
  "risk": "write",
  "approval": { "id": "ap-1", "command": "sudo nginx -s reload", "risk": "write", "mode": "AskWrite", "status": "pending" },
  "block": { "id": "b-2", "seq": 5, "status": "awaiting_approval", "command": "sudo nginx -s reload" }
}
```

或硬拒绝：400 `{ "code": "rejected_hard", "message": "…", "risk": "deny" }`。

`command` 字段在所有响应中已脱敏。

**GET `/sessions/{id}/blocks?afterSeq=0`**

返回 `{prompt, status, items: Block[]}`。`afterSeq` 之后的块（含 running 块的最新 output）。这是刷新和轮询的主路径。

**GET `/sessions/{id}/commands`**

本会话脱敏历史（数组或分页），供上/下键与侧栏。不要返回未脱敏原文。

**GET `/sessions/{id}/events?afterSeq=`（可选 SSE）**

`text/event-stream`，事件：`block_delta`、`block_done`、`session_status`、`approval`。不是 P0 必做，有轮询即可验收。

本里程碑不把「向进程写入任意 stdin / 窗口变更 / 原始 PTY 帧」做成公开接口。

### 5.6 审批

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/approvals?sessionId=&status=pending` | 待审批数组，命令已脱敏 |
| POST | `/approvals/{id}/resolve` | `{decision:"approve"\|"reject"}` |

- `approve`：按内存中的原文执行，202 + running 块。审批不存在 / 过期 / 已处理：404 或 409。
- `reject`：不执行，块记 `rejected` 或移除待执行状态，200 `{status:"rejected"}`。
- 不得提供「批准时改写命令」字段（避免调包）。要改命令，用户应取消后在提示符编辑再回车。

### 5.7 分类（只预览，不执行）

**POST `/classify`**：`{command}` → `{risk, decision, reason, mode}`。供调试或未来 UI，不是主路径必点步骤。

### 5.8 片段

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/snippets` | 数组 `{id, name, command}`（展示脱敏） |
| POST | `/snippets` | `{name, command}` |
| PUT / DELETE | `/snippets/{id}` | 更新 / 删除 |

运行片段 = 对当前会话 `POST /sessions/{id}/commands`，`source=snippet`，不是单独的 `/snippets/{id}/run` 旁路。

### 5.9 助手对话（复用宿主网关）

助手是会话级线程，不是独立账号体系。模型使用宿主已配置的默认 / 当前模型，本里程碑不要求插件内模型选择器。

**GET `/sessions/{id}/chat`** → `{messages, model?}`。

**POST `/sessions/{id}/chat/messages`**

```json
{
  "content": "解释上一条失败",
  "blockId": "b-1"
}
```

- `blockId` 可选；缺省用用户点选或最近一条非系统命令块。服务端把该块的脱敏命令与输出作为只读上下文发给宿主模型。
- 成功：200 返回助手消息（可含 `suggestedCommand`），或 202 + `messageId`，再用 GET 拉取。允许先做非流式完整回复；流式为 P2。
- 思考中由前端根据 202 / 进行中状态展示「正在调用宿主模型…」。
- 宿主网关或模型不可用：424 `host_module_unavailable`，会话本身不受影响。
- **插入到终端是纯前端行为**（写提示符草稿），不要提供「插入并自动执行」的接口。
- **批准后执行**仍走 `POST /sessions/{id}/commands`，`source=assistant`，必须过权限闸。不得提供助手「直接执行」接口。
- 请求与回包脱敏；不得把宿主 API Key 带回客户端。

无 `sessionId` 时不要接受跨会话的「全局聊天执行命令」。可先要求打开会话（与原型一致）。

### 5.10 审计

**GET `/audit`**：查询参数 `sessionId, kind, q, page, pageSize`，分页 `{items, total, page, pageSize}`。每项只有脱敏字段。

## 6. 本里程碑不做的接口

- 任何 `/sftp`、文件树、远程上传下载
- 分屏、向多标签广播同一命令
- 以 PTY 原始帧 / 窗口尺寸 / 交互式 stdin 为验收的接口
- 把密码写入 query string 的 launch GET
- 「记住密码」或把登录口令存进 `/secrets`
- 插件自建的模型供应商 / 登录账号 API

旧版 `POST /launch` 与 URL 深链：**建议沿用，待实现时与本节对齐**。若实现，必须遵守：密码不得进入 URL 或 query；无密钥 SSH 仍返回 `password_required` 且先框后标签；步骤命令仍走权限闸。不挡首版主路径，也不在本节展开完整 LaunchSpec。

## 7. 凭据与宿主存储

产品口径：SSH 配置与密钥进**宿主凭据库**，插件不存明文密码。

实现约定：

1. 登录口令（interactive）：只出现在创建 / 重连的请求内存，用完即焚。不写 DB、不写 `/secrets`、不写 `st:ui`、不写日志。
2. 私钥 / 证书：经 `POST /secrets` 交给插件后，立即用宿主 `ISecretEncryptionService` 加密保存（或写入宿主若已提供的凭据设施），对外只暴露 `secretId` + 指纹。配置表只引用 `secretId`。
3. 若实现时宿主已有更合适的凭据 API，应改走该 API，本插件只保存外部句柄；不得退化为插件目录里的明文 `id_rsa` 或密码文件。
4. `identityFile` 路径是可选项：只存路径，连接时由宿主进程读本地文件，失败则 `credential_unavailable`。不得把路径里的文件内容再抄一份明文到插件库。
5. 所有 GET 列表与详情：没有 `password`、没有 `material`、没有私钥正文。已配置密钥时用 `auth:"key"` + `secretId` 或 `identityFile` 表达。
6. 审计：`secret_add` / `secret_delete` 只记 id 与指纹，不记材料。

## 8. Agent 工具（建议沿用，待实现时与本节对齐）

不在本轮新设计工具面。实现阶段将现有 `st_*` 对齐到本节即可：

| 工具 | 对齐 |
|------|------|
| `st_list_shells` | GET `/shells` |
| `st_list_sessions` | GET `/sessions` |
| `st_create_session` | POST `/sessions`。**不得**接收或在回包中返回密码明文；需交互密码时返回 `password_required`，由人在 UI 完成 |
| `st_run_command` | POST `/sessions/{id}/commands`，过同一道闸；需审批则返回 `awaiting_approval`，不得自批 |
| `st_get_output` | GET `/sessions/{id}/blocks?afterSeq=` |
| `st_set_permission_mode` | 会话级 PUT；改全局须显式且谨慎 |
| `st_query_audit` | GET `/audit` |
| `st_resolve_approval` | 仅在用户已明确授权的前提下；默认应由 UI 点确认。工具回包脱敏 |

工具回包形态与兄弟插件一致：成功 `{success:true, tool, status, data, hint}`，失败 `{success:false, tool, status, code, message, hint}`。`source` 由服务端标记为 `agent`，客户端不能伪造为 `ui`。

## 9. 错误码

| code | HTTP | 何时 |
|------|------|------|
| `unauthorized` | 401 | 无 / 无效 ApiKey |
| `forbidden` | 403 | Agent 试图自批高风险、读取密钥材料等 |
| `not_found` | 404 | 会话 / 配置 / 审批 / 片段 / 凭据不存在 |
| `invalid_request` | 400 | 缺字段、非法 mode / kind / decision、空命令 |
| `password_required` | 409 | SSH 交互认证缺少密码；不创建或不断开重连成功 |
| `password_not_persistable` | 400 | 试图把登录密码写入配置或 secrets |
| `credential_required` | 400 | `auth=key` 但既无 secretId 也无可用 identityFile |
| `credential_unavailable` | 424 或 400 | 句柄解密失败或私钥文件不可读 |
| `shell_unavailable` | 400 | 选择了 `available=false` 的外壳 |
| `connect_failed` | 400 | SSH / 本机壳启动失败（message 可读、无口令） |
| `session_disconnected` | 409 | 向未连接会话提交命令 |
| `command_busy` | 409 | 会话内已有命令在运行 |
| `rejected_hard` | 400 | 分类硬拒绝 |
| `conflict` | 409 | 其它非法状态转换（重复 resolve、关闭后再跑） |
| `host_module_unavailable` | 424 | 解析不到加密服务、AI 网关、模型等 |
| `internal_error` | 500 | 未处理异常；不得回堆栈或密钥 |

## 11. 刷新附着

- 前端按 02 使用 `sessionStorage['st:ui']` 恢复标签、摘要与上限内输出块。
- 若刷新后宿主进程里同一 `sessionId` 仍 `processAlive`，GET `/sessions` / `/blocks` 优先与之附着，不必重连。
- 若进程已死：接口返回 `disconnected` 或 404（已 close）。前端仍展示本地恢复的块，横幅引导重连，**不得**把缓存的密码（本来也不该有）带回去。
