# 04 · 权限、安全与审计

> 状态：**已锁定 / 原型 v0.2** · 2026-11-12（Asia/Shanghai）

本插件按宿主单操作者模型设计（与 DbAdmin / SuperLab 相同）：浏览器请求经类级 `ApiKeyPolicy` 认证即视为本机操作者。本里程碑不做多人角色、不做租户隔离。下面的「谁可以」区分的是 **人在 UI 里操作** 还是 **Agent 经建议沿用的 `st_*` 调用**。

## 1. 三级权限（命令分类闸）

与宿主工具级 PermissionProfile 互补：本插件管**会话内即将执行的命令**；全局工具策略仍走宿主配置。规则文件可放在插件数据目录 `permission-rules.json`（首次从默认文件复制，可热改后重载），但产品行为以下表为准，不得把默认改成 Auto。

| 模式 | 只读 / 日常 | 写 / 副作用 | 高风险 | 硬拒绝名单 |
|------|-------------|-------------|--------|------------|
| **Auto** | 执行 | 执行 | 执行 | 仍拦截 |
| **AskWrite**（**默认**） | 执行 | 先确认 | 先确认 | 仍拦截 |
| **AskHighRisk** | 执行 | 执行 | 先确认 | 仍拦截 |

分类口径（实现可沿用旧分类器并校准，展示与审计用 `read` / `write` / `highRisk` / `deny`）：

- **只读 / 日常**：如 `ls`、`git status`、`df`、`cat`、`journalctl` 只读查看等，AskWrite 下回车即跑。
- **写 / 副作用**：如带 `sudo` 的变更、`chmod` / `chown`、`systemctl`、`nginx -s reload`、包管理安装、`docker rm/stop`、`kubectl delete` 等。
- **高风险**：如 `rm -rf`、`mkfs`、`dd if=`、`reboot` / `shutdown`、`kill -9`、`drop database` 等。
- **硬拒绝**：对标既有 denylist 与破坏性模式（如 `format`、`diskpart`、明显擦盘），任何模式下都不执行。

未知命令在 AskWrite 下按 **写** 处理（偏安全，先问再跑），不要静默当只读放行。

会话可以有自己的模式（覆盖全局默认）。改模式写审计 `permission_mode`。全局默认保持 AskWrite，除非操作者显式修改全局。

## 2. 操作矩阵

| 操作 | UI（已认证操作者） | Agent（建议沿用的 `st_*`） |
|------|--------------------|----------------------------|
| 列出外壳、配置、会话、块、片段、审计 | 允许 | 允许（只读工具） |
| 创建本机会话、密钥 SSH 会话 | 允许 | 允许；`source=agent` |
| 提交交互密码以创建 / 重连 SSH | 允许（密码仅本次请求内存） | **禁止**把密码作为工具参数；应返回 `password_required`，由人在 UI 完成 |
| 在提示符提交只读命令 | 允许，直接执行 | 允许，同样分类 |
| 提交写 / 高风险命令 | 弹出确认，取消则不执行 | 进入待审批，**不得自批**；回包 `awaiting_approval` |
| 批准 / 拒绝待审批命令 | 允许 | 仅当用户明确授权；默认应由 UI 完成。不得把高风险改成自动批准 |
| 修改全局或会话权限模式 | 允许（次级入口） | 允许会话级；改全局须显式。不得把 `source` 伪造成 `ui` |
| 插入助手建议到提示符 | 允许（前端，不执行） | 不需要单独工具 |
| 助手「批准后执行」 | 走同一道闸 | 若有对应调用，同样不得自批 |
| 保存 / 删除配置与片段 | 允许 | 本里程碑可不提供写工具 |
| 导入私钥到宿主凭据句柄 | 允许 | **禁止**经工具上传私钥材料 |
| 读取密钥明文、审计原文密码 | 接口不提供 | 禁止 |
| SFTP / 分屏相关操作 | **无入口、无接口** | 禁止 |

`source` 只能由服务端根据调用入口写入，客户端或工具参数不能指定、不能把 `agent` 改成 `ui`。

## 3. 审批规则

- 需要确认时：**先问后跑**。取消 / 拒绝 = 不执行，不得先跑再撤回。
- 批准后执行的是审批创建时内存中的那一行命令，不允许在 resolve 请求里调包。
- 待审批在宿主重启或超时（建议 30 分钟）后失效，必须重新在提示符提交。
- 浮层顺序：交互密码先于审批。已连接会话上的写命令只出审批，不再要密码。
- 硬拒绝不进入审批队列，直接失败并审计 `rejected`。

## 4. 凭据

- 插件**不存** SSH 登录密码，不做「记住密码」，密码**不进 URL**。
- 密钥材料只进宿主凭据库 / `ISecretEncryptionService` 句柄，见 03 §7。
- 关标签、关闭密码框、会话 close：内存中的口令即焚。
- 刷新恢复不得携带任何秘密。缺密的 SSH 重连必须再次交互输入。

## 5. 审计与脱敏

- 创建 / 关闭 / 断开 / 重连会话、配置变更、分类与审批、命令执行结果、权限模式变更、凭据句柄增删、助手发消息（可选摘要），均追加 `StAudit`，不可改写旧行。
- 一律只存脱敏字段：`commandRedacted`、已擦除的 `detail`。`password=`、`SSHPASS`、`Bearer`、`token=`、私钥块、连接串等替换为 `****`。
- 助手回包、工具回包、日志、CT fixture、`st:ui`：**无密码 / 私钥 / 宿主 ApiKey 原文**。
- 界面展示同样脱敏（对标命令块与失败输出里的密钥形态）。
- 查询入口：`GET /api/smart-terminal/audit`。UI 可用命令面板或次级入口打开，不占用 PageHead 主按钮。

## 6. 前端鉴权表现

未带令牌或令牌失效：接口 401，页面进入 `st-state-401`，提供「重新登录」（`st-relogin`）走宿主登录，不假装有会话数据，也不在插件里自建账号体系。助手同样走宿主已登录上下文，不另开模型账号。
