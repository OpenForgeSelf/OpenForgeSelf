# 05 · 已知风险：密码与审批

> 状态：**已锁定 / 原型 v0.2** · 2026-11-12（Asia/Shanghai）

本轮产品差异化就建立在两件事上：口令与密钥不能漏出去；写 / 高风险命令必须能被拦住。下列风险均须在实现时对冲，残留部分不要用「先做完再补安全」绕过。

## 1. 密码与密钥泄露（P0，已用产品规则对冲）

交互密码、私钥、SSHPASS 可能进入 URL、浏览器存储、审计、日志、命令历史、助手上下文或接口回包。

- 产品规则：插件不存明文密码；不做「记住密码」；密码不进 URL（旧版「内网过渡 + ack」**作废**）；密钥进宿主凭据库；刷新永不恢复秘密。
- 对策：`password_required` 时不创建标签；密码只活在创建 / 重连请求的内存；GET 与事件流不回显；`st:ui` 与审计强制脱敏；`POST /profiles` 拒绝持久化登录密码（`password_not_persistable`）。
- 残留风险：用户把私钥路径指到不安全位置，或在命令行里亲手输入 `mysql -p密码`。后者靠展示 / 审计脱敏缓解，不能从终端里禁止用户键入。本里程碑不做命令行参数防泄漏的完整拦截器。

## 2. 审批被绕过（P0）

若存在不走闸门的执行入口（旧「运行」API 旁路、片段直接 exec、助手自动跑、Agent 自批），AskWrite 形同虚设。

- 对策：提示符回车、片段运行、助手「批准后执行」、Agent `st_run_command` **只允许**进入 `POST /sessions/{id}/commands`。分类与模式判断只在服务端做。Agent 不得自批。resolve 不得改写命令。
- 「插入到终端」被实现成自动执行，视为缺陷。
- 残留风险：分类器把高风险命令误判为只读。未知命令在 AskWrite 下按写处理（偏严）。规则词表需可维护，但不得把默认模式改成 Auto 来「减少弹窗」。

## 3. 先建标签后补密码（P0）

先出现空标签再弹密码，取消时容易留下孤儿会话，或在无认证状态下暴露重连入口。

- 对策：无密码不创建会话（409 `password_required`）。取消 = 零新标签。重连失败保持 disconnected，已有输出仍在。
- 残留风险：网络超时后客户端误以为已创建。必须以服务端是否返回会话 id 为准，前端不得先插入空标签再请求。

## 4. 刷新恢复带出秘密（P0）

- 对策：恢复范围见 02 §8；存储用 sessionStorage 键 `st:ui`；QA 在 DevTools Application 中检查无 password / 私钥 / SSHPASS 明文。后端快照同样禁密。
- 残留风险：用户用浏览器同步重装扩展时拷走 sessionStorage。本产品是本机宿主单操作者模型，不声称对抗同步账号泄露；因此更不能把秘密放进任何 Web 存储。

## 5. 非 PTY 边界被误当成缺陷（P1，产品已声明）

长寿命壳 + 按行命令可以完成本里程碑，但 vim / htop、交互式分页器、需要原始键盘帧的程序可能不可用或表现差。

- 对策：对外文案与 06 验收都不把完整 TUI / 真实 PTY 当通过线。运行中提示符禁用，不把 Ctrl+C 当 P0。
- 残留风险：用户仍可能拿本插件当桌面终端。空态 / 文档保持「可审批的命令会话」口径，避免夸大。

## 6. 助手上下文与自动执行（P0 / P1）

助手若把未脱敏的命令输出（含 token）送进模型，或默认代为执行建议命令，会同时触发泄露与越权。

- 对策：送模型前脱敏；默认只建议；「插入」不执行；「批准后执行」走闸。不另开账号，避免插件自己保存供应商 Key。网关不可用只影响侧栏。
- 残留风险：脱敏词表无法覆盖所有秘密形态。与展示脱敏共用同一套规则，发现一种补一种，不得在助手通道单独放行原文。

## 7. 其它已知限制（不挡 03）

- 跨平台外壳列出但不可用，避免实现只做当前 OS 而 UI 写死另一边。
- `wsl-ssh`、URL 深链、`st_*` 完整回归：**建议沿用，待实现时与 03 对齐**，不挡主路径。
- 本机 `identityFile` 依赖文件权限；不可读时给 `credential_unavailable`，不要回文件内容。
- 宿主重启后待审批与内存会话作废，UI 按断开 + 本地回滚处理，不要伪造仍已连接。
