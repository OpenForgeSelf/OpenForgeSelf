> 口径延续：基础多标签（非完整 WT）、可审批的命令会话（非完整 PTY）、通用 URL 启动器、URL 密码仅内网过渡。

## 2. 屏幕 / 状态清单

| ID | 状态 | 用户可见要点 | 验收要点（建议截图） |
|----|------|--------------|----------------------|
| S0 | **空态** | 无标签；提示「+ 新建」或 URL 启动；推荐密钥文案 | 无串台；+ 可点 |
| S1 | **多标签** | ≥2 标签；单击切换；输出不串；× 关闭；双击重命名 | 切换后内容正确；关闭后焦点落到邻标签 |
| S2 | **新建面板** | shell 列表含 Linux/Windows 可用性标记 | 不可用壳 disabled |
| S3 | **通用 URL 启动成功** | 蓝条摘要含 `profile=`、步数；新标签标题正确 | 与 [03](./03-URL协议.md) 示例一致 |

| S5 | **交互式密码** | 遮罩输入（`type=password`）；显示 host/user；无明文回显 | 取消不连；确认后内存提交；历史/审计无明文 |

| S7 | **审计抽屉** | kind 过滤 + 搜索；无密码明文 | 含 launch / launch_connect 等 |
| S8 | **错误 / 401** | 红条 | 文案可读 |
| S9 | **权限徽章** | Auto / AskWrite / AskHighRisk | 随当前标签变 |

## 3. 关键交互流

### 3.1 通用 URL 启动（无认证）

1. 进入 `/smart-terminal?st=1&profile=local&step=...`  
2. scrub 触发键 → 建标签 → 按 `steps` 排队（仍受 AskWrite 约束）  
3. 顶栏蓝条展示脱敏摘要  

### 3.2 SSH 无密码 → 交互密码（**必做**）

1. `profile=ssh&host&user` 且无 password、非 key  
2. 建标签（或先弹窗再建成，产品可选；推荐**先出 S5 再创建**，避免空连）  
3. S5 输入 → 内存交给 launch → 连接 → 跑 steps  
4. 输入框可「显示/隐藏」可选；默认隐藏  

### 3.3 URL 带密码（内网过渡）

1. scrub 密码 → S4 ack（按 always-ack / intranet）→ launch  
2. 主推改走 S5 或 `auth=key`  

### 3.4 审批

命令分类 Ask → S6 → 批准后执行 / 拒绝写 system 行。

## 4. 文案与视觉约束（请产品拍板）

- 产品名旁副标题建议：「可审批的命令会话」  
- 不出现「完整 Windows Terminal」「完整 SSH 客户端」等夸大语  
- 密码相关按钮主色谨慎；危险操作用确认模态，不用 toast 一秒消失  
- 空态与 S5 明确推荐：**密钥登录**
