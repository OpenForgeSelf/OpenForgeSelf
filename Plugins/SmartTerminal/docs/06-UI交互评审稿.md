## 3. 关键交互流（定稿）

### 3.1 通用 URL 启动（无认证）

1. 进入 `/smart-terminal?st=1&profile=local&step=...`  
2. scrub 触发键 → 建标签 → 按 `steps` 排队（仍受 AskWrite 约束）  
3. 顶栏蓝条展示脱敏摘要  

### 3.2 SSH 无密码 → 交互密码（**必做 · 先框后标签**）

1. `profile=ssh&host&user` 且无 password、非 key  
2. **先出 S5**；用户确认后**再**创建标签并连接（禁止先建空标签）  
3. 密码仅内存交给 launch → 连接 → 跑 steps  
4. **不做**「记住本会话」；关标签即焚  
5. 输入框可「显示/隐藏」可选；默认隐藏  

### 3.3 URL 带密码（内网过渡）

1. scrub 密码 → S4 ack（按 always-ack / intranet）→ launch  
2. 主推改走 S5 或 `auth=key`  

### 3.4 审批

命令分类 Ask → S6 → 批准后执行 / 拒绝写 system 行。

### 3.5 刷新恢复

见 §5；用户刷新浏览器后按上限恢复标签 / 连接信息 / 输出缓冲。

## 5. 刷新恢复验收（S-R · 炳宏新增）

对标 VS Code 终端恢复思路：尽量还原标签与近期 scrollback，**不**持久化密钥。

| 检查项 | 通过标准 |
|--------|----------|
| 标签列表 | 刷新后标签数量、标题、顺序、激活项与刷新前一致（未关闭的标签） |
| 连接信息 | 可见 profile / host / user / cwd / shell / title；**不可见** password |
| 输出缓冲 | 每标签保留 **最近 1000 行或约 100KB UTF-8**（先到先截）内的近期输出 |
| 存活 | sessionStorage（或等价同标签页会话存储）；关终端标签或清站点数据后不再恢复该快照 |
| 安全 | Application 存储与审计中均无 password 明文；缺密 SSH 刷新后若需重连则再走 S5 |
| 截图 | 刷新前有输出的多标签页 → 刷新后同页对照各一张 |

详细范围见 [02-交互说明.md](./02-交互说明.md) §8。
