# TodoTracker · UI 设计简报（设计师向）

> 对应 pilot：`docs/ai/pilot/2026-11-19-todotracker-drawer-progressive/`  
> 可点原型：`docs/prototypes/drawer-progressive.html`  
> 面向：不读代码的审阅者  
> 实现口径：2026-11-19 闸门1 批准项（创建后自动开抽屉停概要、四栏默认收起；抽屉 480 / 窄屏 100%）

## 功能一句话

待办是「人快速记下、再补齐、在下发给 agent 前才强制验收标准」的任务台账。

## 用户旅程

1. **记下** — 只填标题（可选项目）→ 出现在列表，并自动打开右侧抽屉停在概要。  
2. **浏览** — 全宽列表/看板；缺下发字段时显示中性「下发前待补齐」，不是报错。  
3. **打开** — 点任务 → 右侧抽屉盖住，列表不被挤窄。  
4. **补齐** — 抽屉里按门类展开；先看概要，再开「工作单元」填目标/正文/验收/验证。  
5. **下发** — 点下发时若仍缺字段 → 点名告诉缺什么，并自动展开该分类。

## 界面交互行为

| 区域 | 行为 |
| --- | --- |
| 顶栏新建 | 标题空不能建；建完自动开抽屉停在概要，工作单元等分类默认收起 |
| 列表行 | 单击开抽屉；「下发前待补齐」可点「去补齐」，直达工作单元分类 |
| 编号徽标 | 每条任务恒显 `#<数字编号>` 徽标（列表行标题左侧 / 看板卡信息行 / 专注列表前缀 / 抽屉头部 Guid 前）；这是 agent 工具引用的编号（如 agent 说「#93 完成」即此号），只读不可点，悬停提示「待办编号（agent 工具引用）」；与委派串 `#run:…` 并存但样式区分 |
| 看板卡 | 单击同样开抽屉；软提示可点去补齐 |
| 抽屉 | 宽 480px（窄屏 100%）；遮罩/×/Esc 关闭（输入框聚焦时 Esc 不抢）；Teleport 到 body 防裁切 |
| 分类 | 概要恒显；基本信息/项目/工作单元/范围权限/下发委派/执行记录默认收起；点「去补齐」或下发缺项时展开工作单元 |
| 下发按钮 | 缺项可点 → 阻断并点名反馈 + 展开工作单元；齐备后走原流程 |

## 不要做成

- 创建弹窗塞满所有字段  
- 右侧永久分栏挤掉列表  
- 详情只读、编辑另开一页  
- 用红色错误样式暗示「创建失败」
