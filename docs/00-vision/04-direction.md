# 04-direction — 演进方向

> 状态：草稿（待用户确认）
> 最后更新：2026-08-06
> 本文件回答：功能往哪个方向演进、优先级怎么定。是 `15-roadmap/` 的上游输入。

## 演进方向（按主题）

### D1 深度（现有功能的真实可用性）
把已有的能力做深做透，优先于引入新能力：
- 聊天/模型选择动态化、API 鉴权补全、total 分页修复等（见 `02-goals.md` 当前阶段与 TODO.md）；
- 每个功能必须有 e2e 覆盖才视为"完成"。

### D2 广度（插件体系扩展）
在深度达标后，按插件化模式扩展新功能域：
- 候选方向：更多工具类插件（文档处理、数据导入导出）、跨插件工作流编排强化；
- 新增功能一律走 `Plugins/` + `plugin.json`，主程序只留宿主能力。

### D3 自治（自我演进）
向"项目自己评估提案 → 排路线图 → 实现 → 验证"演进：
- 依赖 `00-vision/` 文档完备 + 验证门禁自动化；
- 从"单次任务闭环"逐步到"跨任务自主规划"。

## 优先级决策准则（新功能提案评审用）

一个功能提案按以下顺序判定：

1. **是否符合 `03-principles.md`？**（违反任一条 → 否决/调整）
2. **是否服务于 `01-vision.md` 的愿景？**（与愿景无关 → 低优先）
3. **是否对齐当前阶段目标 `02-goals.md`？**（对齐 → 排进 roadmap；不对齐 → 进 backlog）
4. **成本收益**：实现成本（估算）vs 对 D1/D2/D3 的贡献，同优先级下先做收益大的。

## 明确不做（当前阶段）

- 云端同步/多端登录（与本地优先冲突，除非用户明确改变愿景）；
- 桌面端重写（保持 Vue + 托盘架构，除非架构评估另有结论）。
