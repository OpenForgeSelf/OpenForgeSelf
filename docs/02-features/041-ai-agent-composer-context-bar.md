## 1. 问题

批次 1（2026-10-15 上午）交付的 composer 能力是「**输入框上方** chips + `/` 面板内选择」。实测暴露三个问题：

1. **入口不可见**：模型切换、工具、技能、权限四类能力只能靠记忆打 `/` 才知道存在；用户对照截图找不到这些入口，判为「功能缺失」。
2. **布局与主流不一致**：上下文选择器在输入框**上方**，而业界主流（Claude Code 等）把上下文入口放在输入框**下方一行**——视线自然落在「我要发什么」和「在什么上下文发」。
3. **授权类信息散在消息流**：权限审批、Agent 反问、待办列表本属「下一步要你动作」的信息，却渲染在消息流里被滚动带走。

## 2. 目标与非目标

### 目标

| 编号 | 目标 | 验收 |
| --- | --- | --- |
| G1 | 输入框**下方**一行图标入口：项目 / Agent / 模型 / 工具 / 技能 + `+N` 溢出 + 权限胶囊 | 点任一图标弹出选择面板，改动即时反映到所发请求 |
| G2 | 每个入口**真实可用**：读真实后端数据、选中即改真实状态 | 所选项进入下一条消息的请求体（后端日志可见） |
| G3 | 权限胶囊**真实生效**（非装饰） | 三档权限对工具挂载集合产生实际差异 |
| G4 | 授权询问 / 审批 / 待办列表紧贴输入框上方 | 上翻消息流不影响其可见性 |

### 非目标

- 不做语音输入（参考图右侧麦克风）——浏览器语音识别依赖与实时流冲突，本批留接口不实现。
- 不改后端审批工作流（当前 AIAgent 后端无 approval 端点，见 §5 已知缺口）。
- 不重做 `/` `@` 行内触发（保留，与图标行并存互补）。

## 3. 交互设计

### 3.1 图标行（**嵌在输入框内**，输入框下方一行）

> 2026-10-15 修订：初版把图标行挂在输入框**外**（footer 底部），用户指出两点——
> ① 输入框**上方**的旧 chips（📁/🤖）与图标行信息重复，chips 已移除，
>    其「移除项目」能力补偿进项目面板（`PROJECT_CLEAR_ID` 特殊行）；
> ② 图标行应**嵌进输入框内**成为一体（对齐参考图：图标与权限胶囊就在输入框底行）。
> 做法：ContextBar 移入 `.aiw-input`（textarea 之后），加 `.aiw-ctxbar--inline`
> 以负 margin 抵消输入框内边距，顶部一条淡分隔线贯通全宽；同时**移除输入框聚焦时的
> 边框变色与光环**（常驻交互容器每次聚焦换色太闹）。

```
┌───────────────────────────────────────────────────────────┐
│ 消息输入区（textarea，placeholder 沿用现状）                │
├───────────────────────────────────────────────────────────┤
│ (+) (📁) (🤖) (💠) (🔧) (⚡) (+N)  [🛡 权限胶囊]   标准▾  ➤ │
└───────────────────────────────────────────────────────────┘
```

- 图标为**圆形描边按钮**，选中后填充主色 + 显示计数角标（工具 3 个 → 角标 `3`）。
- `+N` 为溢出入口：当可用项超过 6 个时收纳其余（本批：按已选项数动态计算）。
- **权限胶囊**常驻，显示当前档位文案（`完全访问` / `标准` / `只读`）。
- 右侧保留现状：状态指示（`标准` 位改为主色胶囊表示权限档，避免与既有 `.aiw-status` 混淆）。
- 面板打开时用 `mousedown.prevent` 保住输入框焦点（沿用 `.aiw-trgwrap` 既有做法）。

### 3.2 各图标点开行为

| 图标 | 面板内容 | 选中后 | 数据源 |
| --- | --- | --- | --- |
| 📁 项目 | 项目路径输入 + 已识别项目列表 | 写后端 `POST /api/project/directory` + 本地持久化 | 现状已有 |
| 🤖 Agent | Agent 列表（名称 + 描述） | 切 `activeAgentId` + 持久化 | `GET /api/agents` |
| 💠 模型 | 模型列表（按 provider 分组） | 切 `selectedModelId` + 持久化 | `GET /api/ai-models?enabledOnly=true` |
| 🔧 工具 | 工具多选（按 pluginId 分组，带描述） | 写 `selectedToolNames` | `GET /api/ai-agent/chat/tools` |
| ⚡ 技能 | 技能多选 | 写 `selectedSkillIds` | `GET /api/project/skills` 或 `/api/skills` |
| 🛡 权限 | 三档单选 | 写 `accessMode` + 派生工具白名单 | 本地（映射见 §3.3） |

### 3.3 权限三档语义（G3 的落地方式）

**后端现状**（实施前实测）：
- `ChatRequest` 无任何权限字段（`Plugins/AIAgent/Models/ChatModels.cs`）。
- `AIToolDefinition` / `AIFunctionDefinition` 无风险元数据（`ForgeSelf.Abstractions/ToolDtos.cs`）。
- **但** `ChatRequest.EnabledToolNames` 已是真实门禁：`AIAgentService` 第 396~408 行据此过滤挂载集合，并打日志「工具白名单过滤：请求 N 个，挂载 M 个」。

**决策**：权限三档**复用白名单通道**实现，不新增后端权限字段。理由：本仓工具契约无风险元数据（`AIToolDefinition` 只有 name/description/parameters），若要真正的「只读工具」集合必须先给全仓 ~100 个工具补风险标记——那是跨全插件的契约变更，范围远超本需求；而白名单过滤已是真实生效的门禁，把「权限」映射为「该档允许挂载哪些工具」既真实又零契约变更。

| 档位 | 语义 | 工具挂载集合 |
| --- | --- | --- |
| `readonly` 只读 | Agent 不得写用户文件、不执行命令 | 读类工具（项目文件读、记忆、todo 读、列表查询）+ 无 `run_terminal_command` / 无文件写 |
| `standard` 标准 | 可写文件、不可执行命令 | 默认作用域 + 显式勾选，剔除终端命令类 |
| `full` 完全访问 | 工具全开（含终端命令） | 全注册表勾选集合 |

档位随会话持久化（`localStorage`），并作为**派生白名单的上游**：用户手动勾选的工具与档位取交集——档位是上限，勾选是进一步收窄。

**已知局限（须如实告知用户）**：这是「工具可及性」控制，不是「操作运行时拦截」。当前 AIAgent 后端无工具执行前的二次门禁（无 approval 端点），故 `readonly` 档不构成对已挂载工具的强制拦截——它通过「不挂载写工具」来达成等效效果，而非运行时拒绝。

### 3.4 授权询问 / 审批 / 待办贴输入框（G4）

> 2026-10-15 修订（两次）：
> **修订二（待办拆独立入口）**：待办与审批/询问**生命周期不同**——待办是常驻任务面板
> （要独立入口、看全部），审批/询问是瞬时待你动作（要立刻操作）。混在一起待办会被
> 审批卡挤走。故拆为：`TodoEntry.vue`（输入框**下方底行最左**的入口按钮 + absolute
> 浮层列表，可整体收起/展开）+ `config.todos` 契约；`.aiw-ask` **只留审批/询问**
> （组件内过滤非动作项，防两处渲染同一份待办）。
> **修订一（浮层化）**：两处浮层均由 flex 流改 `position: absolute`
> （footer 加 `position: relative` 作定位上下文）——**不占内容区高度、悬浮于消息之上**，
> 内容区高度恒定（实测 footer 高度恒 73px，浮层展开/收起都不影响）。

在 `.aiw-composer` 与 `.aiw-input` 之间新增 `.aiw-ask` 区（紧贴输入框上沿），承载三类「待你动作」：

| 类型 | 渲染 | 数据来源 |
| --- | --- | --- |
| 权限审批 | 复用组件 `approval` 块的紧凑形态（风险徽标 + 标题 + 批准/拒绝） | `config.ask.items`（宿主注入，本批后端无生产者 → 由工具轨迹的 `dangerous` 标记驱动） |
| 询问用户 | 选项按钮组（单选/多选） | 同上 |
| 待办列表 | 紧凑清单（状态点 + 标题 + 进度） | `GET /api/todos`（TodoTracker 插件） |

**与消息流的关系**：这是**视图位置**变更——同样的数据，改在输入框上方渲染，不再混在 messages 里。组件侧由 `config.ask` 注入，默认 `null`（不渲染），宿主 AIAgent 侧组装。

## 4. 数据流

```
AIAgent 页状态（projectDir / agents / models / tools / skills / accessMode / todos）
   └→ buildContextBar() 组装 config.contextBar（{ items:[{key,icon,label,count,onPick}], accessMode, onAccessChange }）
        └→ ChatWidget 渲染 .aiw-ctxbar（输入框下方）
   └→ buildAskPanel() 组装 config.ask
        └→ ChatWidget 渲染 .aiw-ask（输入框上方）
发送时：accessMode → 派生白名单 ∩ selectedToolNames → EnabledToolNames → 后端真实过滤
```

**组件边界**（守 v1.8.0 迁移定的规矩）：`agent-core` 不认识「项目 / Agent / 模型 / 权限」这些 AIAgent 概念，只认 `config.contextBar` / `config.ask` 的形状与回调。组装逻辑放宿主侧 `composer.ts`（纯逻辑，可单测）。

## 5. 已知缺口（不在本批）

| 缺口 | 影响 | 归属 |
| --- | --- | --- |
| 后端无 approval 端点、无工具运行时门禁 | 权限三档是「不挂载」而非「运行时拒绝」；审批卡暂无真实生产者 | 后端另立项 |
| `AIToolDefinition` 无风险元数据 | 工具「只读/可写」只能靠本仓名册判定，不是工具自述 | Abstractions 契约变更，另立项 |
| 语音输入 | 参考图右侧麦克风未实现 | 本批非目标 |
| 工具「只读名册」 | `readonly` 档的只读集合需人工维护名册，漏收会误挂写工具 | 随 Abstractions 风险元数据一并根治 |
