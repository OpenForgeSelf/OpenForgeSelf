# 审慎不做决策（Decision NOT-to-do）台账

> 记录在**有限时间 / 资源**下明确选择**不做**（或**缓做**）的事项，及被否掉的候选方案。
> 目的：避免下次被误当作"漏做 / 待补 / 出问题就要修"，避免重复评估、前后决策矛盾。
> 使用：每轮任务汇报的「不做事决策」字段按本台账模板逐条登记；新决策追加，勿改写历史条目。
> 关联：正数决策（"做"）的 ADR 见本目录其他 `<NNN>-*.md`；本期汇报模板见 `AGENTS.md §10.4`。

## 002 · 插件前端方案 B（后端源码收进 `src/server/`）

- **决策**：否掉，先落地方案 A（前端仅规范化到 `web/`，后端零迁移），方案 B 列为远景。
- **为何不做**：方案 B 需全量重构 14 个插件目录 + 各 csproj 相对路径 + PluginManager / build.ps1 / publish-plugin.ps1 / 测试同步目标，属架构级高风险（AGENTS §3.3），而本特性目标是「插件自带界面」，不应被一次全仓重构绑架。方案 A 已完整满足 FR-001/FR-011。
- **重新审视的触发条件**：出现「必须统一前后端源码目录布局」的强需求（如新插件暴露出分散维护之痛），且能安排独立重构窗口时不阻塞业务。
- **状态**：有效（记录自 `specs/010-plugin-frontend-runtime/design/plugin-directory-layout.md`）。

## 001 · 进程级全局状态测试 flaky 彻底修复（ForgeConfig / ProxyCapture / ScriptRunner）

- **决策**：缓做，不在此轮一次性根治。
- **为何不做**：已用串行化 + 排除已知 flaky 保持全量绿（1031/1031）；真修复（每个污染用例自行 save+restore，finally 还原 FileName、CaptureEngine 重置）改动面大且与业务无关，当前资源应投到更贴近愿景的待办。
- **重新审视的触发条件**：该 flaky 频率开始（a）阻塞 CI 门禁 或（b）连续吞噬排查时间（≥2 次/周），才值得一次根治。
- **状态**：有效（对应 TODO「进程级全局状态测试 flaky」）。

## 003 · spec010 剩余测试（T012 组件测试 / T017–T021 E2E / T023 错误捕获 / T024–T028 门禁）

- **决策**：缓做，不等这批做完就收尾 US1。
- **为何不做**：这批多为 L1/L2 **端到端或需宿主运行时**（插件远程加载渲染、失败降级 UI、首访路由竞态），跑起来需起宿主 + 前端 + 打包插件，成本高；而 US1 的核心契约已由 T006/T011 单测锁死，残余风险是「运行期集成」层面的。当前把资源投到这里，边际收益低于投给下一个贴近愿景的功能。
- **重新审视的触发条件**：插件界面**正式对外启用**，或要新增第二个带 `web/` 的插件时，先补 T012/T017–T021 的 E2E 再放行，避免带未知集成风险面世。
- **状态**：有效。

## 004 · 硬编码 hex → 官方 `--el-*` 统一（P2）

- **决策**：缓做、分批。
- **为何不做**：grep 命中 48 个 `.vue` 文件，其中 ColorTool / RegexTester / JwtTool 等开发类工具**本就需展示 hex（合理）**，需先人工区分「合理展示」与「可改用 `--el-*`」再替换，量大且易误伤。纯 UI 组件（PluginDetailModal / JwtTool / JsonTool / LinkCard / CategoryManager）已识别但未见功能回归风险。
- **重新审视的触发条件**：做某一 UI 组件的样式调整 / 引入新主题 token 时**顺带**替换该组件，而不是开一个专门的替换专项。
- **状态**：有效。

## 005 · 插件热重载后宿主 DI/ALC 类型错配（控制器 500 基建缺陷）

- **决策**：缓做，不在此轮修 side-by-side ALC；插件生效走「全量发布 + 冷启动宿主」，禁用热重载覆盖已加载 dll。
- **为何不做**：2026-08-30 实测定位：插件控制器 `/api/agents` 500 空体根因非路由、非业务逻辑，而是**热重载**用新 ALC 重新加载插件 dll → 类型标识分裂 → 宿主 DI 里启动期收集的**转发描述符仍指向旧 ALC 类型** → `Unable to resolve IAgentRegistryService` 控制激活失败。`publish-plugin` overlay 在宿主运行期再写插件目录恰会触发该热重载（日志 `热重载/销毁/启用 ai-agent`）。同环境 `/api/todos`（TodoTracker 未热重载）正常佐证。真修复需插件服务侧载（versions/`<ver>`/ + `current` 指针）或用 `Assembly.Load` merge 进宿主 ALC——属架构级改动，且当前「全量发布 + 冷启动」流程稳定、零额外成本。
- **重新审视的触发条件**：需要「热更新单插件 dll 就能立即对宿主 DI 生效（不重启）」的产品化诉求出现（如插件在线升级成为对外能力）时，为 spec010 路由/DI 的 side-by-side 补正。
- **状态**：有效。对应 TODO 阻塞项「宿主插件 MVC 控制器统一 500」已于 2026-08-30 冷启动验证解除（`/api/agents` 200 OK）。

## 新旧决策衔接原则

- 已被本台账**否掉**的方案，若日后又要立项，**必须**在此标注「已被推翻」并写明新依据，不得悄悄改判。
- 「不做」≠「永远不做」：触发条件满足即可重新评估；本台账只为让每次评估有据可查、可追溯。
