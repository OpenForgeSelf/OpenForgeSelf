# 审慎不做决策（Decision NOT-to-do）台账

> 记录在**有限时间 / 资源**下明确选择**不做**（或**缓做**）的事项，及被否掉的候选方案。
> 目的：避免下次被误当作"漏做 / 待补 / 出问题就要修"，避免重复评估、前后决策矛盾。
> 使用：每轮任务汇报的「不做事决策」字段按本台账模板逐条登记；新决策追加，勿改写历史条目。
> 关联：正数决策（"做"）的 ADR 见本目录其他 `<NNN>-*.md`；本期汇报模板见 `AGENTS.md §10.4`。

---

## 台账模板（新条目照此填）

```
### YYYY-MM-DD · <主题>
- **决策**：不做 / 缓做 / 否掉某方案
- **为何不做（代价/收益）**：做要花什么、收益多大、值不值
- **重新审视的触发条件**：什么样的信号出现才值得重新做
- **状态**：有效（默认）/ 已被推翻（注明时间与原因）
```

## 005 · 插件热重载后宿主 DI/ALC 类型错配（控制器 500 基建缺陷）

- **决策**：缓做，不在此轮修 side-by-side ALC；插件生效走「全量发布 + 冷启动宿主」，禁用热重载覆盖已加载 dll。
- **为何不做**：2026-08-30 实测定位：插件控制器 `/api/agents` 500 空体根因非路由、非业务逻辑，而是**热重载**用新 ALC 重新加载插件 dll → 类型标识分裂 → 宿主 DI 里启动期收集的**转发描述符仍指向旧 ALC 类型** → `Unable to resolve IAgentRegistryService` 控制激活失败。`publish-plugin` overlay 在宿主运行期再写插件目录恰会触发该热重载（日志 `热重载/销毁/启用 ai-agent`）。同环境 `/api/todos`（TodoTracker 未热重载）正常佐证。真修复需插件服务侧载（versions/`<ver>`/ + `current` 指针）或用 `Assembly.Load` merge 进宿主 ALC——属架构级改动，且当前「全量发布 + 冷启动」流程稳定、零额外成本。
- **重新审视的触发条件**：需要「热更新单插件 dll 就能立即对宿主 DI 生效（不重启）」的产品化诉求出现（如插件在线升级成为对外能力）时，为 spec010 路由/DI 的 side-by-side 补正。
- **状态**：有效。对应 TODO 阻塞项「宿主插件 MVC 控制器统一 500」已于 2026-08-30 冷启动验证解除（`/api/agents` 200 OK）。
