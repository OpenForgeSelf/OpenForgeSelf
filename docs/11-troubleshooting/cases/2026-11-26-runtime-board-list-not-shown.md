# case：运行实况列表与页面不一致（2026-11-26）

## 现象

重新扫描之后，已登记项目目录下的进程没有留在运行实况里。脚本和工作流的执行详情是空的。带 `session` 打开智能体时，页面是新会话，看不到待批。已经同意的卡片仍被算进页头数字。

## 时间线

- 运行实况按计划做完后，验收只有单测，没有按状态截图。
- 用正规入口拉起验证栈，用各来源自己的接口造数据，再打开 `/task-center`。
- `POST /api/runs/check` 能发现进程，随后的 `GET /api/runs` 只剩本面板拉起的进程。当前列表的注释写着含上次检测，实现只返回本面板拉起的进程。
- 脚本和工作流详情把 `{ data, success }` 信封摊开，状态又是数字，详情组件对不上字段。
- 智能体路由实际导出的是助手页。助手页不读 `session`，也不拉取工具待批。旧页面读了查询参数，但没有被导出。
- 同意之后卡片留下结果句，页头数字仍把这张卡片算进去。

## 同类扫查

同根因，已在本任务修：

- 工程台当前列表丢掉上次扫描。
- 脚本、工作流详情不解信封、不译状态。
- 智能体深链改到未导出的页面。
- 页头数字包含已写下结果的待批。

同一次走查里看见、根因不同、不并入本类修复的：

- 没有可用对话模型，所以没有要续跑，也没有未结束的智能体回合。
- 文件扫描在页面第一次拉取前就结束。
- 扫描不收录对不上项目的进程，因此没有仅 pid 的系统监控行。
- 智能体待批列表在该宿主上不要求访问密钥。这是鉴权策略，不在本类改。

## 修复

见 [PC-052](../problem-classes/PC-052-runtime-board-list-not-the-list-shown.md)。当前列表合并上次扫描里仍活着的进程。详情解开信封并映射状态。助手页按 `session` 放入待批。页头用排除已写结果的计数。
