# Intent

> 阶段：Stage 1｜只描述「为什么做 / 做什么 / 做到什么程度」，不提前决定具体代码实现。
> Task ID：PILOT-ds-m2-showroom ｜ 日期：2026-10-01

## Problem

M1 之后，设计插件对**机器**（agent / MCP）已经可用；但对**人**仍然是一个"设计师工作台"：

1. **交互不友好**：14 个专业 section 平铺成一排导航（令牌工作台、色彩实验室、尺度与密度、审计与门禁…），术语（令牌 / primitive / 门禁 / 投影）对不懂设计的人是障碍；顶栏「新建」用两次 `window.prompt`；生成向导要手填 hue / chroma / typeRatio / radiusBase 等专业参数，没有"选一个我喜欢的风格"这条路。
2. **没有"效果展示"**：现在只有「组件库」「品牌展示页」两处能看效果，只能看**当前项目**，且只有零散组件样张，没有"一整个页面套上去"的体验；想比较两套设计只能来回切项目；想"先试穿再决定"做不到（`generate/preview` 只回摘要不回 CSS，生成后才能看到）。
3. **没有接入引导**：创建完设计系统后，开发者/agent 怎么用它——MCP 地址、`agent-rules` 提示词、brief、写入开关——要么藏在别处，要么根本没有界面入口。

## Why

用户目标（2026-09-30 原话）：「可在插件页面管理项目，查看效果，进行效果展示和微调。效果展示通过内置组件以及页面，通过不同设计进行展示，类似卖衣服的模特，换衣服就是换设计系统，往模特身上套就行」；「可以给专业设计，也可以给不懂设计的程序员，或者完全不懂设计和开发的外行等使用」；「交互也很不友好」。M2 把 M1 的机器能力（预设 / 快速创建 / brief / agent-rules / 写开关 / 工具索引）变成**人能直接用**的界面，同时让"效果"成为可感知的。

## Expected Outcome

- **四个模式**：开始（向导）/ 展厅 / 工作台（原 14 个专业 section 原样收入）/ 交付与接入。外行从「开始」走完 4 步得到一套可用设计系统；设计师仍能用熟悉的工作台。
- **展厅**：左「衣柜」（我的设计 + 风格预设，缩略图 = 内存预览）、中「舞台」（场景与页面切换、设备框、明暗与密度）、右「微调」（品牌色 / 圆角 / 密度 / 字阶 / 动效，实时预览，**保存才落库**）。模特是一批只消费 `--ds-*` 变量的内置页面，五类场景全覆盖：后台/中台管理、工具/工作台、状态板、官网/落地页、移动端 H5；支持并排对比两套设计。
- **交付与接入**：MCP 网关地址与客户端配置片段、`agent-rules` 与提示词一键复制、brief / DESIGN.md / tokens.css / 整包下载、工具索引与写开关、贴代码试审查。
- **术语词典**：新模式用大白话，一个"专业术语"开关可切回行话。
- 后端新增**一个**端点 `POST generate/preview-css`（内存预览，不落库，与导出同源）；其余全是前端。

## Constraints

对照规范 §1 硬性约束逐条：

1. 不改生产；agent 不停/启用户宿主；未授权不提交 git / 推 tag。
2. **不改数据库结构**（`Model.xml` 零 diff；`DesignGuideline` 属 M3）。
3. 不改鉴权/权限/安全核心：新端点沿用类级 `ApiKeyPolicy`；展厅**不写库**，唯一写入口是「保存为新设计」且走 M1 的 `quick-create`。
4. **不新增依赖**（npm / NuGet 均不增）；插件界面**不使用 Element Plus 组件**（原生标签 + 令牌变量）。
5. **不改 14 个专业 section**（组件、DOM、类名、文案原样），e2e 只允许**新增** `enterWorkbench()` 助手并在页面刚加载与 `reload` 之后各调用一次（`nav()` 与全部断言不动）。
6. **模特零字面量**：模特页面只消费导出的 `--ds-*` 变量，不出现字面色值/字体栈/阴影（前端不得长回第二套设计值，自查表 #8）；它引用的每个变量必须在每个预设的导出 CSS 里有定义（防"整片透明"）。
7. 不接 LLM（"一句话出设计"由选择题向导 + 预设推荐承担）；不改 McpCenter / 宿主 Element Plus 主题。
8. 必须真实跑测试 / 构建 / e2e；失败不伪造；截图必须读图（Level 3）。
9. 数据安全铁律 10：不提供任何删除；归档 = 软删。

## Success Criteria

（详见 02-spec 的 AC 全表；摘要）

- 后端：`preview-css` 对 8 个预设 × 明暗主题与「同请求落库后导出」的 CSS 逐字一致（去注释后），且调用前后 12 张表行数不变；模特引用的每个 `--ds-*` 在每个预设 CSS 里都有定义。
- 前端：`pnpm run check/test/build` 全绿；`window.prompt` 清零；向导状态机、微调竞态守卫、术语词典、模特零字面量、皮肤作用域参数化均有 vitest 钉住（含反例）。
- e2e（真实宿主）：向导走完 → 项目真入库且令牌 >100；展厅画布底色 == 后端该主题 `semantic.surface-bg`（预设与已存项目各一）；微调不落库、保存才落库；并排对比两画布底色各自等于各自后端值；交付页网关地址 == `GET api/mcp-center/config` 的 `listenUrl + /mcp`；既有设计系统 e2e 无新增红。
- 视觉 QA：预设 × 场景 × 明暗抽样截图逐张读图，缺陷已修或记 TODO。
