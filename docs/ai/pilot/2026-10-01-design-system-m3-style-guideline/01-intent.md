# Intent

> 阶段：Stage 1｜只描述「为什么做 / 做什么 / 做到什么程度」，不提前决定具体代码实现。
> Task ID：PILOT-ds-m3-style-guideline ｜ 日期：2026-10-01

## Problem

M1 让机器能用设计系统，M2 让人能看、能试、能接入；但设计系统**本身的质量与完整度**仍有两个缺口：

1. **风格几乎只能换色**：生成器真正可变的只有色相、彩度、圆角基准、密度、字号比例与动效倍率；字体栈、阴影模型、描边、组件到圆角档的映射、中性色取向全部写死。结果是不同行业/不同"性格"的设计系统看起来大同小异——展厅里换十件"衣服"，轮廓却是同一个人。用户要的是"都能产出令人满意的设计"。
2. **只有 UI，没有 UX**：设计系统只覆盖视觉令牌（颜色、字体、间距、阴影、动效、组件规格）。布局栅格、页面模式、导航、表单与校验、反馈与状态、文案、可达性、动效使用规则这类 **UX 规范**没有载体——"后续项目开发，关于前端 UI/UX 的一切都依据该插件产出的设计系统，唯一真源，开发完页面审查也可作为依据"只兑现了一半。

## Why

用户目标（2026-09-30 原话）：「都能产出令人满意的设计，输出完整的设计系统」「关于前端 ui ux 的一切都依据该插件产出的设计系统，唯一真源，开发完页面审查也可作为依据」。M3 补齐这两块：让风格**真的有差异**（且每个差异都可复现、过审计、能在展厅里看见），并把 UX 规范变成**库里的数据**——可编辑、进快照与版本、进所有交付物、agent 和审查都能读到。

## Expected Outcome

- **风格轴**（后端，向后兼容）：阴影风格 / 阴影强度 / 描边强度 / 中性色温 / 字体搭配 / 圆角风格 / 强调色策略 七个可选参数；**每个轴取值都真改产物、都过审计**；全部缺省时产物与 M3 开工时**逐字节相同**；取值词表由 `GET meta.styleAxes` 供给，界面与工具不另抄。
- **预设库**从 8 个扩到 13 个（新增 5 个专门体现不同轴取值的预设），原 8 个预设不改。
- **UX 规范**：新增 `DesignGuideline` 表（唯一的结构变更）；确定性的 `GuidelineGenerator` 按用途/行业/密度产出一套默认规范（布局栅格、页面模式、导航、表单、反馈、状态、按钮层级、数据展示、文案、可达性、动效、层级与阴影、密度、响应式，共 14 条）；规范**只写令牌路径、不写数字**（数字由渲染端查当前令牌值，杜绝漂移）；可编辑（手改行受保护）、归档 = 软删；进 `brief` / `design-md` / `bundle` / 版本快照（schema 2→3，且 diff 对旧快照 kind 级"不可比"）；`design_context / design_lookup / design_edit / design_review checklist` 读写同一份数据（工具仍 ≤8 个）。
- **界面**：工作台新增第 15 个 section「UX 规范」；展厅微调面板的「更多风格选项」读 `meta.styleAxes`。
- 视觉 QA：不同轴取值在展厅里肉眼可辨，且读图无缺陷。

## Constraints

对照规范 §1 硬性约束逐条：

1. 不改生产；agent 不停/启用户宿主；未授权不提交 git / 推 tag。
2. **结构变更仅限新增一张表 `DesignGuideline`**（加法、自动建表、旧数据不动）；不改既有表/列；**闸门1 必须显式批准**这一条（见 04-task「闸门1 待批事项」）。
3. 不改鉴权/权限/安全核心：新增 REST 沿用类级 `ApiKeyPolicy`；规范写入沿用 M1 的写开关（对 `design_*` 工具路径）。
4. **默认轴逐字节兼容**：不传任何新参数，产物（令牌值/别名/种子/CSS）与开工时 HEAD 完全一致（黄金哈希钉住）；这是"不破坏存量项目"的硬判据。
5. 不新增依赖；不接 LLM（规范由确定性模板 + 参数产出）；不改宿主 / McpCenter。
6. **不扩充组件蓝本**、**不改 Stardust 十类实体**（会改变默认产物/外部契约；如需另立项）。
7. 数据安全铁律 10：不提供任何删除；规范归档 = `Status=archived`；不回填存量项目的规范（只在用户显式生成时写入，避免静默改变已发布版本的内容哈希）。
8. 必须真实跑测试 / 构建 / e2e；失败不伪造；视觉 QA 必须读图。
9. 规范文案是产品内容：实现方产出初稿，**交用户在闸门2 审阅**（规划/验收方只验结构、同源与可核对性，不替用户拍板措辞）。

## Success Criteria

（详见 02-spec 的 AC 全表；摘要）

- 黄金回归：13 个预设（含新增）里原 8 个 × 各主题的规范化令牌文本哈希与开工基线逐一相等；每个轴的每个非默认取值都有"改了哪些令牌"的断言与"审计 0 critical"的矩阵断言。
- 同源：`preview-css` 与落库导出对 13 个预设仍逐字一致；M2 模特变量契约对 13 个预设全过。
- 规范：生成器确定性、引用的令牌路径全部真存在、对用途/密度/行业有敏感性；CRUD 与软归档；`brief/design-md/bundle` 含规范；快照 schema 3，schema 2↔3 的 diff 不凭空报新增、v3↔v3 能报规范变更；无规范的存量项目同版本同内容重发**仍幂等**；旧库升级后新表自动建出且旧数据不动。
- 工具/界面：`design_edit action=guideline`、`design_lookup kind=guideline`、`design_context sections=guidelines`、checklist 派生项；第 15 个 section 读写回读；既有 14 个 section 与既有 e2e 无新增红。
- 视觉 QA 与文档/技能更新完成。
