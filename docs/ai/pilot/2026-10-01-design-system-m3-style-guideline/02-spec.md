## Input

- 生成：`GenerationRequest` 全部既有字段 + 7 个新字段（缺省 null）。
- 规范：`PUT guidelines/{code}` 体 `{title, summary, body, category, rules:[{level,text}], tokenRefs:[path], appliesTo:[kind], status?, expectUpdatedAt?}`；`generate?overwrite=`。
- 工具：见 FR13。

## Output

- `generate` / `quick-create` 响应增 `guidelines`（条数）；`meta` 增 `styleAxes`、`guidelineCategories`、capabilities `guidelines`。
- 规范读取：`{code,category,title,summary,body,rules[],tokenRefs[],brokenRefs[],appliesTo[],source,status,updatedAt}`。
- 导出：见 FR11；`bundle` 增两个文件；快照 `schemaVersion=3`。

## Business Rules

1. **默认轴逐字节兼容**（黄金哈希钉）：任何新参数缺省时，产物与开工 HEAD 一致；这是不破坏存量项目的硬判据。
2. **每个轴值真改产物且过审计**：非默认取值必须改动白名单内至少一条令牌，并对所有主题（light/dark/high-contrast/compact）审计 0 critical；改了白名单外的路径 = 缺陷。
3. **规范只写令牌路径、不写数字**：数字由渲染端（brief/design-md/bundle/界面）**同一个函数**查当前有效令牌值得到；令牌后来改值，规范无需改；令牌被删/改名 → `brokenRefs` 可见、渲染标注"（令牌已不存在）"，不静默。
4. **手改保护**：`Source=manual` 行 `generate` 不覆盖；`overwrite=true` 才覆盖，且响应列出被覆盖 code。
5. **只写不删**：规范归档 = `Status=archived`；无 DELETE；旧快照文件不动。
6. **升级安全**：旧库只加表；已发布版本的内容哈希不被升级改变（无规范项目 hash 相同）；不回填存量项目。
7. **同源**：`preview-css` 与落库导出对 13 个预设仍逐字一致；模特变量契约对 13 个预设全过。
8. **规范文案是产品内容**：实现方产出初稿并随 05 提交"规范全文清单"，由用户在闸门2 审阅；规划/验收方只验结构、可核对性与同源。
9. **工具仍 ≤8 个**；写开关对 `design_edit action=guideline` 同样生效。

## Boundary Conditions

- 存量项目无规范：`design_context` / 导出对应章节不开；界面空态引导"重新生成默认规范"；`design_review checklist` 回落 M1 静态基线。
- 项目 `kind` 未知：回落 `product` 模板；`industry` 取生成时的推断值（不可得则 `general`）。
- `tokenPaths` 缺某引用：该引用被过滤；规则文本不依赖数字，故规则保留。
- `font.display` 仅 `fontPairing=editorial` 时存在：brief/界面/导出对缺失它不报错；`SeedBrandCatalog` 对它登记 `role=display` 的字体行（仅当令牌存在）。
- 并发：规范保存/生成走整批事务；`PUT` 带 `expectUpdatedAt` 不一致 → 409，不一致时不写。
- 规模：每项目 ≤200 条规范；`Body ≤ 4000`；`rules ≤ 30`/条。
- 窄屏：第 15 个 section 的列表/详情纵向堆叠。

## Error Handling

| 情形                                    | 行为                                                           |
| --------------------------------------- | -------------------------------------------------------------- |
| 风格轴取值非法                          | 400：`风格轴 x 的取值 v 不在 [..] 内`                          |
| `tokenRefs` 含不存在路径                | 400 + 逐条列出不存在的路径；零行写入                           |
| `level`/`category`/`code` 非法          | 400 + 合法取值                                                 |
| `PUT` 的 `expectUpdatedAt` 过期         | 409 + 最新 `updatedAt`                                         |
| 超限（条数/Body/rules）                 | 400 + 上限                                                     |
| `generate` 遇手改行且 `overwrite=false` | 跳过并在响应 `skippedProtected` 列出 code（不静默）            |
| 旧快照 diff 缺 guideline                | `NotComparableKinds=["guideline"]`，界面显示"不可比"，不报新增 |
| SQLITE BUSY                             | 读重试；写绝不重试                                             |

## Compatibility

- **REST**：纯增量（新端点、`meta` 增项、`generate` 响应增键 `guidelines`、`GenerationRequest` 增可选字段）；既有端点与形状不变。
- **数据库**：仅新增 `DesignGuideline` 表；`Model.xml` 对既有 12 张表**零 diff**；`Data/Entities` 仅新增 `DesignGuideline.cs/.Biz.cs` 并更新 `DesignSystem.htm`。
- **快照**：schema 2→3；读旧文件兼容；无规范项目 hash 不变。
- **前端 / e2e**：原 14 个 section 与文案不变（`ReleaseBoard.vue` 仅新增一处 `notComparableKinds` 提示）；既有 e2e 的 14 个 `nav` 断言、`entities.length===10`、`auditKinds` 序断言不变（M3 不改审计类别、不改 Stardust 十类）。
- **M1/M2**：M1 工具 schema 只增属性（对表测试同步更新）；M2 `preview-css`/展厅/模特契约继续成立（对 13 个预设）。
- **版本**：3.0.0 → 3.1.0（三常量与 `plugin.json` 同步）。

## Non-functional Requirements

- **确定性**：生成（含风格轴）与 `GuidelineGenerator` 无随机、无时钟参与结果；同输入逐字节相同。
- **性能**：非默认轴生成耗时与默认同量级（单次 p95 ≤ 默认的 1.5 倍，实测记 Evidence）；`GuidelineGenerator` < 50ms。
- **安全**：规范正文一律文本节点展示；写入走类级鉴权 + 写开关（工具路径）；不接受服务器路径输入。
- **可维护**：风格轴取值/默认值只在 `StyleAxes` 一处定义；分类词表只在 `GuidelineCategories` 一处定义；渲染端取值函数只有一个（`GuidelineRenderer`）。
- **无警告**：新增代码 `dotnet build` 0 warning（生成的 Entities 存量 warning 不计）。
