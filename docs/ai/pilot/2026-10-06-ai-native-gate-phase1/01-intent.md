# Intent

> 阶段：Stage 1｜只回答为什么做 / 做什么 / 做到什么程度。

## Problem
AI-Native 流程的"防偏离"机制存在多处缺口与失真：文档声称的 CI 门禁不存在；钩子用错 PowerShell 引擎；校验脚本与流程规范在"轻量任务"上自相矛盾；改动业务代码无需任何工件即可提交；功能文档没有稳定需求 ID，导致需求无法从文档一路追溯到测试与证据。

## Why
流程若无机械化闸门，只能靠 Agent 自觉；文档与实现一旦偏离，后续每个任务都会在错误前提上继续。本轮要把"让偏离可见"的机制补齐，并消除文档说谎的部分。

## Expected Outcome
- 非文档改动必须有对应 pilot 工件（提交时机械拒绝）。
- 工件链校验支持轻量形态，消除与流程规范的矛盾。
- 宪法层文档与实际仓库一致（路径、CI、表述）。
- 功能文档具备稳定需求 ID 的规范、模板与半自动回填工具。

## Constraints
- 只增不改：不改动现有 39 篇功能文档的既有内容（回填仅注入骨架，且本批只做样例）。
- 不改运行时代码；不动 `Plugins/**`、`ForgeSelf.Web/**`、`ForgeSelf.Api/**`。
- 不提交 git（留给用户）。

## Success Criteria
1. 新增闸门脚本与钩子通过语法检查，并在能执行 git 的环境下可运行。
2. 工件链校验对轻量目录返回 PASS、对缺头部块目录返回 FAIL。
3. 判级脚本给出与改动面相符的级别。
4. 迁移规范、模板、回填工具就绪且回填工具 dry-run 覆盖全部 39 篇。
