# Intent

> 阶段：Stage 1｜只描述「为什么做 / 做什么 / 做到什么程度」，**不提前决定具体代码实现**。
> Task ID：PILOT-053 ｜ 日期：2026-10-06

## Problem

用户要验证「一个 AI 会不会正确使用工具」，但他用的是**网页版聊天**（没有 API、没有函数调用通道，也无法直连本机）。现有链路只能这样跑：

1. 把一段"本机支持哪些工具"的初始化指令发给网页 AI；
2. AI 回一段自然语言 + 工具调用文本；
3. 人把这段文本搬到本地执行，再把执行结果搬回去。

第 3 步**今天没有任何工具承接**：仓内既没有"解析 AI 返回文本里的工具调用"的代码（00-repository-understanding §候选原因 已 Verified 确认），也没有一个"粘进来→跑掉→结果原样给你复制走"的界面。MCP 中心的 `tools/{toolId}/test` 是 `Thread.Sleep` + 恒 `Success=true` 的假端点（`Plugins/McpCenter/Services/McpService.cs:207-241`），承接不了这个场景。

于是每轮测试都得人肉开终端敲命令、手动截 stdout，既慢又拿不到"AI 拿到的到底是什么"的忠实记录 —— 而这正是评估 AI 工具调用能力时唯一有意义的观察数据。

## Why

- **这是评估，不是日常执行**：内置 AIAgent / AgentHub 走的是结构化流式协议（`ReactLoopAgent.AccumulateToolCall:824-836`，输入已是 provider 解析好的 delta），无法用来观察"某个外部模型在纯文本约束下能否正确拼出工具调用"。缺的正是**文本协议这一侧的承接器**。
- **安全面必须显式**：这个场景会在用户真机上起进程、写文件。仓内已有一套经 e2e 实测打磨过的命令策略（换行/管道即拒、白名单、破坏性词红线、`-EncodedCommand` 解码扫描），新场景没有理由另起一套更松的口径。
- **落点必须受限**：AI 生成的路径不可信，读写要能被限制在一个可改的工作根内，越界即拒。

## Expected Outcome

新增一个自带界面的插件（运行时 id 建议 `tool-bridge`，见 03-plan 命名节），使用户能在一屏内完成一轮人工 agent 回合：

1. **出去**：一键复制"给 AI 的初始指令"，其中自动列出本机支持的工具名、参数 schema、以及要求 AI 用什么格式回复；
2. **进**：把 AI 的回复整段粘进来，插件识别出其中的**全部**工具调用（认不出来的部分原样列出并说明为什么没认出来，**绝不猜**）；
3. **跑**：在指定工作目录内真实执行读文件 / 写文件 / 列目录 / 执行命令，命令受白名单与破坏性红线约束；
4. **回**：把每条调用的结果（文件内容、退出码、stdout/stderr 原文、拒绝原因）原样拼成一段可一键复制的文本，粘回给 AI 就是它能读懂的观察；
5. **留**：每一轮（粘贴文本 + 解析出的调用 + 执行结果）留有可回看的记录，便于对比 AI 在多轮里的表现。

做到什么程度：**这一期是一个能真跑通"提示词出去 → 结果回来"完整一轮的最小可用插件**，含单测 + 插件层 e2e + 界面走查；不做的是"把全仓 77 个已注册工具都开放""把工具调用做成内置 agent 的一部分""自动对接任何 AI API"。

## Success Criteria

全部可自动化或现场实测判定，不接受"看起来能用"：

1. 复制出的初始指令文本里**逐字包含**四个工具名与其参数 schema；把这段文本喂给任意网页 AI，插件能认出该 AI 回的工具调用（由单测 + e2e 各钉一条）。
2. 对同一段 AI 文本，`解析` 与 `执行` 是两个可分别验证的动作：解析结果不启动任何进程、不写任何文件（由守卫测试断言"纯解析零副作用"）。
3. 认不出的片段以原文形式出现在诊断区，且带**具体原因**（如"JSON 缺 tool/name 字段"）；不产生任何猜测性调用（反向探针：给解析层塞入猜测分支 ⇒ 用例必红）。
4. 越界路径（`../`、绝对路径指到工作根之外）一律拒绝，拒绝响应里带工作根与目标路径；命令走白名单外的可执行名一律拒绝并原样回报守卫原因。
5. 结果文本可一键复制，且复制内容是执行结果的**原文**（stdout/文件内容不被 JSON 转义破坏、不截断到丢失结尾标记，超限必须显式标 `truncated`）。
6. 一轮回合产生一条可回看的记录（含粘贴原文、解析清单、每条结果），记录落文件且重启插件后仍读得到（证明不是只在内存里）。
7. 门禁：插件后端单测全绿；`dotnet build ForgeSelf.Api` 后**宿主产物内存在 `Plugins/ToolBridge/ToolBridge.dll` 且与插件目录 md5 相同**（铁律 12b 判据，不能只报插件目录自建通过）；宿主前端 `check`+`test` 无新增红；插件层 e2e 走真实前后端跑绿并出截图，按 `e2e-testing` Level 3 读图核对。
8. 五步维护闭环全部有证据（门禁/e2e/发布/隔离实例走查/运行实例只读复验；后两步依发布授权与用户升级动作，未做的如实标 Unknown）。
