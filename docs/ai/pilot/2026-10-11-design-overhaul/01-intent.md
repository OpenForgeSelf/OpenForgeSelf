# Intent — 按高保真设计稿全面改造（设计对齐总规划）

> 阶段：Stage 1｜Task：DESIGN-OVERHAUL-2026-10-11｜日期：2026-10-11
> 用户指令（原文）：「你认为要完全达到设计稿需要做哪些？请出一个完整的方案，分步骤进行的方案」
> 用户 /goal 追加（原文）：「按照方案对应设计文件进行全部迁移，完善项目文档相关给规范以后新建页面、新建查询全部按照规范去做，避免不一致。除了 UI 还有 UX 必须要保持一致 品牌一致性」

## Problem

当前宿主（ForgeSelf.Web）与插件 UI 是 Element Plus 常规风格（实底 40px 顶栏、旧色板 token、无统一空态/反馈体系），与唯一真源高保真设计稿（东方器物美学：玻璃 48px TopBar、22px StatusBar、熔金/墨黑/宣纸 token、Plugin-First 首页 widget）**全面不一致**；且设计规范无登记、无守卫生效，新建页面/查询无强制依据，持续产生漂移。

## Why

1. 用户以高保真设计稿为**唯一真源**，要求视觉与交互完整对齐（品牌一致性）。
2. 无规范守卫 → 每次新建页面/查询都会重新漂移，返工成本持续累积（用户明确要求"以后新建页面、新建查询全部按照规范去做，避免不一致"）。
3. UI 对齐之外，UX（空态/反馈/边界/动效）与品牌（Logo/纹理/文案语汇）也必须一致，才能形成可辨识的产品形象。

## Expected Outcome

1. **全量迁移**：宿主壳层、主题 token、首页插件、23 个宿主视图、插件前端全部按设计稿/DESIGN.md 对齐；背景图本地化无 404。
2. **规范守卫生效**：DESIGN.md 登记进 `docs/README.md` §一与 AGENTS.md §8；新建页面/查询的规范（交互规格 + 视觉规格 + 品牌语汇）成文；`check-style-tokens.mjs`（或等效守卫）基线重建并接入门禁；e2e 视觉基线建立（每屏截图对照设计稿）。
3. **UI/UX/品牌一致**：视觉（token/玻璃/间距/圆角/字体）、交互（160/220/360ms 动效、空态/反馈/边界、锤落回弹）、品牌（Logo/纹理/「锻造师」语汇）三线统一，且后续新功能按规范自动继承。

## Constraints

- 硬性约束（AI-Native 规范 §1 逐条适用）：不碰生产实例、不改数据库结构、不改鉴权/权限/支付/安全核心、不新增大规模依赖、不做无关重构、不伪造验证。
- 开发流程：本方案为总规划（闸门1 输入）；**每个里程碑实施时各自走 AI-Native 闭环**（全量/轻量按改动面裁定），闸门1 逐个批准后 Implement。
- 插件任务硬门禁：凡改 `Plugins/<X>/web/` 或插件本体，须走 plugin-development 五步闭环（门禁→插件 e2e→发布→隔离走查→运行实例只读复验）；**禁止 agent 停/启/杀宿主进程**。
- 技术约束（设计稿 README）：生产用 Vue3+TS+Vite 转写；React 参考非生产；manifest 字段与 surface 类型按其规范。
- 中文 UI/文档：全部中文；图节点禁裸缩写（用户偏好）。

## Success Criteria（可验证判据）

1. **迁移**：`pnpm run check`（vue-tsc 0 error + eslint 0 error）+ `pnpm run test` 全绿；每屏 e2e 视觉用例通过与设计稿截图对照（截图落 `ForgeSelf.Web/screenshots/e2e/`）；首页/壳层/主题/功能屏各里程碑验收清单（02-spec AC）逐条 ✅。
2. **守卫**：`docs/README.md` §一出现 DESIGN.md 行；AGENTS.md §8 指向新真源；新建页面/查询规范章节存在并被后续 pilot 引用；`check-style-tokens.mjs` 基线重建后 0 新增漂移（跑通并记录数字）；CI/门禁中 token 守卫生效（违规提交被拦或至少门禁报红）。
3. **一致**：DESIGN.md 待对齐清单逐条勾销（熔炉 404 修复、workshop-forge.css token 迁移、基线重建）；三禁红线（玻璃过拟态/emoji/胶囊按钮/蓝紫渐变/可爱风）走查 0 命中；品牌资产（logo/纹理/语汇）在壳层与首页落地。
4. **流程**：每个里程碑有 00-07 工件（或轻量 mini-task+05/06），Evidence 全部 Verified（真跑命令，非推断）。
