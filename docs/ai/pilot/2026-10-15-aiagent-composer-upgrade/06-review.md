## 3. 决策记录

| # | 决策 | 理由 | 被否项 |
| --- | --- | --- | --- |
| D1 | 触发判定要求「行首或空白后」，规则放 `utils/trigger.js` 供单测 | 路径/邮箱/分数误弹是最扰人的一类 bug；规则与测试同源才不会长歪 | 只在组件里写正则 —— 无法单测，两处实现必然漂移 |
| D2 | 组件只做骨架，数据全由 `config.triggers` / `config.context` 注入，**默认 null = 完全关闭** | 组件要能独立交付；AIAgent 的工具/脚本/项目概念不能进 `agent-core` | 把数据源写进组件 —— 组件从此绑死一个宿主 |
| D3 | 候选缓存用 **WeakMap 以 def 对象为键** | 宿主换 def 对象（切项目）即让旧缓存失效；以 char 为键会永远命中旧文件列表 | Map + char 为键 —— 切项目后 `@` 还列着上个项目的文件 |
| D4 | 工具/技能/Agent/模型选中后**挂 chip 不插文本**（闸门1 P3） | 后端契约是 `selectedToolNames` 数组；插文本等于让模型把工具名当自然语言 | 插入 `/read_file` —— 与后端语义脱节 |
| D5 | 文件遍历 **BFS + 限深 4 + 排除噪声目录/扩展名 + 总量 1500** | DFS 会把名额耗在深层模板目录；日志与二进制永不该被引用 | 全量 DFS —— 大项目卡死，且候选被噪声占满 |
| D6 | 不恢复 5 个常驻 popover，收敛为行内触发 + chips | 中栏 inline 窄；5 个按钮 + 发送键挤一排；组件偏离源形态 | 原样照搬 —— 与行业形态和组件升级路径冲突 |
