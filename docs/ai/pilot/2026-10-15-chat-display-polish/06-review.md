## 3. 决策记录

| # | 决策 | 为什么这么定 | 替代方案为何不选 |
| --- | --- | --- | --- |
| D1 | 头像做成 `config.showBotAvatar`（默认 `true`），宿主置 `false` | 组件源 FR-205 明写「AI 带头像」；去头像属宿主风格裁剪，改默认值会让组件脱离自己的需求文档 | 直接在 `MessageItem.vue` 删掉头像块 —— 会让组件与 FR-205 永久冲突，且以后别的宿主无法恢复 |
| D2 | 状态条独立成 `.aiw-status` 块挂 footer 之外 | `readOnly`（无输入框）时也要能看到错误；且不随消息滚动 | 塞进 footer 内部 —— 被 `v-if="!config.readOnly"` 连带隐藏，只读场景丢提示 |
| D3 | 双分隔线用 `.aiw-status + .aiw-footer { border-top: 0 }` 消 | 纯 CSS，无 JS 状态；状态条在时视觉是一条线，不在时 footer 自己画 | 用 JS 给 footer 加动态类 —— 徒增状态 |
| D4 | 刻度容差常量化 `TICK_TOLERANCE = JUMP_OFFSET + 8` | 两个数必须保持大小关系，写成派生量就不怕以后只改一个 | 直接把 8 改 20 —— 下次有人调 `JUMP_OFFSET` 依然会破 |
| D5 | 跳转时先置亮目标索引，再靠 scroll 校准 | smooth 动画全程连发 scroll，不先置亮会「中途抢亮再闪回」 | 只等动画结束 —— 动画期间高亮乱跳，观感更差 |
| D6 | 折叠用 `max-height` + mask，不删 DOM | 复制 / Ctrl+F / 读屏都依赖全文；删 DOM 会把这些一起废掉 | 只渲染前 N 行 —— 检索与无障碍双输 |
| D7 | 折叠只对助手生效 | 用户自己敲的字折叠会让人误以为发出去了别的内容 | 一视同仁 —— 用户消息短，折叠纯负收益 |
| D8 | mask 用 `var(--aiw-text)` 而非 `#000` | mask 只读 alpha，颜色不可见；用 token 免得给 style-tokens 门禁平白加两处硬编码 | 写 `#000` —— 硬编码计数器上涨 |

## 4. 自查发现的偏差（已修）

| 偏差 | 现象 | 处理 |
| --- | --- | --- |
| 折叠未排除用户消息 | 注释写了「只折助手」，`measure()` 却对用户消息同样判定，超长用户输入会被折叠 | `measure()` 加 `isUser.value` 短路；补第 3 条单测锁死 |
| mask 用了 `#000` | design 门禁硬编码色值 1703→1705（PASS 但虚增） | 改用 `var(--aiw-text)`，回到 1704（+1 为 `transparent` 关键词，无色值含义） |
| 折叠气泡左上圆角 | 原 `border-top-left-radius: 5px` 是给「头像+气泡」配的，无头像时圆角会显得缺角 | `is-noavatar` 下补回 14px |
