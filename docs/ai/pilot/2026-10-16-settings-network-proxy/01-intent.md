## Problem

后端发出的模型请求（对话、流式、拉模型列表、密钥校验等）目前没有任何用户可控的代理入口：行为跟随系统代理，网络受限环境下（需要代理才能访问 OpenAI 等上游）用户只能改系统级代理或环境变量，影响全局且不可按应用控制；也没有地方能显式要求"不走代理直连"。

## Why

用户明确要求：「在设置里增加网络设置，按照行业通用做法，可设置代理，让后端所有发出去的模型请求都走代理或者不设置就不走代理」。行业通用做法（VS Code `http.proxy`、Chatbox、LobeChat、clash 类客户端）= 应用内独立的代理开关 + 服务器地址/端口 + 可选认证，关闭即直连。

## Expected Outcome

- 设置页新增「网络设置」分类与面板：代理开关、服务器地址、端口、用户名、密码（加密存储），保存即生效、重启后保持。
- 开关打开时：后端**所有发出去的模型请求**（见 00 盘点 M1~M6）经该代理出去；关闭（默认）时：直连，不受系统代理影响。
- 本机回环地址（127.0.0.1/localhost）请求永不走代理。

## Constraints

- 规范 §1 硬约束：不新增大规模依赖（.NET BCL `IWebProxy`/`SocketsHttpHandler` 原生支持 HTTP(S) 代理，SOCKS5 需第三方依赖 ⇒ 本批仅支持 HTTP/HTTPS 代理，SOCKS5 记 Unknown/TODO）。
- 不改数据库结构（配置走既有 `ForgeSetting.config` XML 机制，不落库）。
- 敏感值（代理密码）落盘须加密，复用既有 `ISecretEncryptionService`，GET 接口不回传明文。
- 不影响非模型请求出口（更新下载/webhook/MCP 等，本批不动，记 TODO）。
- 前端样式走 `--el-*` + Tailwind，按既有设置面板形态，不定义独立色值。

## Success Criteria

1. 后端单测：代理开/关/回环/非法值四种状态下，模型请求出口实际使用的 handler 的 Proxy 解析结果有断言证据（`dotnet test` 绿）。
2. 契约测试：`/api/settings` GET/POST 网络字段的读、写、校验（端口越界/开启无地址 400）、密码不回传，有测试覆盖。
3. e2e：设置页「网络设置」面板可进入、开关+表单可操作、保存后刷新仍在（真实前后端），截图读图通过。
4. 现场验证：dev-stack 起源码前后端，开启代理指向一个本地监听端口，观测模型请求经该端口转出（用探针 listener 证明），关闭后直连。
