# Intent

> 任务：2026-10-16-settings-proxy-mode-bypass ｜ 来源：用户输入7（2026-10-16）

## Problem

现行网络设置只有「手动代理 / 显式直连」二值，缺两个行业标配能力：
1. **跟随系统代理**——上一批把「关闭」定义为显式直连（屏蔽系统代理），依赖系统代理（含其旁路规则）的场景没有出口；
2. **旁路条目（不走代理的地址）**——内网域经代理 502/504、直连却正常的实测案例（gpustack via 10808）证明：内/外混合网络下「要么全走代理要么全直连」不可用；
3. **代理可用性无反馈**——保存后只能等模型请求失败才知道代理不通，排障靠猜（用户输入6 的整轮诊断皆源于此）。

## Why

- 用户在输入6 的诊断中确认了「502 来自代理本身」，现在的诉求闭环是：**配置 → 立即验证 → 不行就旁路**，三步都在界面内完成；
- 浏览器 / Docker / Clash Verge / VS Code 的代理设置均为「系统 / 手动 / 直连」三选 + 旁路列表，用户心智成本最低。

## Expected Outcome

1. 网络设置面板：代理模式三选一（跟随系统 / 手动配置 / 直连·不走代理），切换即时呈现对应表单/说明；
2. 手动配置时地址行后有「测试」按钮：点击实时经该代理发探测请求，成功/失败均有明确行内反馈（状态码 + 延迟 / 错误原文），探测目标地址可选填（默认公共探针）；
3. 可配置「不走代理的条目」：一行一条、可添加可删除，语义参考系统代理 ProxyOverride（域名后缀 / `*.` 通配 / IP / `10.*` 前缀），命中条目经代理模式请求时直连；
4. 保存即生效语义与密码安全语义（密文存储、不下发）不因本次变更退化。

## Constraints

- 不新增第三方依赖（BCL 能力内解决；跟随系统 = 委托 .NET 系统代理对象）；
- 沿用现有出口接线（M1~M6 一条 handler），不扩大到其他 HTTP 出口（衍生项③仍不做）；
- 配置仍走 `ForgeSetting.config` XML 落盘；密码仍只走 `ISecretEncryptionService` 密文；
- 上一批确立且不冲突的裁决保留：回环永不走代理；无效配置兜底直连 + Warn；行内错误常驻占位；仅 HTTP/HTTPS 代理类型；
- 不动 `ProxyEnabled` 之外的既有字段语义；测试端点不得把明文密码写日志/落盘。

## Success Criteria

- 三模式 × 旁路命中的转发决策有后端单测矩阵覆盖（Verified）；
- 「测试」按钮在真实 dev-stack 上点出 10808 代理的成败反馈（现场 Verified）；
- 旁路 `gpustack.luxvisions-inno.com` 后，代理开启状态下该域请求实际走直连（现场 Verified——用户输入6 场景端到端闭环）；
- 前端 check/test、后端 build/test、本面板 e2e 全绿；旧断言不留假绿。
