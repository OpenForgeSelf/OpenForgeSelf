# 任务意图

## 问题

TodoTracker 当前页面把阶段筛选、任务详情、下发配置、阶段变更和历史记录放在长表单中。用户需要处理的待验收与阻塞任务不突出，阶段操作也离任务标题较远。用户提供的 `待办.html` 原型将页面重新组织为任务控制台。

## 原因

用户通过此插件准备交给 Agent 的工作，并在之后验收执行结果。页面应清楚呈现下一项人工动作，让阶段流转一目了然，并方便访问工作单元、委派和执行记录。

## 预期结果

TodoTracker 提供原型中的列表/看板与阶段流水线交互，优先显示待验收和阻塞任务，在任务标题旁提供阶段操作，并将详情拆成三个页签。所有操作继续以现有 API 和后端状态机为准。

## 约束

- 复用 TodoTracker 现有 API 与数据模型；只为现有列表查询增加可选、向后兼容的优先级筛选参数；不迁移数据库、不增加依赖。
- 阶段图只以服务端 `TodoStage` 和响应中的 `allowedTargets` 为准。
- 保留只追加执行记录、旧完成/重开接口及供其他调用方使用的状态兼容。
- 采用宿主现有主题变量与无障碍约定，实现原型中的布局和交互意图。
- 实现期间不发布到运行实例、不操作用户正在运行的宿主；后续插件发布与运行实例走查遵循项目流程，并等待用户更新运行实例。

## 成功标准

1. 页面提供列表和看板视图、带数量的阶段流水线；数量反映当前非阶段筛选条件，看板各列独立分页。
2. 待验收和阻塞任务排在常规任务之前；完成和取消任务排在最后。
3. 详情页首屏显示任务标题、阶段进度和可用操作；提供「工作单元」「下发与委派」「执行记录」三个页签。
4. 每个阶段操作都依据 `allowedTargets`；转入阻塞必须填写原因；转为完成或取消须二次确认；完成操作在界面上只有一条阶段流转入口。
5. 执行记录表单的阶段选项显示中文，并仅列出当前任务可达的阶段。
6. 搜索、项目/优先级筛选、空态、快捷键、窄屏、加载和错误状态均可理解、可操作且反馈真实。
7. 在隔离环境中真实下发一条只读任务，由真实 Agent 完成并回写记录，再由人工验收到「完成」，以完整任务闭环作为最终验收。
