# 功能规格

> 任务：TodoTracker 交互调整

## 功能需求

- 将平铺阶段按钮改为带数量的阶段流水线。点击阶段可筛选任务；点击关注摘要可筛选待验收、阻塞或缺少下发必填项的任务。
- 通过现有列表接口的可选优先级参数增加 P1/P2/P3 筛选，使其适用于所有分页，并同步作用于列表、看板、流水线数量和关注摘要。
- 增加列表/看板切换。看板按后端的 8 个阶段分列；拖动任务时，只高亮该任务 `allowedTargets` 中的目标列，并通过现有分页接口按列继续加载。
- 优先显示需要人工处理的任务（待验收、阻塞），其次显示执行中的任务，最后显示完成/取消任务；相同紧急程度下继续按项目和优先级排序。
- 详情页顶部固定显示任务标题、阶段进度与可用操作。标题显示人可读的任务标题；`taskKey` 保留为次要且可复制的信息。
- 详情拆为「工作单元」「下发与委派」「执行记录」三个页签。保留现有字段、工件导入、提示词预览、执行引擎/Agent 选择、委派状态和只追加执行记录，并放入对应页签。
- 界面中只保留通过阶段流转完成任务的入口。其他调用方仍可继续使用旧接口；TodoTracker 不再同时显示第二个完成按钮。
- 执行记录中的阶段选项显示中文，并根据当前任务的 `allowedTargets` 生成；不再维护独立的阶段列表。
- 分别说明因字段缺失、阶段不符、委派能力不可用或已有委派任务运行而禁用下发的原因；保留现有 API 错误原文，禁止静默失败。
- 支持快捷键：`/` 聚焦搜索，`N` 新建任务，`Escape` 关闭详情；焦点在文本输入控件时不拦截快捷键。提供可用键盘操作的阶段流转方式，不能只依赖拖拽。
- 最终验收必须在隔离的源码预览环境中真实创建并下发一条只读任务，使用真实可用的 Agent 引擎执行，不使用 mock 或伪造状态；确认 Agent 实际完成并回写记录后，再由人工将任务从「待验收」流转到「完成」。

## 输入与输出

- 输入：现有待办 DTO 和分页列表响应；项目/状态/关键词筛选以及新增的可选优先级查询；服务端返回的 `allowedTargets` 与 `missing`。
- 输出：只调用现有的新建、更新、阶段流转、委派和执行记录接口。看板拖放与详情操作使用同一个阶段流转请求。

## 业务规则

- 阶段图只由 `Plugins/TodoTracker/Services/TodoStage.cs` 定义；界面操作严格使用每个 DTO 的 `allowedTargets`。
- 转入阻塞时必须填写原因。转为完成或取消时必须二次确认。完成与取消只能通过服务端返回的合法目标重开。
- 看板每列使用阶段筛选分页，每次最多加载 100 条（后端上限）；有更多任务时，该列显示自己的「加载更多」操作。
- 在当前项目/状态/关键词/优先级筛选下，阶段数量采用服务端 `total`。缺少必填项的摘要必须基于全部匹配 DTO 的 `missing` 计算，不能只统计当前已加载页。
- 执行记录保持只追加，不可编辑或删除。
- 保持旧的 `Status`、完成/重开路由、Home 插件消费和已有数据不变。

## 边界情况与错误处理

- 没有任务时说明如何新建；筛选无结果时说明如何清除筛选。
- 看板空列明确显示空态。各列加载和错误状态独立；刷新失败时保留已加载任务。
- 不显示非法阶段目标。如果并发更新导致服务端拒绝流转，显示服务端原因并重新读取任务。
- 取消拖动或拖到不可用列时不发送请求。键盘及详情操作仍可完成阶段流转。
- 长标题、长项目路径、窄屏、无可用 Agent 和字段未齐时，内容不得溢出或遮住下一项操作。
- 计划驱动 Agent 若回合结束时未调用出口工具，必须保持卡住并保留现场；不把纯文本误认作任务完成。
- 计划器或步骤执行器已挂载出口工具时，请求必须要求模型返回工具调用；不支持工具调用的提供方应如实失败/挂起，不伪造完成。

## 兼容性与非功能要求

- 不改数据库结构、不增加依赖。优先级筛选参数为新增可选项；旧调用方及响应形状不变。
- 保留鉴权 API 调用、插件远程入口/导出名、宿主主题变量，以及响应式和无障碍约定。
- 桌面 HTML 中模拟的阶段映射与示例任务状态不能作为产品状态机依据。

## 交互设计

| 交互点 | 操作触发 | 操作结果 | 状态 | 反馈 | 空态 | 边界 |
| --- | --- | --- | --- | --- | --- | --- |
| 阶段流水线 | 点击阶段或「全部」 | 筛选列表/看板 | 阶段选中/未选中 | 显示选中态与结果数 | 数量为零时仍显示该阶段 | 保留其他筛选条件 |
| 关注摘要 | 点击待验收、阻塞或缺项摘要 | 应用对应的关注筛选 | 已应用/已清除 | 摘要与结果数量更新 | 数量为零时不显示摘要 | 缺项数须基于全部匹配数据 |
| 视图切换 | 点击「列表/看板」 | 显示分页列表或阶段分列 | 列表/看板 | 控件显示当前视图 | 均提供新建任务引导 | 看板各列独立分页 |
| 看板流转 | 将任务拖至高亮的合法列 | 提交流转并更新卡片与数量 | 拖动/合法/非法/提交中/失败 | 高亮合法目标；成功提示；错误显示原文 | 空列只接受合法放置 | 阻塞要求原因；完成/取消二次确认；支持键盘操作 |
| 详情页头部 | 选择任务 | 无需滚动即可查看标题、阶段、进度和合法操作 | 已选/加载中/错误 | 显示阶段操作结果与保存状态 | 未选择时显示提示 | taskKey 仅作次要信息 |
| 详情页签 | 点击三个页签之一 | 显示对应内容 | 当前页签 | 页签显示选中态与数量标记 | 按页签显示相应引导 | 保留既有字段行为与滚动位置 |
| 阶段操作 | 点击合法阶段操作 | 调用现有阶段接口 | 目标来自 `allowedTargets` | 加载中、成功或显示服务端原因 | 无合法目标时说明原因 | 阻塞须填原因；完成/取消须确认 |
| 执行记录阶段 | 打开追加表单并选择阶段 | 显示中文合法目标并提交记录 | 收起/展开/提交中 | 显示成功或失败提示 | 无记录时提供引导 | 历史记录不可更改 |
| 下发 | 选择引擎/Agent 并委派 | 仅在后端预检允许时下发 | 不可用/可下发/执行中/终态 | 显示具体原因 | 无 Agent 时引导登记 | 不显示误导性通用提示 |
| 真实任务闭环 | 创建只读任务并委派，等待真实 Agent 执行，再人工验收 | 任务从草稿/就绪，经已下发/执行中/待验收，最终到完成 | 各阶段均由真实服务端状态支撑 | 核对 Agent 真实状态、结果回写、记录和最终阶段 | 无真实 Agent 可用时验收阻塞，不用模拟结果代替 | 只读权限、无副作用任务；只清理本次测试任务 |
| 搜索与快捷键 | 输入搜索；按 `/`、`N` 或 `Escape` | 搜索、新建或关闭详情 | 空闲/加载中/已筛选 | 显示结果数量 | 提供清除筛选操作 | 输入控件聚焦时不拦截快捷键 |

### 验收标准

- AC1：点击各阶段流水线后只显示该阶段任务；该阶段数量等于服务端在其他筛选条件下返回的总数。
- AC1a：P1/P2/P3 筛选作用于完整匹配结果，包含看板列和流水线数量，而非只作用于已加载页。
- AC2：关注摘要数量覆盖全部匹配分页；点击摘要后显示对应任务集合。
- AC3：看板初始加载每阶段第一页，可独立继续加载；任何卡片均不提供非法流转目标。
- AC4：待验收和阻塞任务优先于常规进行中任务；完成和取消任务排最后。
- AC5：详情标题显示任务名称；三个页签分别可访问现有工作单元、委派和执行记录操作。
- AC6：阶段按钮和看板拖放均使用 `allowedTargets`；阻塞原因校验、完成/取消确认正常；非法或并发冲突时显示服务端原因且不伪报成功。
- AC7：TodoTracker 界面只有一个完成路径（阶段流转）；旧 API 契约及调用方测试继续通过。
- AC8：执行记录阶段下拉只显示当前任务的合法目标，且使用中文标签。
- AC9：下发禁用提示与真实的字段缺失、阶段、能力或委派状态原因一致。
- AC10：快捷键生效且不拦截输入；所有操作均有键盘可用方式。
- AC11：空态、加载态、错误态、窄屏、长标题和长路径均可阅读并可采取下一步操作。
- AC12：`pnpm run build`、相关后端测试、唯一一条 TodoTracker 冒烟 e2e 和源码宿主走查全部通过，并完成截图检查。
- AC13：在隔离源码预览环境中真实创建一条只读任务，使用真实 Agent 引擎下发并观察到执行中状态；Agent 实际成功后，核对服务端委派状态、自动进入「待验收」、执行结果和只追加记录均已持久化；人工查看结果后按合法目标流转到「完成」，刷新后再次核对任务终态与完整历史。不得 mock Agent、伪造状态或把「已入队」回执当作完成；无法调用真实 Agent 时此项记为阻塞，不得判通过。
- AC14：计划驱动回合挂载 `submit_plan`、`complete_step` 或 `request_help` 出口工具时，发送给 OpenAI 兼容提供方的请求包含 `tool_choice: required`；未挂出口工具的普通 Agent 回合不强制工具选择。纯文本结束不得被误判成功。
