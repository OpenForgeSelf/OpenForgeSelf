## 八问

1. **需求原文要求什么？** 复现 write_file schema 问题 → 补测试 → 修复 → 本地 zip 发布 → 浏览器代点升级 ：51888 → fs 复测。goal 原文即闸门1。
2. **交付了什么？** 修复①（删 schema 重复键）+ 修复②（补 `File.WriteAllText`，复测中发现的第二缺陷）+ G2 守卫×2（`ToolSchemaJsonGuardTests` 3 用例、`FileToolsWritePersistTests` 4 用例）+ plugin.json 1.2.2 + 本地包 2.4.20/2.4.21 两轮（-Sign）+ 浏览器两轮升级到 2.4.21.2610301259 + fs 终验全绿 + PC-017/PC-018 双归档。
3. **验证了什么、怎么验的？** 见 05 矩阵 17 项，全部实跑：红→绿两轮（守卫各自先红后绿，红探针用 stash 对照法）、包 SHA256/签名/包内插件版本三核、升级后版本徽标 + 进程路径核验、fs 端到端含**磁盘独立复核**（不信工具响应体）。
4. **什么没验？为什么可以？** 中档/深档门禁（未触宿主源码与 e2e 基建，§5.6 触发表不要求）；前端三件套（零前端变更面）；file-tools 取消流 e2e 既有红（异根因，已定责记 TODO）。
5. **改变了哪些行为？** write_file 从「网关必挂」→「可用但假成功」→「真落盘」；read_file/list_files/run_terminal_command/list_files 行为零变更（回归绿）；升级链 2.4.19→2.4.21 走的是宿主自更新正常路径。
6. **风险？** ①2.4.20 包只活了约 20 分钟就被 2.4.21 替换（其间实例上的 write_file 假成功——本会话自用，无用户数据经此写入）；②file-tools 其余副作用工具可能有同形态静默缺陷（TODO 扩面）；③守卫盲区：拼接型 schema（DesignSystem）仍只能靠实例级扩展。
7. **如果回滚？** 版本目录回滚到 2.4.19/2.4.20 由宿主 versions 机制天然支持；代码回滚 = revert 两个文件的对应 hunk（守卫测试会转红提示，正是其用途）。
8. **学到了什么？** ①「修好报错」≠「功能恢复」——修复报错类缺陷后必须跑成功路径端到端复验（已入 PC-018 lens）；②上游响亮故障会遮蔽深层静默故障，解蔽后第一件事就是端到端复测；③响应体不是副作用的证据，回读才是。
