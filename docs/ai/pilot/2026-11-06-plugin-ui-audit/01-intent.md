# Intent

> 阶段：Stage 1｜Task ID：PILOT-plugin-ui-audit｜只出工件，不执行修复。

## Problem

DbAdmin 暗色连接名不可见（1.10:1）暴露的是一类问题：**插件 UI 的颜色配对与状态反馈没有被逐插件核对过**，门禁只覆盖文本模式（裸色值/token 族），不覆盖「配对后的可读性」与「异步加载反馈」。已知覆盖缺口：

- CostScope 有前端但**无 e2e**；
- 12 个带前端插件**无 CT 组件状态基线**；
- 9 个插件仍有两位数以上硬编码色值（AIAgent 397 / Sems 178 / DesignSystem 108 / AgentHub 104 / Home 61 / ImGateway 46 / CostScope 31 / FileTools 14 / McpCenter 13）；
- 渲染态对比度断言目前只有 DbAdmin 一条。

## Why

用户要求「逐个插件核对排查修复」，并先只出工件。目的是把「下一次不会再发生」从「靠人记得」变成「每插件有清单、有基线、有断言」。

## Expected Outcome

- 一份逐插件核对表（14 行 × 固定检查项），每项给出「已核 / 未核 / 风险等级 / 计划动作」。
- 明确的批次顺序与每批的验证命令，后续执行时可直接照做。
- 不虚构任何未实际检查的结论（未读 = 未核）。

## Constraints

- 本批**不改任何代码**（只落工件）。
- 不得以「看起来正常」代替实测；未核项必须标 Unknown。
- 不以重写样式为目标，优先「改 token 引用 / 补状态 / 补断言」。
- 基线棘轮只降不升。

## Success Criteria

| 判据 | 目标 |
|---|---|
| 覆盖度 | 14 个带前端插件全部出现在核对表，无遗漏 |
| 可执行性 | 每条修复项都带「改哪个文件 / 怎么验证 / 判定标准」 |
| 诚实性 | 未实际读过的项标 `Unknown(未核)`，不填推测结论 |
| 批次 | 至少分出 P1（可读性/无 e2e）与 P2（状态/基线）两批 |
