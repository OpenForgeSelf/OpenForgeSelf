# Intent

> Task ID：2026-11-14-commit-hygiene-gate ｜ 日期：2026-11-14

## Problem

用户 2026-11-14 输入1（08:59）问「本项目提交，是否要求一个固定流程，进行审计？」并指令「增加一条，所提交文档、代码和注释，不得硬编码工作区绝对地址，工作区外地址……也不要出现任何人名、角色名、成员名等信息、以及与本项目无关的其他项目信息、其他项目业务信息」。

现状（00 已实测）：pre-commit 已有三道固定门（设计守卫 / 问题类台账 / PILOT 工件链），但**提交内容卫生没有任何机械门禁与规则条文**；存量中已有工作区外绝对地址（AGENTS.md、DESIGN.md 等）与群内称呼（AGENTS.md:326 对话方名录等）入库。

## Why

- 工作区绝对地址（盘符路径、POSIX 用户目录、UNC、file URL）换环境即失效，文档与代码的可移植性被破坏（用户原话：「换个环境文件就不存在了」）。
- 人名/角色名/成员名与无关项目信息入仓 = 隐私与边界泄露，且 git 历史不可轻易抹除——必须在提交口拦新增。
- 「是否要求固定流程审计」的回答依赖机械门禁存在：没有第 4 道门，答案只能是「部分」；落门后回答变成「是，四道」。

## Expected Outcome

1. 提交前自动审计第 4 道门上线：暂存区新增行命中卫生红线即拒绝提交（FAIL 聚合进现有 pre-commit）。
2. 规则条文入库：项目不变工程规则真源（b-engineering-daily）新增一节；AGENTS.md 登记；技能沉淀并可复用。
3. 本地拒绝列表（不入库）承接「具体称呼/账号」类规则，格式与豁免策略明确。
4. 存量盘点口径建立（-All 模式），本批规范文件就地清零，其余存量列清理批次决策（not-taken 记录）。
5. Part 1 问题答复已给出（3 道既有门 + 本批第 4 道，带 file:line 证据）。

## Constraints

- 规范 §1 硬约束对照：不动 L4（工件链校验脚本）；不碰运行实例与发布链；宿主源码/前端源码不触（中档全量测试兜底）。
- 脚本一律 pwsh 7；含中文的 .ps1 必须 UTF-8 BOM（RepositoryScriptTests 红灯约束）。
- **自洽红线**：本批新增入库内容不得自身包含任何违规样本字符串（用运行期拼接、规则描述替代）。
- 拒绝列表必须不入库（放 .forgeself/），并文档化「新 clone 无此文件」的局限。
- git 提交/推送须用户同意（§8.5）：本批完成所有工作后停在提交前，向用户提供提交确认话术。
