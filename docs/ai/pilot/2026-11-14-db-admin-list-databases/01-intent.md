# Intent

> 闸门1：2026-11-14 用户原文「P1 一并做，当前没开工吧，开工作树去做」。批准树形列库，并把 `docs/02-features/044-db-admin.md` §8.2 十条纳入本批。实现只在分支 `feat/db-admin-list-databases` 的工作树，不改主工作区业务代码。

## Problem

用户要新建数据库连接时可以不填数据库名，点开左侧连接后先看到这台服务器上自己有权访问的全部数据库，再点进某一个库看表。

现在页面做不到：非 SQLite 的表单一律要求「请填写数据库名」，点连接只列出该连接已保存的那一个库里的表。后端从 2026-11-07 起已经允许 mysql / sqlserver / postgresql 不填库名，并提供列库接口，页面没接。

## Why

不填库名再浏览，是 Navicat、SSMS、pgAdmin、MySQL Workbench 的共同做法。自己另做一套「必须先填一个库」或「下拉里切库」会和用户要的列表不一致。后端协议已经有了，缺的是页面。

## Expected Outcome

- mysql / sqlserver / postgresql：表单库名可留空并保存、可测试连接。留空的 PostgreSQL 仍由后端用维护库 `postgres` 连入（已有行为，页面说明写明）。
- 点这类用户连接：先列出全部可见数据库（系统库靠后并标「系统」，连接上填过的默认库标「默认」）。点其中一个库，才列出该库的表，查询落在该库。
- SQLite、系统只读连接：保持现在的「点连接直接列表」。Oracle：服务名仍必填，点连接仍直接列表；不把 schema 伪装成可切换的库。
- 同批做完 044 §8.2 十条：标签快捷键、列宽拖拽、单元格/列名复制、分页键盘、表树右键、连接名过滤、查询标签重命名、0 行空态与加载骨架、导出全部页 CSV、导出当前页 JSON 与 INSERT。§8.3 与决策 056 仍不做。

## Constraints

- 不改枚举 SQL、不改切库连接串规则、不加驱动、不改权限模型。
- 不新增依赖。不碰 `:51888` 宿主进程。
- 系统库只作标记，不隐藏、不禁止点开（与 `IsSystemDatabase` 注释一致）。
- 账号只能看到有权限的库；列表缺库是服务器权限，不是页面过滤。
- PostgreSQL 在协议上必须先连入一个库；留空时的维护库是后端已写死的 `postgres`，本批不改这个回落。

## Success Criteria

1. 插件前端单测：mysql/sqlserver/postgresql 空库名 `validateForm` 返回 null；sqlite 空路径、oracle 空服务名仍被拒。
2. CT 或组件测试：点一个 mysql 连接出现库节点（含「系统」「默认」标记），点库名后才出现该库的表；加载完成前不出现「无库」。
3. 保存空库名的请求体不含非空 `database`，且前端会调用 `GET .../databases`。
4. 查询请求在选中库之后带上 `database` 字段。
5. 插件 `pnpm run test` 与 `pnpm run build` 通过。既有「点连接加载表」的 SQLite/系统连接路径仍然成立。
6. §8.2 十条各有一条可单测或 CT 断言（快捷键、导出文本、重命名、空态文案不依赖真实服务器）。
