## 需求演进时间线（按时间顺序）

| 序 | 需求要点 | 对意图的约束 |
| --- | --- | --- |
| 1 | 按静态 HTML 项目管理原型重构 `Plugins/Sems`，**保留原本 sems 功能** | 原型是设计基座；sems 原有能力不可丢 |
| 2 | 不是简单换界面，而是做「全站项目管理平台」——.NET 后端 + Vue 前端，以静态 HTML 原型为设计基座，与 sems 原有能力融合；后续要扩展需求管理 / 开发规范 / 派发任务 / 门禁 / 宪法管理等（**仅设计预留，本期不实现**）；项目首页支持**列表/卡片双模式切换** | 平台化愿景；扩展项**只预留不实现**；双模式是硬需求 |
| 3 | 纠偏：不需要模块设计 / 模块注册 / 插槽契约；加功能**直接改**；新模块状态**直接在首页改展示**；把 HTML 原型功能加到 sems，重复功能**以 HTML 为准**；点名缺陷：命令交互差、实际使用不返回实时日志、运行中命令运行记录突然不见；后续加模块只是「设计上预留」 | 严禁过度设计；重复功能以 HTML 呈现为准；3 个交互缺陷须修；扩展项仍只预留 |
| 4 | v0.3 三条硬性要求：① 项目管理功能对齐 HTML 原型，**最终功能大于 HTML**；② **不要设计过于复杂，能实现功能即可**；③ 撤掉之前的定时任务、不需要专家、更新项目计划即可。补充「后台服务日志运行台没问题，不用担心，还有没做的功能可先不实现」 | 功能 ≥ HTML；最小复杂度；删定时任务/专家；未做功能可不做；日志运行台无需重做 |
| 5 | 在本工区完成 sems 插件重构开发，走项目内流程规范 | 走九阶段闭环 + 00–07 工件（→ 闸门裁剪依据，见 04-task） |

> **口径合成（本任务遵循）**：演进序 1–5 为最高优先级的产品意图；4 份评审基线为实现约束。「以 HTML 为准 / 最终功能大于 HTML」指**信息架构、11 屏呈现、列表/卡片双模式、双入口切换**等 UI/UX 与功能覆盖面，**不等于**复制 HTML 中无后端支撑的假能力（4 份评审一致判定须删）。二者冲突时以「保留 sems 真实能力 + 不做假能力 + 最小复杂度 + 评审 D1–D5」裁定，冲突登记见本文末「已识别口径冲突」。

## Problem

1. **交付与流程双重缺口**：设计研发评审判定「有条件不通过」，P1（重构代码未入库 + 缺 `docs/ai/pilot/` 00–07 工件）、RK-01/RK-04 直指本次重构未纳入项目唯一开发流程；合入功能扩展代码后 `pnpm run design:check` 已 FAIL（`Plugins/Sems/web/src` 的 `a` 从基线 0 涨到 46），pre-commit 会拦提交。
2. **产品语义失真**：4 份评审一致指出「假能力 UI」——4 步向导承诺 Git 初始化/包管理器/预设/功能但只写 localStorage；S07/S08 有「安装依赖/添加插件/安装开发工具/下载」死按钮；S09 配置屏是空壳；S06 仪表盘含「端口占用 8080 / 结束占用进程」伪概念；紫色 DEMO 徽标与薄荷绿主题违反项目主题与守卫规则。
3. **历史交互缺陷**：v0.2 已点名命令交互差、实际使用不返回实时日志、运行中命令运行记录突然不见。
4. **自动化资产失配**：宿主 e2e `sems.spec.ts` 断言经典视图 DOM 与工具数 13（后端实为 22），交付说明端点数 21（实测 25），三处版本号历史欠账（现已同步 1.3.0）。
5. **视觉退化**：评审实测上一版自引入 B1（状态栏墨黑底墨黑字隐形）、B2（`--sp-*` 间距塌陷）两个 bug；原型 54 个自定义 token 属「从合规退回不合规」（Sems 基线 `a:0`）。

## Why

- 本项目是 AI-agent-first 自迭代工具系统，插件是主要交付物；`AGENTS.md` §11 规定所有开发类任务必须走九阶段闭环并产出 00–07 工件，缺件视为未完成（红线）。
- 本任务已获开工授权并按项目内流程规范推进；`AGENTS.md` §8.5 规定规范覆盖内的迭代由 agent 自主推进、如无必要无需用户决策。
- 4 份评审基线已把 D1–D5、P1–P6、G1–G9、T 任务卡、RK 风险逐条锁定，若不在 Spec/Plan 阶段一次收敛，开发会照着离线预览把假按钮实现出来，返工成本更高。
- 主题口径是机器门禁（`design:check` 棘轮 + pre-commit），不是偏好：Sems 目录当前 `a:0`，照搬原型薄荷绿会直接 FAIL。

## Expected Outcome

- `Plugins/Sems` 在完整仓库内完成 1.3.0 重构：**11 屏信息架构对齐原型且功能 ≥ HTML**，同时完整保留 sems 原有 22 工具 / 25 端点 / 经典视图 / 规格能力；列表/卡片双模式可切；经典视图在**顶栏 + 侧栏双入口**一键切回且不丢状态。
- 原型假能力全部清除：向导砍成 2 步「登记」向导（按钮「登记项目」、明示不创建文件），S07/S08 改名并加语义说明条、删死按钮，S09 改「项目设置」，S06 换 Sems 真实信号；不做假能力。
- 主题走 `workshop-forge.css`：零自定义 token、明暗自动跟随、圆角 `--radius-md` 禁胶囊、强调色 `--el-color-primary`、破坏性操作 `--cinnabar-400`；`design:check` PASS 且 Sems 目录 `a` 保持 **0**（禁 `--update` 抹平）。
- 3 个交互缺陷修复（命令交互 / 实时日志增量轮询 / 运行中记录不消失）；明暗双模 11 屏截图与 4 态齐全。
