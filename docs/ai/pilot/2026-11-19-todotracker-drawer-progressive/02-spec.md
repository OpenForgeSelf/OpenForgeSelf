# Spec

> Task ID：`2026-11-19-todotracker-drawer-progressive`｜日期：2026-11-19

## Functional Requirements

- **FR-1 轻量创建**：新建入口仅强制标题（可选项目）；创建成功后不自动把用户推进「必须填四栏」的错误态。  
- **FR-2 校验时机**：`objective/content/acceptance/verification` 仅在「下发」「一键委派」「生成提示词后尝试下发」等关键动作前硬校验；缺项点名反馈并阻断该动作。  
- **FR-3 抽屉壳**：选中任务 → 右侧抽屉（覆盖层）打开详情/编辑；主列表/看板保持全宽，不被分栏挤压。  
- **FR-4 详情=编辑**：同一抽屉内查看与编辑（失焦保存策略不变）；无独立「只读页 vs 编辑页」双壳。  
- **FR-5 渐进披露**：抽屉首屏（折叠前）只展示摘要条 + 分类折叠头；字段按门类展开，默认不全开。  
- **FR-6 软提示**：列表/看板缺四栏时用中性「下发前待补齐」提示，不用危险色「还缺」冒充创建失败。

## Input / Output

- 输入：现有 Todo DTO（含 `missing`/`allowedTargets`）、现有 create/update/dispatch/delegate API。  
- 输出：同一套写接口；UI 壳与文案变化；不新增必填服务端字段。

## Business Rules

- BR-1：创建校验 = 仅非空 `title`（既有）。  
- BR-2：下发/委派校验 = `DispatchPayloadBuilder.Missing` 四栏（既有）；项目缺失保持 warning，不阻断。  
- BR-3：Escape / 关闭按钮 / 点遮罩关闭抽屉；关闭后列表无选中高亮或保留选中但不占宽（推荐：保留 `selectedId` 高亮，但不占分栏）。  
- BR-4：抽屉默认展开分类「概要」；「工作单元（下发必填）」在缺项或用户点「去补齐」时自动展开。  
- BR-5：快捷键：`/` 搜索、`N` 新建、`Escape` 关抽屉（输入框聚焦时不拦截）——延续既有约定。

## Boundary / Error

- 窄屏：抽屉 `size` 近全宽（≥90% 或 100%），列表仍在底层可滚动。  
- 下发缺项：按钮可点 → toast/横幅点名缺项（或 disabled + 同文案）；禁止无反馈。  
- 并发保存失败：保留既有错误原文提示。  
- 无任务选中：不渲染抽屉。

## Compatibility / NFR

- 不改 DB、不改鉴权、不大依赖升级。  
- 主题继续 `--el-*`；`pnpm run design:check` 不新增违规。  
- e2e 选择器：详情容器从 `.tt-detail-panel` 迁到抽屉根（须同步冒烟用例）。

## Failure Modes

- 无已知 PC 同根因；相邻 PC-012：抽屉必须挂到 body，避免插件根 overflow 裁切。

## Interaction Design

### 信息架构（抽屉内分类）

| 序 | 分类 | 默认 | 首屏是否露出折叠头 |
| --- | --- | --- | --- |
| 0 | **概要条**（标题可编、阶段徽标、优先级、软提示条、主操作：关闭/阶段快捷） | 恒显 | 是（非折叠） |
| 1 | 基本信息（备注、下发对象文案） | 收起 | 是 |
| 2 | 项目关联 | 收起（无项目时折叠头带「建议关联」角标） | 是 |
| 3 | 工作单元 · 下发必填（目标/正文/验收/验证） | 缺项时展开，齐备时收起 | 是 |
| 4 | 范围与权限（允许/禁止范围、permissionMode） | 收起 | 是 |
| 5 | 下发与委派（工件导入、提示词、下发/委派、状态） | 收起 | 是 |
| 6 | 执行记录 | 收起 | 是 |

「分页前展示」落地口径：列表分页控件之上仍是完整任务列表；**抽屉内**则是「概要条在滚动区之上固定，分类折叠头在进入长表单之前可见」——用户不必先滚过整页字段才找到门类。

### 点什么出现什么

| 触发 | 结果 | 状态 | 反馈 | 空态 | 边界 |
| --- | --- | --- | --- | --- | --- |
| 标题框回车/点新建 | 创建任务，可选中并开抽屉 | Draft | toast「已创建」；四栏空不报错 | 标题空则按钮 disabled | 仅 title 必填 |
| 点列表/看板卡 | 开右侧抽屉，列表宽度不变 | 抽屉 open | 行高亮 | — | 再点同行可关或保持 |
| 展开「工作单元」 | 显示四栏；失焦保存 | 展开 | dirty 提示 | 空 placeholder 引导「下发前再填」 | 不在创建时标红 |
| 点下发/委派且缺项 | 不发请求 | blocked | 「下发前还缺：验收判据、…」 | — | 自动展开工作单元分类 |
| 点下发且齐备 | 调既有 dispatch | 进行中 | 成功/服务端原文 | — | 与现逻辑一致 |
| Escape / × / 遮罩 | 关抽屉 | closed | — | — | 输入中不抢 Escape |
| 点「去补齐」软链 | 开抽屉并展开工作单元 | open+expand | 滚动到该分类 | — | 列表软提示可点 |

### 五态

- 加载：抽屉内骨架或沿用 operating 遮罩。  
- 空：未选中不显示抽屉；分类内空字段用引导文案非错误色。  
- 出错：保存/下发失败显示原文。  
- 无权限：401 既有横幅。  
- 正常：如上表。

### 验收标准（交互）

- AC-UI-1：创建仅标题；创建后列表无危险色「还缺」冒充失败（允许中性「下发前待补齐」）。  
- AC-UI-2：打开详情时列表/看板主区宽度与未打开时一致（无右侧分栏）。  
- AC-UI-3：详情与编辑同一抽屉；字段失焦仍可保存。  
- AC-UI-4：抽屉首屏可见概要 + 全部分类折叠头，无需先滚过长表单。  
- AC-UI-5：下发缺项时点名反馈且展开工作单元分类。  
- AC-UI-6：原型截图与最终实现在布局结构上一致（抽屉 + 分类），视觉走宿主 token。
