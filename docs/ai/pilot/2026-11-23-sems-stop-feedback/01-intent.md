# Intent

> Task ID：PILOT-087｜来源：用户输入1（2026-11-23）原文「sems的运行功能，点击停止，没法停止，进程早就停止了的，点击停止没反应，页面没提示。在对应需求增加改验收标准，并增加测试复现。完善该功能，要求点击停止命令，无论什么结果都要有反馈」

## Problem

sems 运行页点击「停止」时，若目标进程早已停止（自行退出、会话已消失、宿主/插件重启过），页面没有任何反馈：后端把「已不存在」折叠成 404 失败，前端要么无声禁用、要么反复报失败且任务状态永远卡在「运行中」；日志轮询对 404 无限吞错。用户无法分辨「停掉了/本来就没在跑/停失败」，也无法让界面回到一致状态。

## Why

「停止」是一个改变用户可见状态的操作，它的每一种可观察结果都必须有可见反馈——这是本项目 confirmOps 层已确立的「操作成败可见」约定的缺口面。同时该面命中 PC-024 lens（轮询终态不收敛），按 problem-class-closure 属同根因批量收口，不修会再次以「又卡住了」回流。

## Expected Outcome

1. 点击停止（详情区任务停止、会话面板停止、外部进程停止）后**无论结果如何都有可见反馈**：已停止 / 已不在运行（明确说「无需停止」并收敛状态）/ 停止失败（含原因、保留重试）。
2. 「已不在运行」不算失败：状态收敛为已结束、按钮回到不可用态、列表与运行计数刷新，不再反复报错。
3. 验收标准写入 `Plugins/Sems/docs/01-requirements.md` F09；测试计划同步。
4. 红灯复现 + 类级守卫测试落地（后端 xUnit + 插件前端 vitest），PC-024 增记复发。

## Constraints

- 对外 22 个 `sems_*` 工具的名称、权限、既有语义不改（F25）：工具对「无存活会话」仍返回既有 Fail 文案。
- 不触宿主内核、不触鉴权、无 DB 迁移、不新增依赖；不改 e2e 主链路结构（保持每插件 1 冒烟口径）。
- 不发布（发布须用户同意）；不触碰用户 :51888 运行实例。

## Success Criteria

- 需求文档 F09 含可测的停止反馈验收标准（AC-F09-1…7）。
- 后端停止接口可区分三种 outcome（stopped / already-stopped / failed），有 xUnit 证据。
- 前端三条停止路径对三种 outcome 均有可见反馈且状态收敛，有 vitest 证据（先红后绿）。
- 门禁：快档全绿（dotnet build+过滤测试 / pnpm check+test+design:check）+ sems 冒烟 e2e。
