# 待办任务（Todo Tracker）当前功能设计

> 版本基线：宿主 2.3.4 ｜ 插件 v1.1.2 ｜ 2026-10-09（含 2026-10-08 PILOT-056/057A/057B 全部增强）
> 数据真源：`docs/02-features/005-todo-tracker.md`；界面现状以运行实例 :51888 实测为准

## 1. 功能定位

一条待办 = **一个 agent 可直接开工的工作单元**，是「人与 agent 之间的工作交接面」：

- 任务带完整开工要件：目标 / 正文 / 允许·禁止范围 / 验收判据 / 验证命令 / 优先级 / 下发对象 / 阶段
- 任务关联项目（路径任意写法归一为同一项目），正文可从项目工件目录一键组装
- agent 干完回写执行记录（动作 / 结果 / 改文件 / 验证 / 风险 / 遗留 / 证据 / 状态流转）
- 一键交给 AgentHub 执行，状态与结果回流到任务时间线

## 2. 数据模型

| 对象 | 说明 |
|------|------|
| `Todo` | 任务主表：18 个扩展列（TaskKey / ProjectId / ProjectRoot / Objective / Content / AllowedScope / ForbiddenScope / Acceptance / Verification / Priority / Assignee / Stage / ArtifactRef / AgentTaskKey / AgentId / PermissionMode 等） |
| `TaskExecution` | 执行记录表（1:N，append-only）：TodoId / Seq / Actor / Action / Detail / Result / FilesChanged / Verification / Risks / Residuals / Evidence / StageFrom / StageTo / ElapsedMs / BlockReason / NextStep / CreatedAt |

落库位置：插件库 `{数据根}/Plugins/todo-tracker/TodoTracker.db`（跨版本持久，随宿主升级不丢）。

## 3. 阶段状态机（Stage）

```
0 Draft → 1 Ready → 2 Dispatched → 3 Running → 5 Review → 6 Done
                       ↕                 ↕           ↓（打回 3）
                     4 Blocked ←────────┘      Done/Cancelled 可重开 → 3/5
   任一非终态 → 7 Cancelled；同态幂等放行
```

- 非法流转 → **409 + 列出可达目标**；进 Blocked 必填 blockReason
- 界面只按出参 `allowedTargets` 渲染按钮，前端不抄第二份流转表

## 4. 界面设计（057A：两栏 + 三卡片）

### 4.1 布局

- **宽屏（≥900px）两栏主区**：左列表固定 400px（任务行），右详情 flex 撑满（≥2/3 宽），替换旧 520px 固定侧栏
- **窄屏（<900px）堆叠**：列表全宽 + 详情整宽排在下方（不破版、不挤压）
- 顶部筛选条：状态标签（全部/草稿/就绪/已下发/执行中/阻塞/待验收/完成/已取消）、项目下拉、完成态过滤、搜索框、新建输入条

### 4.2 列表行

一行含：阶段徽标 + 优先级 P1-P3 + 标题（超长省略 `…` + title）+ 项目名 + **委派徽标**（`待验收·agent#1` / taskKey 短显 `#d2e1ca8a…` / `记录 N` / 相对时间）+ 任务详情摘要 / 缺项提示（红色「还缺：可验证目标、任务正文、验收判据、验证命令」）。

### 4.3 详情 = 三张卡片

| 卡片 | 内容 | 关键交互 |
|------|------|----------|
| **任务信息** | 标题 / 备注 / 优先级 / 下发对象 / 项目路径（+「选择项目」下拉、归一提示、关联按钮）/ 工作单元四栏（Objective、任务正文、允许、禁止、验收判据、验证命令） | 失焦即保存（只发变化栏）；四栏齐备提示「可下发」；缺项逐条红字列出 |
| **下发与执行** | 从工件导入（列目录 → 勾工件 → 导入为正文）/ 生成提示词 / 下发（权限模式 chips）/ **交给 AgentHub 执行** / 委派状态区（agent 名 + 终态徽标 `Failed exit-1 timeout` + 刷新 + 记为执行记录 + 查看执行记录） | 按钮禁用**原因可见**（四态文案）；执行 agent 下拉（data-test=delegate-agent）；委派状态轮询，终态 toast「委派已结束：Failed (timeout)」 |
| **阶段与执行记录** | 阶段操作按钮（完成/执行中/标记完成/删除任务，进 Blocked 弹原因）/ 执行记录时间线（#N + actor + 动作 + StageFrom→StageTo + 相对时间 + 明细 + 证据 + 改动文件） | append-only；长 resultSummary >240 字符折叠可展开；删除有二次确认 |

### 4.4 委派状态口径（057B 回报优先）

- **双状态源**：todo 的 `Stage`（任务生命周期）与 AgentHub 的 `TaskStatus`（进程执行）独立
- **回报优先**：agent 回报 `stageTo=Review` 时，todo 回调 AgentHub 标记 `Completed`——已回报完成的任务**不被**进程退出码 / 600s 超时覆盖为 Failed
- **404 兜底**：AgentHub 任务不存在（如升级清库）→ 详情委派区显示「委派任务不存在（可能已被清理）」，静默降级不弹错
- 徽标口径：todo 侧 `Stage` + AgentHub 终态并显（列表徽标、详情徽标、toast 三处一致）

## 5. 下发与执行链路

```
新建任务（回车）→ 填四栏/Objective → 选项目（任意路径写法，自动归一）
→ [列目录 → 勾工件 → 导入为正文] → 生成提示词 → 交给 AgentHub 执行
→ 任务流转 Dispatched → Running → agent 干活（opencode 等）
→ agent 回报 POST /api/todos/by-key/{taskKey}/records（stageTo=Review）
→ todo 回调 AgentHub 标记完成 → 时间线可见 → 阶段推到「待验收」→ 标记完成
```

- 路径归一 13 条规则：`/d/project` ≡ `D:\project` ≡ `D:/project/` ≡ `/mnt/d/project`，Key 相等即同一项目；相对路径/越界 400
- 委派接缝：`IAgentDelegation`（AgentHub 提供），接缝缺席 → 503 原文；业务拒绝 → 400 透传
- agent 领取面：`GET /api/todos/agent/next`（原子置 Running，无可领 204）

## 6. 端点面（前缀 api/todos，全部需 Bearer）

列表/CRUD、by-key 详情、complete/reopen、stage 流转、projects 归一、project 关联、artifact 列目录与导入、dispatch 预览与下发、dispatch-to-agent 委派、agent-status 回读/记录、agent/next 领取、records 读写（三面同形状）。

Agent 工具面（universal_tool / MCP 可调）：create_todo / list_todos / complete_todo / get_agent_task / claim_agent_task / append_task_execution / update_task_stage / dispatch_task。

## 7. 交互设计规范（落地口径，均经实测）

1. **点即保存**：失焦即回写，写请求串行队列（防乱序旧快照盖回）
2. **成败可见**：每个动作有 toast；失败端出后端 reason 原文且不清空表单
3. **防闪**：轮询刷新先比对 JSON 一致不赋值
4. **空态分级**：「未选中任务」引导 / 缺项逐条红字 / 筛选无匹配，各态文案可自证
5. **边界**：筛选回第 1 页、越界回退、长文本省略 title、窄屏堆叠
6. **禁用有因**：委派按钮四态原因照实说，不用 title 藏信息
7. **破坏性二次确认**：删除任务弹窗真实计数确认

## 8. 安全

- 全部控制器类级 `[Authorize("ApiKeyPolicy")]`（新增漏登记即测试红）
- 路径归一防穿越（ResolveInside）；cwd 白名单；权限模式 read-only / workspace-write / accept-edits
- 插件源码静态守卫：不得直连其他插件的 HTTP 路径
